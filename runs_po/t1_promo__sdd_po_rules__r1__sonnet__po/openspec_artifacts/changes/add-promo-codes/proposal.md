## Why

Летняя кампания маркетинга (SHOP-412) идёт с промокодами, а скидки сейчас вручную делает поддержка, из-за чего суммы расходятся с чеками. Нужна автоматическая скидка, которая попадает в итоги и построчно в чек: бухгалтерия считает налог по строкам.

## What Changes

- Новый модуль `shop/promo.py`: `DiscountKind` (`PERCENT`, `FIXED`), `PromoCode` (frozen dataclass, поля `code`, `kind`, `value`, `min_order_amount`, `starts_at`, `expires_at`, `max_uses`, `excluded_categories`) и `PromoRegistry(clock)` с методами `add`, `resolve`, `uses`, а также `consume` и `release` (учёт использования при оформлении и возврат при отмене).
- `shop/errors.py`: `PromoError(ShopError)` и три независимых наследника `UnknownPromoCodeError`, `PromoExpiredError`, `PromoConditionsError`.
- `shop/pricing.py`: `calculate_total(cart, shipping=None, tax=None, *, promo: PromoCode | None = None)`; новые поля `LineTotal.discount` и `OrderTotal.discount`; `total = subtotal - discount + shipping + tax`. Скидка раскладывается по строкам с точной суммой, налог считается с суммы строки после скидки, доставка не скидывается, а порог бесплатной доставки сравнивается с суммой товаров после скидки. Функция проверяет только условия заказа (срок и лимит проверяет реестр).
- `shop/orders.py`: `OrderService(..., promos: PromoRegistry | None = None)`, `quote(cart, promo_code=None)`, `place_order(cart, promo_code=None)`, `Order.promo_code: str | None`. Использование кода засчитывается только при успешно оформленном заказе; при отмене такого заказа (`OrderService.cancel`) использование возвращается.
- Не ломаем: старые вызовы `calculate_total(cart)`, `calculate_total(cart, shipping, tax)`, `quote(cart)`, `place_order(cart)` дают прежние суммы. `shop/cli.py`, `shop/reports.py` и существующие тесты не меняются; новые тесты — в отдельных файлах.

Допущения (задача не уточняет, решение принято автономно):

- Подарочные сертификаты не участвуют никогда (README), независимо от `excluded_categories`.
- Порог бесплатной доставки сравнивается с суммой товаров после скидки (`subtotal - discount`), а не с `subtotal` (решение владельца продукта: иначе покупатели добирали бы до порога промокодом). Сама стоимость доставки скидкой не уменьшается.
- `min_order_amount` сравнивается с суммой участвующих строк до скидки (включительно: сумма >= минимума).
- Если участвующих строк нет, код не подходит заказу: `PromoConditionsError`.
- Отмена заказа с промокодом уменьшает счётчик использований на один (решение владельца продукта), чтобы поддержка могла переоформить заказ клиенту с лимитированным кодом. Счётчик не опускается ниже нуля.
- Для реестра добавляются два дополнительных метода: `consume(code)` для учёта использования при оформлении заказа и `release(code)` для его возврата при отмене; остальной заданный API не меняется.

## Capabilities

### New Capabilities
- `promo-codes`: описание промокода, его валидация и нормализация, реестр с проверкой существования, срока и лимита, учёт использований, иерархия ошибок.
- `order-discounts`: применение промокода при расчёте итогов, построчная раскладка скидки, налог после скидки, интеграция с `quote`/`place_order` и сохранение кода в заказе.

## Impact

- Код: `shop/promo.py` (новый), `shop/errors.py`, `shop/pricing.py`, `shop/orders.py`; новые тесты в отдельных файлах.
- Публичный API: только расширение с необязательными параметрами и полями; обратная совместимость сохраняется.
- Зависимости: новых нет (только стандартная библиотека). `cli.py`, `reports.py` не затрагиваются.
