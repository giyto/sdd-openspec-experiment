### design.md

## Context

Сейчас `ledger/importer.py` содержит только `import_csv` для «Новы»: читает UTF-8, пишет `store.add` построчно, на первой ошибке бросает `StatementError`. Сравнение описаний «везде в проекте» — `rules.normalize_text` (README требует только его). `MemoryStore.add_many` атомарен (проверка всех, затем один `_commit` и одна запись JSON). Мотивация и требования — см. proposal.md и specs/statement-import.

## Goals / Non-Goals

**Goals:**
- Один конвейер «прочитать → разобрать всё → отфильтровать дубли → записать одним `add_many`», общий для `import_statement` и `import_csv`.
- Атомарность в обоих режимах; точная нумерация физических строк.

**Non-Goals:**
- Изменения CLI (вывод, флаги `--strict`/`--format`), отчётов, моделей, хранилищ.
- Новые зависимости, другие кодировки и разделители.

## Decisions

1. **`normalize_description` = `rules.normalize_text`** (обёртка, без второй реализации). Альтернатива — своя нормализация: расходится с правилами категоризации и нарушает соглашение README.
2. **Конвейер без побочных эффектов до конца разбора.** Файл читается целиком, все строки превращаются в `Transaction` или `RowError`; `store.add_many(new)` вызывается один раз в конце и только если есть что добавлять (пустой вызов создал бы JSON-файл). `strict` бросает `StatementRowError` до обращения к хранилищу. Альтернатива — откат записи: у хранилищ нет API отката.
3. **Кодировка:** `decode("utf-8-sig")`; при `UnicodeDecodeError` — `decode("cp1251")`; при ошибке и здесь (байт 0x98 и т.п.) — `StatementError` без `line_no`. Имя в результате — `utf-8` или `cp1251`. Пустой файл — `utf-8` и `UnknownFormatError`.
4. **Разбор CSV:** `csv.reader(io.StringIO(text, newline=""), delimiter=...)`. Номер начала записи = `prev_line_num + 1`, где `prev_line_num` — `reader.line_num` после предыдущей записи (учитывает пустые строки и многострочные кавычки). `str.splitlines` не используем из-за U+2028 и подобных. `csv.Error` на записи — ошибка строки.
5. **Заголовок:** первая запись, у которой не все поля пусты. Для `sfera`/`sfera_split` — точное сравнение кортежа `casefold(strip(поле))` с эталоном; для `nova` — как прежде: обязательные колонки по имени, порядок и лишние колонки допустимы (совместимость с `import_csv`). Форматы не пересекаются (разный разделитель/состав колонок). Данные «Новы» читаются по именам колонок, «Сферы» — по позициям. Неизвестный `fmt` → `UnknownFormatError`. `UnknownFormatError.line_no` = номер строки заголовка (None, если заголовка нет): сохраняет прежний `line_no == 1` для `import_csv`.
6. **Суммы «Сферы»:** регулярка `^[+-]?(\d{1,3}([   ]\d{3})+|\d+)(,\d{1,2})?$` после `strip()`; затем `,`→`.`, удаление разделителей, делегирование в `parse_amount`. Нулевая сумма и пустое описание ловятся `Transaction`. Для split знак запрещён отдельной проверкой, расход — `-amount`. Дата — `\d{2}\.\d{2}\.\d{4}` + `datetime.date` (строго `ДД.ММ.ГГГГ`).
7. **Дедупликация:** `Counter` ключей `(date, amount, normalize_description(description))` по `store.all()`; для каждой строки файла, если счётчик ключа > 0, уменьшаем его и считаем дублем, иначе добавляем. Повторный импорт идемпотентен, две реальные одинаковые покупки не теряются. Альтернативы: «множество ключей» теряет законные повторы в файле; «сравнение только с хранилищем до импорта без счётчика» теряет строку при частичном пересечении.
8. **Мусор:** запись, у которой все поля пусты после `strip()` (включая `[]`), пропускается, счётчики не меняются.
9. **Ошибки строк:** `ValidationError`/`ValueError`/неверное число полей → `RowError(line_no, message)` (сообщение без префикса `line N:`, берётся `StatementError.message`); в strict — `StatementRowError(message, line_no=...)`. Лишние поля сверх колонок — ошибка (для «Новы» раньше молча попадали в `restkey`; ужесточение, см. риски).
10. **`import_csv`:** `import_statement(path, store, strict=True, categorizer=..., clock=...).added`. Альтернатива — оставить старый код: дубли и BOM остались бы, «одного входа» не получилось бы.
11. **Категоризация** как раньше: `categorizer.categorize(tx)`, при не-None — `dataclasses.replace(tx, category=...)`. Категория не участвует в ключе дубля. `clock.now()` вызывается один раз.
12. **Допущения (в тикете не оговорены):** неизвестный `fmt` → `UnknownFormatError`; минус только ASCII `-`; мусорные строки допускаются и перед заголовком; мусор определяется по разобранным полям формата (строка `,,` в файле «Сферы» — ошибка строки, не мусор); невозможность декодировать — `StatementError` без `line_no`; явный `fmt` в результате отдаётся как есть.

## Risks / Trade-offs

- [Повторный импорт через CLI теперь даёт `Imported 0`] → это цель тикета; отражено в proposal, README обновляется.
- [Старые файлы «Новы» с лишними полями в строке раньше проходили] → теперь ошибка строки (в `import_csv` — `StatementError`); при возражениях уточнить у продакта (Марина Белова).
- [Внутрифайловые дубли, возможно ошибочные, не отсеиваются] → осознанно: отличить от двух одинаковых покупок нельзя.
- [Файл читается целиком] → выписки малы; упрощает атомарность.
- [Реально разные операции, отличающиеся только регистром/ё/пробелами, склеиваются] → то же правило, что в категоризации.


### proposal.md

## Why

Пользователи приносят выписки банка «Сфера» (два формата), а импорт умеет только «Нову». Текущий импорт хрупкий: повторный импорт задваивает операции, одна кривая строка обрывает импорт на середине (часть строк уже записана), файлы из Excel (UTF-8 с BOM) не читаются. Нужен единый вход, который сам определяет формат, не задваивает операции и честно сообщает о нераспознанном (LEDGER-58).

## What Changes

- Новая функция `import_statement` — единая точка импорта: автоопределение формата по заголовку (`nova`, `sfera`, `sfera_split`) или явный `fmt`, определение кодировки (UTF-8 с BOM/без, иначе cp1251), возврат `ImportResult` (формат, кодировка, добавлено, дубли, ошибки строк).
- Новые `detect_format`, `normalize_description` (сравнение описаний — то же, что `rules.normalize_text`), `RowError`, `ImportResult`.
- Пропуск дублей (дата + сумма + нормализованное описание) относительно уже сохранённых транзакций.
- Нераспознанный заголовок и несовпадение с явным `fmt` — `UnknownFormatError`; строки с ошибками не роняют импорт (попадают в `errors`), а при `strict=True` — `StatementRowError` без каких-либо записей в хранилище.
- Мусорные строки (пустые, из пробелов, из одних разделителей) пропускаются молча.
- Добавляются исключения `UnknownFormatError` и `StatementRowError` (наследники `StatementError`).
- `import_csv` сохраняет сигнатуру и тип результата (`int`), но становится тонкой обёрткой над `import_statement(strict=True)`; CLI не меняется, получает дедупликацию, BOM, формат «Сферы» и атомарность.
- **Изменение поведения CLI**: повторный импорт не задваивает операции, число в `Imported N transactions` не включает дубли.

## Capabilities

### New Capabilities
- `statement-import`: импорт банковских выписок (Нова, Сфера, Сфера split): определение формата и кодировки, разбор строк, дедупликация, обработка ошибок и режим strict.

### Modified Capabilities

(нет: в `openspec/specs/` спецификаций пока нет, поведение `import_csv` описано в новой capability)

## Impact

- Код: `ledger/importer.py`, `ledger/errors.py`; README (раздел форматов и таблица модулей). Тесты — только новые (`tests/test_importer_statement.py`).
- Не трогаем: `ledger/cli.py`, `ledger/reports.py`, существующие тесты, публичный API `Transaction`, хранилищ и `Categorizer`. Только стандартная библиотека.


### specs/statement-import/spec.md

## Purpose

Единый импорт банковских выписок («Нова», «Сфера», «Сфера split») в хранилище транзакций: автоопределение формата и кодировки, защита от дублей и честный отчёт о неразобранных строках.

## ADDED Requirements

### Requirement: Определение формата
Система SHALL определять формат выписки по строке заголовка: `nova` (`date,amount,description`, разделитель `,`), `sfera` (`Дата;Сумма;Описание`) и `sfera_split` (`Дата;Описание;Приход;Расход`), разделитель `;`. Названия колонок сравниваются без учёта регистра и пробелов по краям; для `nova` сохраняется прежняя терпимость к порядку колонок и лишним колонкам, для «Сферы» порядок и состав колонок точные. Заголовком считается первая непустая (не мусорная) строка файла. Если формат задан явно, заголовок MUST ему соответствовать.

#### Scenario: Автоопределение
- **WHEN** импортируется файл с заголовком `Дата;Описание;Приход;Расход` и `fmt` не задан
- **THEN** результат имеет `format == "sfera_split"`

#### Scenario: Нераспознанный заголовок
- **WHEN** заголовок файла не соответствует ни одному формату, или файл пуст, или состоит только из мусорных строк
- **THEN** выбрасывается `UnknownFormatError` в любом режиме (`strict` или нет), и хранилище не изменяется

#### Scenario: Заголовок не подходит к явному формату
- **WHEN** задан `fmt="sfera"`, а заголовок файла — формат `nova`
- **THEN** выбрасывается `UnknownFormatError`, и хранилище не изменяется

#### Scenario: Неизвестное значение fmt
- **WHEN** `fmt` не входит в `nova`, `sfera`, `sfera_split`
- **THEN** выбрасывается `UnknownFormatError`

#### Scenario: Ошибка заголовка указывает строку
- **WHEN** непустой файл имеет нераспознанный заголовок
- **THEN** у ошибки `line_no` равен физическому номеру строки заголовка (для заголовка в первой строке — 1)

### Requirement: Определение кодировки
Система SHALL считать файл `utf-8`, если он целиком декодируется как UTF-8 (BOM допустим и не попадает в данные), иначе — `cp1251`. Результат MUST содержать выбранную кодировку.

#### Scenario: UTF-8 с BOM
- **WHEN** файл сохранён из Excel как UTF-8 с BOM
- **THEN** заголовок распознаётся, `encoding == "utf-8"`

#### Scenario: cp1251
- **WHEN** файл не является корректным UTF-8 и декодируется как cp1251
- **THEN** описания читаются корректно, `encoding == "cp1251"`

#### Scenario: Файл не декодируется
- **WHEN** файл не читается ни как UTF-8, ни как cp1251
- **THEN** выбрасывается `StatementError` без `line_no`, хранилище не изменяется

### Requirement: Разбор формата «Сфера»
Для `sfera` система SHALL разбирать дату как `ДД.ММ.ГГГГ`, сумму — с десятичной запятой, не более двух знаков после неё. Допустимы разделители тысяч: обычный пробел, U+00A0, U+202F (группы по три цифры). Минус — расход, плюс или отсутствие знака — приход.

#### Scenario: Расход с неразрывным пробелом
- **WHEN** строка `01.03.2026;-1 200,50;Магазин Лента` (между «1» и «200» — U+00A0)
- **THEN** добавляется транзакция 2026-03-01, сумма `-1200.50`, описание `Магазин Лента`

#### Scenario: Приход с плюсом
- **WHEN** строка `02.03.2026;+85 000,00;Зарплата`
- **THEN** добавляется транзакция с суммой `85000.00`

#### Scenario: Некорректная сумма или дата
- **WHEN** сумма — `abc`, `1 20,50`, `0,00` или имеет больше двух знаков после запятой, либо дата невалидна (`31.02.2026`, `2026-03-01`, `1.3.2026`)
- **THEN** строка попадает в ошибки, остальные строки обрабатываются

### Requirement: Разбор формата «Сфера split»
Для `sfera_split` система SHALL брать приход из колонки «Приход», расход из колонки «Расход» и сохранять расход отрицательной суммой. Суммы в колонках MUST быть без знака, формат суммы и даты — как у `sfera`. Ровно одна из двух колонок суммы MUST быть заполнена.

#### Scenario: Расход
- **WHEN** строка `05.03.2026;Кофе;;350,00`
- **THEN** сумма транзакции `-350.00`

#### Scenario: Знак в сумме
- **WHEN** в колонке «Приход» или «Расход» указан знак (`-350,00`, `+100,00`)
- **THEN** строка — ошибка

#### Scenario: Заполнены обе колонки или ни одной
- **WHEN** обе колонки суммы заполнены, либо обе пусты (при непустой остальной строке)
- **THEN** строка — ошибка

### Requirement: Формат «Нова»
Для `nova` система SHALL сохранять прежний разбор: дата ISO `ГГГГ-ММ-ДД`, сумма с точкой и знаком, описание обрезается по краям.

#### Scenario: Совместимый разбор
- **WHEN** импортируется выписка `date,amount,description` из текущей документации
- **THEN** результат совпадает с прежним импортом (даты, суммы, описания, `imported_at`, категории)

### Requirement: Мусорные строки
Система SHALL молча пропускать в любом месте файла строки, у которых все поля пусты после обрезки пробелов: пустые, из пробелов, из одних разделителей формата (`;;;` для «Сферы», `,,` для «Новы»). Такая строка не является ошибкой, дублем или добавленной транзакцией и не влияет на счётчики, но учитывается в нумерации строк.

#### Scenario: Мусор в конце и в середине
- **WHEN** файл «Сферы» содержит пустую строку, строку из пробелов и `;;;` после последней операции и между операциями
- **THEN** `errors == []`, `duplicates == 0`, `added` равен числу настоящих операций

#### Scenario: Мусор перед заголовком
- **WHEN** перед заголовком стоят пустые строки
- **THEN** формат определяется по первой непустой строке

### Requirement: Дедупликация
Система SHALL пропускать транзакцию, если в хранилище уже есть транзакция с той же датой, той же суммой и тем же описанием, сравниваемым через `normalize_description` (регистр, ё/е и пробельные символы не различаются, как в `rules.normalize_text`); такие строки считаются в `duplicates`. Сопоставление идёт по количеству: каждая существующая в хранилище транзакция «гасит» не более одной строки файла, поэтому две одинаковые покупки в одном файле добавляются обе, а повторный импорт того же файла не добавляет ничего. Сопоставление не зависит от формата и категории. Описание сохраняется как в файле (обрезанное по краям), не нормализованным.

#### Scenario: Повторный импорт
- **WHEN** один и тот же файл импортируется дважды
- **THEN** второй раз `added == 0`, `duplicates` равен числу операций, хранилище не изменилось

#### Scenario: Различия только в регистре и пробелах
- **WHEN** в хранилище есть `Магазин Лента`, а в файле `  магазин   лента `, дата и сумма те же
- **THEN** строка считается дублем

#### Scenario: Одинаковые операции внутри одного файла
- **WHEN** в файле две одинаковые строки, а в хранилище таких нет
- **THEN** добавляются обе

#### Scenario: Частичное пересечение
- **WHEN** в хранилище одна такая операция, а в файле две одинаковые
- **THEN** `duplicates == 1`, `added == 1`

#### Scenario: Дубль между форматами
- **WHEN** операция уже импортирована из `nova`, а такая же приходит из `sfera`
- **THEN** она считается дублем

### Requirement: Ошибки строк
Система SHALL считать ошибкой строки всё, из чего не собирается корректная транзакция: неверное число полей, неверная дата, неверная или нулевая сумма, пустое описание, нарушение правил формата. Ошибка записывается в `errors` как `RowError(line_no, message)`, остальные строки импортируются. `line_no` — номер физической строки файла (заголовок — первая строка, пустые строки считаются; запись в кавычках на нескольких строках нумеруется по строке начала). Дубль ошибкой не считается.

#### Scenario: Кривая строка не роняет импорт
- **WHEN** в файле из пяти операций третья имеет неверную дату
- **THEN** добавлено 4, `errors` содержит один `RowError` с номером физической строки третьей операции

#### Scenario: Нумерация с мусором и многострочной записью
- **WHEN** перед ошибочной строкой стоят пустые строки и запись в кавычках на две строки
- **THEN** `line_no` соответствует физической строке файла

### Requirement: Режим strict
При `strict=True` система SHALL на первой ошибочной строке выбросить `StatementRowError` (с заполненным `line_no`), и из файла в хранилище не должно попасть ничего — ни в память, ни в JSON-файл, даже если до ошибки были корректные строки. Дубли ошибками не являются. `UnknownFormatError` не зависит от `strict`. Без `strict` допустимые строки сохраняются одной атомарной операцией.

#### Scenario: Откат всего файла
- **WHEN** `strict=True`, первые две строки корректны, третья — ошибочна, хранилище — `JsonFileStore`
- **THEN** выбрасывается `StatementRowError` с `line_no == 4` (заголовок — строка 1), в памяти и в JSON ничего не добавлено, файл хранилища не создаётся и не изменяется

#### Scenario: Дубли в strict
- **WHEN** `strict=True`, все строки файла — дубли
- **THEN** ошибки нет, `added == 0`, `duplicates` равен числу строк

### Requirement: Категоризация, время и совместимость
Система SHALL применять `categorizer` к новым транзакциям так же, как прежний импорт, проставлять всем добавленным транзакциям `imported_at` из единого вызова `clock.now()` (по умолчанию — системные часы). `import_csv(path, store, categorizer=None, clock=None)` SHALL сохранять сигнатуру, возвращать число добавленных транзакций (`int`) и работать как `import_statement(..., strict=True)`.

#### Scenario: Категория и время
- **WHEN** импортируется файл с `categorizer` и `FixedClock`
- **THEN** у добавленных транзакций проставлены категории по правилам, `imported_at == clock.now()`

#### Scenario: import_csv для совместимости
- **WHEN** вызывается `import_csv` на корректном файле «Новы», затем на нём же повторно
- **THEN** первый вызов возвращает число операций, второй — `0`

#### Scenario: import_csv и ошибка строки
- **WHEN** `import_csv` читает файл с кривой строкой
- **THEN** выбрасывается `StatementError` с `line_no` этой строки, хранилище не изменено

### Requirement: Исключения
`UnknownFormatError` и `StatementRowError` SHALL наследоваться от `StatementError`. `StatementRowError` MUST всегда иметь заполненный `line_no`.

#### Scenario: Перехват общим исключением
- **WHEN** выбрасывается `UnknownFormatError` или `StatementRowError`
- **THEN** их можно перехватить как `StatementError` и как `LedgerError`
