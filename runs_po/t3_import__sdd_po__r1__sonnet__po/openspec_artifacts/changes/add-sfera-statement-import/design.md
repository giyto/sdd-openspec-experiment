## Context

Сейчас `ledger/importer.py` содержит только `import_csv` для «Новы»: читает UTF-8, пишет `store.add` построчно, на первой ошибке бросает `StatementError`. Сравнение описаний «везде в проекте» — `rules.normalize_text` (README требует только его). `MemoryStore.add_many` атомарен (проверка всех, затем один `_commit` и одна запись JSON). Мотивация и требования — см. proposal.md и specs/statement-import.

## Goals / Non-Goals

**Goals:**
- Один конвейер «прочитать → разобрать всё → отфильтровать дубли → записать одним `add_many`», общий для `import_statement` и `import_csv`.
- Атомарность в обоих режимах; точная нумерация физических строк.

**Non-Goals:**
- Изменения CLI (вывод, флаги `--strict`/`--format`), отчётов, моделей, хранилищ.
- Новые зависимости, другие кодировки и разделители.

## Decisions

1. **`normalize_description` = `rules.normalize_text`** (обёртка, без второй реализации). Альтернатива — своя нормализация: расходится с правилами категоризации и нарушает соглашение README.
2. **Конвейер без побочных эффектов до конца разбора.** Файл читается целиком, все строки превращаются в `Transaction` или `RowError`; `store.add_many(new)` вызывается один раз в конце и только если есть что добавлять (пустой вызов создал бы JSON-файл). `strict` бросает `StatementRowError` до обращения к хранилищу. Альтернатива — откат записи: у хранилищ нет API отката.
3. **Кодировка:** `decode("utf-8-sig")`; при `UnicodeDecodeError` — `decode("cp1251")`; при ошибке и здесь (байт 0x98 и т.п.) — `StatementError` без `line_no`. Имя в результате — `utf-8` или `cp1251`. Пустой файл — `utf-8` и `UnknownFormatError`.
4. **Разбор CSV:** `csv.reader(io.StringIO(text, newline=""), delimiter=...)`. Номер начала записи = `prev_line_num + 1`, где `prev_line_num` — `reader.line_num` после предыдущей записи (учитывает пустые строки и многострочные кавычки). `str.splitlines` не используем из-за U+2028 и подобных. `csv.Error` на записи — ошибка строки.
5. **Заголовок:** первая запись, у которой не все поля пусты. Для всех форматов имена колонок нормализуются `casefold(strip(поле))`, нужные колонки ищутся по имени, порядок произвольный, лишние колонки («Номер карты», «Остаток») не читаются. Формат — по разделителю и набору обязательных колонок (`nova`: `,`; `sfera`/`sfera_split`: `;`). Если в заголовке есть колонки обоих форматов «Сферы» (`Сумма` и `Приход`/`Расход`), автоопределение даёт `UnknownFormatError`; при явном `fmt` формат принимается. При повторе имени колонки берётся первое вхождение. Данные всех форматов читаются по найденным индексам колонок. Поскольку мусор зависит от разделителя, поиск заголовка выполняется отдельно для каждого разделителя. Неизвестный `fmt` → `UnknownFormatError`. `UnknownFormatError.line_no` = номер строки заголовка (None, если заголовка нет): сохраняет прежний `line_no == 1` для `import_csv`.
6. **Суммы «Сферы»:** регулярка `^[+-]?(\d{1,3}([   ]\d{3})+|\d+)(,\d{1,2})?$` после `strip()`; затем `,`→`.`, удаление разделителей, делегирование в `parse_amount`. Нулевая сумма и пустое описание ловятся `Transaction`. Для split знак запрещён отдельной проверкой (в любой из колонок), расход — `-amount`; непустая колонка с нулевой суммой приравнивается к пустой, ошибкой остаются обе ненулевые или обе пустые/нулевые; нечитаемая сумма в любой колонке — ошибка. Дата — `\d{2}\.\d{2}\.\d{4}` + `datetime.date` (строго `ДД.ММ.ГГГГ`).
7. **Дедупликация:** `Counter` ключей `(date, amount, normalize_description(description))` по `store.all()`; для каждой строки файла, если счётчик ключа > 0, уменьшаем его и считаем дублем, иначе добавляем. Повторный импорт идемпотентен, две реальные одинаковые покупки не теряются. Альтернативы: «множество ключей» теряет законные повторы в файле; «сравнение только с хранилищем до импорта без счётчика» теряет строку при частичном пересечении.
8. **Мусор:** запись, у которой все поля пусты после `strip()` (включая `[]`), пропускается, счётчики не меняются.
9. **Ошибки строк:** `ValidationError`/`ValueError`/нехватка полей для нужных колонок → `RowError(line_no, message)` (сообщение без префикса `line N:`, берётся `StatementError.message`); в strict — `StatementRowError(message, line_no=...)`. Лишние поля сверх колонок игнорируются во всех форматах (для «Новы» это прежнее поведение `import_csv`, ужесточения нет); ошибка только если полей меньше, чем нужно для найденных колонок.
10. **`import_csv`:** `import_statement(path, store, strict=True, categorizer=..., clock=...).added`. Альтернатива — оставить старый код: дубли и BOM остались бы, «одного входа» не получилось бы.
11. **Категоризация** как раньше: `categorizer.categorize(tx)`, при не-None — `dataclasses.replace(tx, category=...)`. Категория не участвует в ключе дубля. `clock.now()` вызывается один раз.
12. **Допущения (в тикете не оговорены):** неизвестный `fmt` → `UnknownFormatError`; минус только ASCII `-`; мусорные строки допускаются и перед заголовком; мусор определяется по разобранным полям формата (строка `,,` в файле «Сферы» — ошибка строки, не мусор); невозможность декодировать — `StatementError` без `line_no`; явный `fmt` в результате отдаётся как есть.

## Risks / Trade-offs

- [Повторный импорт через CLI теперь даёт `Imported 0`] → это цель тикета; отражено в proposal, README обновляется.
- [Внутрифайловые дубли, возможно ошибочные, не отсеиваются] → осознанно: отличить от двух одинаковых покупок нельзя.
- [Файл читается целиком] → выписки малы; упрощает атомарность.
- [Реально разные операции, отличающиеся только регистром/ё/пробелами, склеиваются] → то же правило, что в категоризации.
