### design.md

## Context

Сейчас `ledger/importer.py` содержит только `import_csv` для «Новы»: читает UTF-8 через `csv.DictReader`, на первой плохой строке бросает `StatementError`, а каждую транзакцию пишет через `store.add` (для `JsonFileStore` это отдельная запись на диск). Сравнение описаний «везде в проекте» — `rules.normalize_text`. `MemoryStore.add_many` атомарен (проверка всех, одна запись). Требования — в `specs/statement-import/spec.md`, мотивация — в `proposal.md`.

## Goals / Non-Goals

**Goals:**
- Один проход «прочитать и разобрать всё → принять решение → одна запись `add_many`», чтобы строгий режим и ошибки строк не оставляли частичных данных.
- Одна точка истины для сравнения описаний и для разбора форматов.

**Non-Goals:**
- Изменения `cli.py`, `reports.py`, `Transaction`, хранилищ, `Categorizer`.
- Новые CLI-флаги (`--strict`, `--format`): CLI остаётся на `import_csv`.
- Дедупликация внутри одного файла и «умная» сверка с кратностью.

## Decisions

**Структура `importer.py`.** Публичный API строго по задаче (`import_statement`, `detect_format`, `normalize_description`, `RowError`, `ImportResult`, `import_csv`). Внутри: чтение байтов и декодирование, разбор заголовка, таблица форматов `{имя: (разделитель, обязательные колонки, функция разбора строки)}`, общий цикл по строкам. Исключения добавляются в `errors.py` рядом с `StatementError`.

**Чтение файла.** `path.read_bytes()`, затем `bytes.decode("utf-8-sig")`; при `UnicodeDecodeError` — `decode("cp1251")`; при повторной ошибке (байты 0x98 и т.п.) — `UnknownFormatError` без `line_no`. `utf-8-sig` одновременно допускает и не допускает BOM, и убирает BOM из первой колонки. Альтернатива (`open(..., encoding=...)` с построчным чтением) отвергнута: нужно знать кодировку до разбора и целиком проверять «читается как UTF-8». Файлы выписок небольшие, чтение целиком приемлемо.

**Разбор CSV.** `csv.reader(io.StringIO(text, newline=""), delimiter=...)`, а не `DictReader`: `DictReader` молча пропускает пустые строки и прячет лишние поля; `csv.reader` отдаёт `[]` для пустой строки и ведёт `reader.line_num`. Номер строки записи = `line_num` после предыдущей записи + 1 (так для многострочных записей в кавычках получается строка начала, а пустые строки считаются). Заголовок — строка 1. `csv.Error` на записи превращается в ошибку строки с номером `prev + 1`; цикл продолжается.

**Определение формата.** Заголовок сначала делится запятой, затем точкой с запятой; названия `strip()` + `casefold()`. `nova`: делимитер `,`, множество названий содержит `date/amount/description` (как раньше, лишние колонки допустимы, порядок любой). `sfera`/`sfera_split`: делимитер `;`, множество названий совпадает точно. Колонки берутся по индексу из заголовка. `detect_format` и `import_statement` используют одну внутреннюю функцию; `fmt` не из трёх значений → `UnknownFormatError`; `fmt` не совпал с заголовком → `UnknownFormatError`. `line_no=1` для всех проблем заголовка (в т. ч. пустой файл) — этого ждёт существующий тест `test_import_missing_column`.

**Мусорные строки.** Запись — мусор, если после удаления пробельных символов (включая U+00A0), `;` и `,` из всех полей ничего не осталось. Проверка идёт до разбора и до подсчёта чего-либо. Это покрывает пустые, пробельные, `;;;` и `,,`, независимо от формата (в `nova` строка `;;;` приходит одним полем).

**Разбор строк.** Строка должна иметь не меньше полей, чем колонок в заголовке; непустые лишние поля — ошибка (пустые — от хвостовых разделителей — допускаются). Описание — `strip()` значения (как раньше). Дальнейшие проверки — в самом `Transaction` (ноль, пустое описание): `ValidationError` превращается в `RowError`. Любое другое исключение разбора (`ValueError` от даты, `ValidationError`) тоже становится ошибкой строки.
- `nova`: логика прежняя (`date.fromisoformat`, `parse_amount`).
- `sfera`: дата — регулярка `\d{2}\.\d{2}\.\d{4}` + `datetime.date(...)` (строго, чтобы `strptime` не принимал `1.3.2026`); сумма — регулярка `^[+-]?(\d{1,3}([   ]\d{3})+|\d+)(,\d{1,2})?$` на `strip()`-значении, затем удаление пробелов, `,`→`.`, `Decimal` через `parse_amount` (даёт `to_money` и единые тексты ошибок). Явного `+` достаточно для прихода.
- `sfera_split`: тот же разбор суммы, но знак запрещён; пустота колонки — `not value.strip()`; ровно одна заполнена; расход → `-amount`.

**Дубли.** Перед разбором строится `set` ключей `(date, amount, normalize_description(description))` по `store.all()`. `normalize_description` — тонкий псевдоним/обёртка над `rules.normalize_text`, чтобы определение не расходилось. Множество не пополняется новыми строками файла: так две одинаковые покупки в одном файле остаются двумя операциями (это реальные покупки), а повторный импорт того же файла даёт их обе как дубли. Альтернатива «дедуп внутри файла» отвергнута: теряла бы законные операции. Альтернатива «мультимножество» отвергнута как избыточная.

**Атомарность.** Весь файл разбирается в память. Строгий режим бросает `StatementRowError` до любой записи. После разбора вызывается один `store.add_many(new)` (если список не пуст): для `JsonFileStore` — одна атомарная запись файла. Категоризация и `replace`/сборка транзакции — до записи; `imported_at` берётся один раз `clock.now()`.

**Порядок ошибок в strict.** Первая ошибочная строка в порядке файла; дубли и мусор пропускаются без эффекта. Ошибки заголовка/формата/кодировки идут раньше любых строк.

**`import_csv`.** `return import_statement(path, store, strict=True, categorizer=categorizer, clock=clock).added`. Strict выбран, чтобы сохранить прежнюю семантику «ошибка строки → исключение с `line_no`» для CLI (`error: line 3: ...`, код 1), но без частичной записи.

## Risks / Trade-offs

- [Поведение CLI меняется: дубли пропускаются, `Imported N` считает только новые] → допустимо по замыслу задачи; сообщение CLI не трогаем (рамки), существующие тесты не затрагиваются.
- [Нестрогий `nova` раньше принимал лишние непустые поля, теперь это ошибка строки] → редкий случай; зафиксировано как допущение.
- [Строгое условие на тысячи (группы по 3 цифры) отклонит `1 20,00`] → лучше ошибка строки, чем молча неверная сумма.
- [Чтение файла целиком в память] → выписки малы; упрощает определение кодировки.
- [Пропуск мусора по набору `;`/`,` может скрыть строку, где потеряно всё содержимое] → такая строка и по смыслу пуста.
- [Одинаковые операции с другой кратностью в хранилище и файле считаются дублями все] → приемлемо, см. «Дубли».

## Допущения (решения без уточнения у продукта)

1. Дубли ищутся только среди уже сохранённого до начала импорта; повторы внутри файла не дубли.
2. Не декодируемый ни как UTF-8, ни как cp1251 файл → `UnknownFormatError` без `line_no`.
3. Заголовок — всегда первая строка файла; пустые строки перед заголовком = нераспознанный заголовок.
4. Недопустимый `fmt` (не из трёх значений) → `UnknownFormatError`.
5. `import_csv` использует `strict=True`, автоопределение формата и дедупликацию.
6. Формат даты в `sfera`/`sfera_split` — `ДД.ММ.ГГГГ` (в задаче явно не указан, следует из примера).
7. Сообщения `RowError.message` — на английском, как в существующем коде.


### proposal.md

## Why

Пользователи приносят выписки банка «Сфера», а импорт умеет только «Нову». Текущий `import_csv` к тому же хрупкий: повторный импорт задваивает операции, одна кривая строка роняет импорт посреди файла (часть строк уже записана), файлы из Excel (UTF-8 с BOM) не читаются. Задача LEDGER-58.

## What Changes

- Новый единый вход `import_statement(path, store, *, fmt=None, strict=False, categorizer=None, clock=None) -> ImportResult` в `ledger/importer.py`.
- Новые функции `detect_format(path) -> str` (`"nova"` | `"sfera"` | `"sfera_split"`) и `normalize_description(text: str) -> str`.
- Новые frozen-датаклассы `RowError(line_no, message)` и `ImportResult(format, encoding, added, duplicates, errors)`.
- Новые исключения в `ledger/errors.py`: `UnknownFormatError(StatementError)` и `StatementRowError(StatementError)` (с заполненным `line_no`).
- Поддержка форматов «Сферы»: `sfera` (`Дата;Сумма;Описание`) и `sfera_split` (`Дата;Описание;Приход;Расход`), помимо `nova`.
- Определение кодировки: UTF-8 (BOM допустим), иначе cp1251.
- Пропуск дублей (дата + сумма + описание после `normalize_description`) со счётчиком `duplicates`.
- Пустые, пробельные и «из одних разделителей» строки пропускаются молча, где бы ни стояли.
- Кривые строки собираются в `errors` и не мешают остальным; при `strict=True` первая кривая строка даёт `StatementRowError`, и в хранилище не попадает ничего.
- `import_csv(path, store, categorizer=None, clock=None) -> int` сохраняет сигнатуру и тип результата и становится тонкой обёрткой над `import_statement` (`strict=True`); CLI на нём продолжает работать без изменений.
- **Поведенческое изменение `import_csv`/CLI** (существующие тесты не ломает): повторный импорт не задваивает операции, ошибка строки не оставляет частично записанных данных, файл с BOM читается, форматы «Сферы» распознаются автоматически.

## Capabilities

### New Capabilities
- `statement-import`: импорт банковских выписок (`nova`, `sfera`, `sfera_split`): определение формата и кодировки, разбор строк, дубли, мусорные строки, ошибки строк, строгий режим, совместимая обёртка `import_csv`.

### specs/statement-import/spec.md

## Purpose

Импорт банковских выписок («Нова» и «Сфера») в хранилище транзакций: автоопределение формата и кодировки, защита от дублей и от частичной записи, честный отчёт об ошибках разбора.

## ADDED Requirements

### Requirement: Единый вход импорта
Система SHALL предоставлять `import_statement(path, store, *, fmt=None, strict=False, categorizer=None, clock=None) -> ImportResult` в `ledger/importer.py`. `ImportResult` — `@dataclass(frozen=True)` с полями `format: str` (`"nova"` | `"sfera"` | `"sfera_split"`), `encoding: str` (`"utf-8"` | `"cp1251"`), `added: int`, `duplicates: int`, `errors: list[RowError]`. `RowError` — `@dataclass(frozen=True)` с полями `line_no: int` и `message: str`. `format` содержит фактически применённый формат. Транзакции SHALL получать `imported_at = clock.now()` (одно значение на весь импорт; без `clock` — `SystemClock`), описание — как в текущем импорте (значение поля без пробелов по краям, без нормализации), категорию — от `categorizer`, если он задан и вернул не `None`.

#### Scenario: Успешный импорт файла «Новы»
- **WHEN** вызван `import_statement(path, store, clock=clock)` для корректного файла «Новы» из трёх строк
- **THEN** результат имеет `format="nova"`, `added=3`, `duplicates=0`, `errors=[]`, а в хранилище три транзакции с `imported_at == clock.now()`

#### Scenario: Категоризация
- **WHEN** передан `categorizer`, правило которого подходит к строке
- **THEN** сохранённая транзакция имеет категорию из правила, а неподходящие остаются без категории

### Requirement: Определение формата
Система SHALL предоставлять `detect_format(path) -> str`, возвращающий `"nova"`, `"sfera"` или `"sfera_split"` по заголовку (первая строка файла; BOM, пробелы вокруг названий колонок и регистр не важны). Заголовок `nova` — разделитель `,`, колонки `date`, `amount`, `description` (порядок любой). Заголовок `sfera` — разделитель `;`, ровно колонки `Дата`, `Сумма`, `Описание`. Заголовок `sfera_split` — разделитель `;`, ровно колонки `Дата`, `Описание`, `Приход`, `Расход`. Колонки SHALL читаться по названиям, а не по позициям. При `fmt=None` `import_statement` использует результат `detect_format`. Если заголовок не распознан (в том числе файл пустой) или не подходит к явно указанному `fmt`, `detect_format` и `import_statement` SHALL бросать `UnknownFormatError` независимо от `strict`, ничего не сохраняя.

#### Scenario: Автоопределение
- **WHEN** `import_statement` вызван с `fmt=None` для файла с заголовком `Дата;Описание;Приход;Расход`
- **THEN** `result.format == "sfera_split"`

#### Scenario: Нераспознанный заголовок
- **WHEN** первая строка файла `foo,bar`
- **THEN** бросается `UnknownFormatError` (это `StatementError`, `line_no == 1`), хранилище не изменено

#### Scenario: Пустой файл
- **WHEN** файл имеет нулевой размер
- **THEN** бросается `UnknownFormatError` при `strict=False` и при `strict=True`

#### Scenario: Явный формат не подходит к заголовку
- **WHEN** `fmt="nova"`, а заголовок файла соответствует `sfera`
- **THEN** бросается `UnknownFormatError`, хранилище не изменено

#### Scenario: Неизвестное значение fmt
- **WHEN** `fmt="bank-x"`
- **THEN** бросается `UnknownFormatError`

### Requirement: Определение кодировки
Система SHALL считать кодировку `"utf-8"`, если файл целиком декодируется как UTF-8 (наличие BOM допустимо, BOM не попадает в данные, в том числе в название первой колонки), иначе `"cp1251"`. Результат SHALL возвращаться в `ImportResult.encoding`. Если байты не декодируются и как cp1251, SHALL бросаться `UnknownFormatError` без `line_no`.

#### Scenario: UTF-8 с BOM
- **WHEN** файл «Сферы» сохранён из Excel как UTF-8 с BOM
- **THEN** импорт проходит, `encoding == "utf-8"`

#### Scenario: cp1251
- **WHEN** файл закодирован в cp1251 и не является корректным UTF-8
- **THEN** кириллица в описаниях читается верно, `encoding == "cp1251"`

### Requirement: Формат sfera
В формате `sfera` (`Дата;Сумма;Описание`) дата SHALL быть `ДД.ММ.ГГГГ`. Сумма — необязательный знак `-` или `+`, целая часть с необязательным разделением тысяч пробелом (обычным, U+00A0 или U+202F; группы по три цифры), необязательная дробная часть через запятую (1–2 цифры). Минус — расход (отрицательная сумма), без знака или с плюсом — приход.

#### Scenario: Расход с неразрывным пробелом
- **WHEN** строка `01.03.2026;-1 200,50;Магазин Лента`, где пробел — U+00A0
- **THEN** добавляется транзакция 2026-03-01, сумма `-1200.50`, описание `Магазин Лента`

#### Scenario: Приход
- **WHEN** строки `02.03.2026;+85 000,00;Зарплата` и `03.03.2026;100,00;Возврат`
- **THEN** добавляются транзакции с суммами `85000.00` и `100.00`

#### Scenario: Некорректная сумма или дата
- **WHEN** сумма `1,200.50`, `1 20,00`, `abc` или `0,00`, либо дата `2026-03-01` или `31.02.2026`
- **THEN** строка попадает в ошибки строк, а не в хранилище

### Requirement: Формат sfera_split
В формате `sfera_split` (`Дата;Описание;Приход;Расход`) дата и запись суммы SHALL подчиняться тем же правилам, что в `sfera`, но суммы пишутся без знака; знак `+` или `-` в сумме — ошибка строки. Ровно одна из колонок `Приход`/`Расход` должна быть заполнена (значение из одних пробелов считается пустым); заполнены обе или ни одной — ошибка строки. Сумма из `Приход` положительна, из `Расход` — отрицательна.

#### Scenario: Расход
- **WHEN** строка `01.03.2026;Магазин Лента;;1 200,50`
- **THEN** добавляется транзакция с суммой `-1200.50`

#### Scenario: Приход
- **WHEN** строка `02.03.2026;Зарплата;85 000,00;`
- **THEN** добавляется транзакция с суммой `85000.00`

#### Scenario: Ошибки заполнения
- **WHEN** обе суммы заполнены, обе пусты или сумма записана со знаком (`-5,00` в `Расход`)
- **THEN** строка попадает в ошибки строк

### Requirement: Формат nova
Формат `nova` (`date,amount,description`; дата ISO `ГГГГ-ММ-ДД`; сумма с точкой и знаком, без разделителей тысяч) SHALL разбираться так же, как до этого изменения.

#### Scenario: Строка «Новы»
- **WHEN** строка `2026-03-03,-1200.5,"Магазин ""Лента"", чек 42"`
- **THEN** добавляется транзакция с суммой `-1200.50` и описанием `Магазин "Лента", чек 42`

### Requirement: Нормализация описаний и дубли
Система SHALL предоставлять `normalize_description(text: str) -> str`, дающую ровно то же сравнение описаний, что принято в проекте (`normalize_text`: схлопывание пробельных символов, обрезка краёв, `casefold()`, `ё`→`е`). Транзакция файла SHALL считаться дублём, если в хранилище на момент начала импорта уже есть транзакция с той же датой, той же суммой и тем же `normalize_description` описанием. Дубли не добавляются, считаются в `ImportResult.duplicates` и не являются ошибками (в том числе при `strict=True`). Сравнение идёт только с содержимым хранилища на начало импорта: одинаковые строки внутри одного файла между собой дублями не считаются.

#### Scenario: Повторный импорт
- **WHEN** один и тот же файл импортирован дважды
- **THEN** второй вызов возвращает `added=0`, `duplicates` равен числу строк с данными, хранилище не изменилось

#### Scenario: Различие регистра, пробелов и ё
- **WHEN** в хранилище есть `Зарплата` за 2026-03-02 на `85000.00`, а в файле `  ЗАРПЛАТА ` с той же датой и суммой
- **THEN** строка — дубль

#### Scenario: Разные суммы или даты
- **WHEN** описание совпадает, но отличается сумма или дата
- **THEN** строка добавляется

#### Scenario: Одинаковые покупки в одном файле
- **WHEN** в файле две строки с одинаковой датой, суммой и описанием, а в хранилище такой операции не было
- **THEN** добавляются обе

#### Scenario: Дубль между форматами
- **WHEN** операция, импортированная из `sfera`, встречается в файле `sfera_split` с теми же датой, суммой и описанием
- **THEN** она считается дублем

### Requirement: Мусорные строки
Система SHALL молча пропускать строки, которые пусты, состоят из одних пробельных символов или из одних разделителей (`;`, `,`) и пробельных символов, где бы они ни стояли (между строками данных, в конце файла). Такие строки не являются ни ошибкой, ни дублем, ни добавленной транзакцией и не учитываются ни в одном счётчике, но участвуют в нумерации физических строк.

#### Scenario: Мусор в конце выгрузки
- **WHEN** после строк данных идут пустая строка, строка из пробелов и `;;;` (для «Новы» — `,,`)
- **THEN** `errors == []`, `duplicates` не увеличивается, `added` равно числу строк с данными

#### Scenario: Мусор посреди файла и номера строк
- **WHEN** между двумя строками данных стоит `;;;`, а следующая за второй строка некорректна
- **THEN** номер строки в ошибке — её физический номер в файле, с учётом пропущенных строк

### Requirement: Ошибки строк в обычном режиме
При `strict=False` система SHALL считать ошибкой строки всё, из чего не собирается корректная `Transaction`: неверное число полей, непустые лишние поля, неразбираемая дата или сумма, нулевая сумма, пустое описание, нарушение правил формата. Каждая ошибка SHALL попадать в `ImportResult.errors` как `RowError` с `line_no` по правилам `StatementError` (физическая строка файла, заголовок — строка 1, пустые строки считаются, запись в кавычках на несколько строк — строка начала записи) и непустым `message`. Остальные корректные строки SHALL импортироваться.

#### Scenario: Кривая строка среди хороших
- **WHEN** в файле из пяти строк данных третья имеет неверную дату
- **THEN** `added == 4`, `errors == [RowError(line_no=4, message=...)]`

#### Scenario: Запись в кавычках на несколько строк
- **WHEN** некорректная запись в кавычках начинается на строке 5 и занимает строки 5–6
- **THEN** `line_no == 5`

### Requirement: Строгий режим
При `strict=True` на первой ошибочной строке (в порядке файла) система SHALL бросать `StatementRowError` (наследник `StatementError`) с заполненным `line_no`; при этом ни одна транзакция файла не должна попасть в хранилище — ни в память, ни в JSON-файл `JsonFileStore`, ни частично. Дубли ошибками не считаются. `UnknownFormatError` бросается в обоих режимах.

#### Scenario: Ошибка в конце файла
- **WHEN** `strict=True`, первые 100 строк корректны, строка 102 нет
- **THEN** бросается `StatementRowError` с `line_no == 102`, `store.all()` пуст, JSON-файл не создан и не изменён

#### Scenario: Дубли в строгом режиме
- **WHEN** `strict=True` и файл целиком состоит из уже существующих операций
- **THEN** исключения нет, `added == 0`, `duplicates` равно числу строк

### Requirement: Атомарность записи
Корректные транзакции SHALL записываться в хранилище одним пакетным вызовом после разбора всего файла: либо весь импорт, либо ни одной новой транзакции. Если запись в хранилище не удалась, исключение хранилища SHALL быть передано вызывающему.

#### Scenario: Одна запись на диск
- **WHEN** импортируется файл из нескольких строк в `JsonFileStore`
- **THEN** JSON-файл записывается один раз для всего импорта

### Requirement: Совместимость import_csv
Система SHALL сохранять `import_csv(path, store, categorizer=None, clock=None) -> int`: сигнатура прежняя, возвращается число добавленных транзакций. Функция работает в строгом режиме (`strict=True`, `fmt=None`): ошибка строки — `StatementError` (фактически `StatementRowError`) с тем же `line_no`, что раньше, нераспознанный заголовок — `StatementError` (`UnknownFormatError`) с `line_no == 1`. Дубли пропускаются и в возвращаемое число не входят. CLI SHALL работать без изменений.

#### Scenario: Возвращаемое значение
- **WHEN** `import_csv` вызван для файла «Новы» из трёх новых строк
- **THEN** возвращено `3` (тип `int`)

#### Scenario: Кривая строка
- **WHEN** третья строка файла содержит неверную сумму
- **THEN** бросается `StatementError` с `line_no == 3`, хранилище не изменено

#### Scenario: Выписка «Сферы» через путь CLI
- **WHEN** `import_csv` вызван для файла `sfera`
- **THEN** операции импортированы, как при `import_statement`
