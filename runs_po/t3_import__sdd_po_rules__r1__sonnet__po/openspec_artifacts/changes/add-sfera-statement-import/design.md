## Context

Сейчас `ledger/importer.py` содержит только `import_csv` для «Новы»: читает UTF-8 через `csv.DictReader`, на первой плохой строке бросает `StatementError`, а каждую транзакцию пишет через `store.add` (для `JsonFileStore` это отдельная запись на диск). Сравнение описаний «везде в проекте» — `rules.normalize_text`. `MemoryStore.add_many` атомарен (проверка всех, одна запись). Требования — в `specs/statement-import/spec.md`, мотивация — в `proposal.md`.

## Goals / Non-Goals

**Goals:**
- Один проход «прочитать и разобрать всё → принять решение → одна запись `add_many`», чтобы строгий режим и ошибки строк не оставляли частичных данных.
- Одна точка истины для сравнения описаний и для разбора форматов.

**Non-Goals:**
- Изменения `cli.py`, `reports.py`, `Transaction`, хранилищ, `Categorizer`.
- Новые CLI-флаги (`--strict`, `--format`): CLI остаётся на `import_csv`.
- Дедупликация внутри одного файла (идентичные строки файла между собой не повторы).

## Decisions

**Структура `importer.py`.** Публичный API строго по задаче (`import_statement`, `detect_format`, `normalize_description`, `RowError`, `ImportResult`, `import_csv`). Внутри: чтение байтов и декодирование, разбор заголовка, таблица форматов `{имя: (разделитель, обязательные колонки, функция разбора строки)}`, общий цикл по строкам. Исключения добавляются в `errors.py` рядом с `StatementError`.

**Чтение файла.** `path.read_bytes()`, затем `bytes.decode("utf-8-sig")`; при `UnicodeDecodeError` — `decode("cp1251")`; при повторной ошибке (байты 0x98 и т.п.) — `UnknownFormatError` без `line_no`. `utf-8-sig` одновременно допускает и не допускает BOM, и убирает BOM из первой колонки. Альтернатива (`open(..., encoding=...)` с построчным чтением) отвергнута: нужно знать кодировку до разбора и целиком проверять «читается как UTF-8». Файлы выписок небольшие, чтение целиком приемлемо.

**Разбор CSV.** `csv.reader(io.StringIO(text, newline=""), delimiter=...)`, а не `DictReader`: `DictReader` молча пропускает пустые строки и прячет лишние поля; `csv.reader` отдаёт `[]` для пустой строки и ведёт `reader.line_num`. Номер строки записи = `line_num` после предыдущей записи + 1 (так для многострочных записей в кавычках получается строка начала, а пустые строки считаются). Заголовок — строка 1. `csv.Error` на записи превращается в ошибку строки с номером `prev + 1`; цикл продолжается.

**Определение формата.** Заголовок сначала делится запятой, затем точкой с запятой; названия `strip()` + `casefold()`. Для всех форматов: нужные колонки ищутся среди названий заголовка, лишние колонки игнорируются (в `nova` так было и раньше). `nova`: делимитер `,`, есть `date/amount/description`. `sfera`: делимитер `;`, есть `дата/сумма/описание`. `sfera_split`: делимитер `;`, есть `дата/описание/приход/расход`. Если автоопределение подходит к нескольким форматам (например, есть `сумма`, `приход` и `расход` одновременно) — `UnknownFormatError`; при явном `fmt` проверяется только он. При повторяющемся названии берётся первая колонка. Колонки берутся по индексу из заголовка. `detect_format` и `import_statement` используют одну внутреннюю функцию; `fmt` не из трёх значений → `UnknownFormatError`; `fmt` не совпал с заголовком → `UnknownFormatError`. `line_no=1` для всех проблем заголовка (в т. ч. пустой файл) — этого ждёт существующий тест `test_import_missing_column`.

**Мусорные строки.** Запись — мусор, если после удаления пробельных символов (включая U+00A0), `;` и `,` из всех полей ничего не осталось. Проверка идёт до разбора и до подсчёта чего-либо. Это покрывает пустые, пробельные, `;;;` и `,,`, независимо от формата (в `nova` строка `;;;` приходит одним полем).

**Разбор строк.** Строка должна содержать поля до максимального индекса нужных колонок включительно, иначе «not enough fields» (так же, как раньше для `nova`); любые поля сверх этого игнорируются, в том числе непустые, во всех форматах — прежнее поведение `import_csv` для «Новы» не меняется. Описание — `strip()` значения (как раньше). Дальнейшие проверки — в самом `Transaction` (ноль, пустое описание): `ValidationError` превращается в `RowError`. Любое другое исключение разбора (`ValueError` от даты, `ValidationError`) тоже становится ошибкой строки.
- `nova`: логика прежняя (`date.fromisoformat`, `parse_amount`).
- `sfera`: дата — регулярка `\d{2}\.\d{2}\.\d{4}` + `datetime.date(...)` (строго, чтобы `strptime` не принимал `1.3.2026`); сумма — регулярка `^[+-]?(\d{1,3}([   ]\d{3})+|\d+)(,\d{1,2})?$` на `strip()`-значении, затем удаление пробелов, `,`→`.`, `Decimal` через `parse_amount` (даёт `to_money` и единые тексты ошибок). Явного `+` достаточно для прихода.
- `sfera_split`: тот же разбор суммы, но знак запрещён. Непустое значение колонки разбирается (неразбираемое — ошибка строки); пустое (`not value.strip()`) или нулевое (`0,00`) значение считается «колонка пуста». Ровно одна колонка должна остаться непустой; обе непустые или обе пустые (включая `0,00`/`0,00`) — ошибка; расход → `-amount`.

**Дубли.** Перед разбором строится `collections.Counter` ключей `(date, amount, normalize_description(description))` по `store.all()` — снимок хранилища до импорта. Для каждой строки файла по порядку: если счётчик её ключа > 0, он уменьшается и строка — дубль; иначе строка добавляется. Новые строки файла в счётчик не попадают, поэтому идентичные строки внутри файла между собой не дубли: при одной такой операции в хранилище и трёх в файле — 1 дубль и 2 добавления; при повторном импорте файла с двумя одинаковыми покупками обе — дубли. `normalize_description` — тонкая обёртка над `rules.normalize_text`, чтобы определение не расходилось. Альтернатива «множество ключей» отвергнута: она считала бы дублями все строки файла с ключом из хранилища и теряла бы реальные операции. Альтернатива «дедуп внутри файла» отвергнута по той же причине.

**Атомарность.** Весь файл разбирается в память. Строгий режим бросает `StatementRowError` до любой записи. После разбора вызывается один `store.add_many(new)` (если список не пуст): для `JsonFileStore` — одна атомарная запись файла. Категоризация и `replace`/сборка транзакции — до записи; `imported_at` берётся один раз `clock.now()`.

**Порядок ошибок в strict.** Первая ошибочная строка в порядке файла; дубли и мусор пропускаются без эффекта. Ошибки заголовка/формата/кодировки идут раньше любых строк.

**`import_csv`.** `return import_statement(path, store, strict=True, categorizer=categorizer, clock=clock).added`. Strict выбран, чтобы сохранить прежнюю семантику «ошибка строки → исключение с `line_no`» для CLI (`error: line 3: ...`, код 1), но без частичной записи.

## Risks / Trade-offs

- [Поведение CLI меняется: дубли пропускаются, `Imported N` считает только новые] → допустимо по замыслу задачи; сообщение CLI не трогаем (рамки), существующие тесты не затрагиваются.
- [Строгое условие на тысячи (группы по 3 цифры) отклонит `1 20,00`] → лучше ошибка строки, чем молча неверная сумма.
- [Чтение файла целиком в память] → выписки малы; упрощает определение кодировки.
- [Пропуск мусора по набору `;`/`,` может скрыть строку, где потеряно всё содержимое] → такая строка и по смыслу пуста.
- [Строка с лишними непустыми полями в `sfera`/`sfera_split` принимается, хотя может означать сбой разделителя] → единое правило для всех форматов и совместимость с `nova`; число нужных полей всё равно проверяется.

## Допущения (решения без уточнения у продукта)

1. Дубли ищутся только среди уже сохранённого до начала импорта, с учётом количества; идентичные строки внутри файла не повторы между собой.
2. Не декодируемый ни как UTF-8, ни как cp1251 файл → `UnknownFormatError` без `line_no`.
3. Заголовок — всегда первая строка файла; пустые строки перед заголовком = нераспознанный заголовок.
4. Недопустимый `fmt` (не из трёх значений) → `UnknownFormatError`.
5. `import_csv` использует `strict=True`, автоопределение формата и дедупликацию.
6. Формат даты в `sfera`/`sfera_split` — `ДД.ММ.ГГГГ` (в задаче явно не указан, следует из примера).
7. Сообщения `RowError.message` — на английском, как в существующем коде.
8. Лишние поля в строке данных игнорируются во всех форматах (не только в `nova`), чтобы правило было единым и `import_csv` для «Новы» вёл себя как раньше.
9. Заголовок, подходящий сразу к нескольким форматам при `fmt=None`, — `UnknownFormatError`.
10. `0,00` в обеих колонках `sfera_split` — ошибка строки (обе пусты); ненулевое значение в обеих — тоже.
