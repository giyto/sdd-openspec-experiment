### design.md

## Context

Сейчас `ledger/importer.py` содержит один `import_csv` для «Новы»: читает файл как UTF-8 (BOM ломает заголовок), добавляет транзакции по одной через `store.add` (ошибка посреди файла оставляет часть записанной), дедупликации нет. Описания в проекте сравниваются через `rules.normalize_text`. `MemoryStore.add_many` атомарно добавляет пачку (одна запись на диск у `JsonFileStore`). Требования — в `specs/statement-import/spec.md`, мотивация — в proposal.md.

## Goals / Non-Goals

**Goals:**
- Один разборщик для трёх форматов, общий для `import_statement` и `import_csv`.
- Атомарность: разбор и дедупликация целиком в памяти, затем один `add_many`.

**Non-Goals:**
- Изменения `cli.py`, `reports.py`, `Transaction`, хранилищ, `Categorizer`.
- Новые флаги CLI, внешние зависимости, поддержка других банков/разделителей.

## Decisions

1. **Чтение файла.** `bytes = Path.read_bytes()`; пробуем `decode("utf-8-sig")` (строго), при `UnicodeDecodeError` — `decode("cp1251")`; если и он падает — `UnknownFormatError`. Потом `io.StringIO(text, newline="")` в `csv.reader`. Альтернатива (`chardet`) отвергнута: нужна только стандартная библиотека. Кодировка по умолчанию `utf-8` для файла из чистого ASCII — допустимо.
2. **Формат по заголовку.** Первая запись `csv.reader` нужным разделителем не известна заранее, поэтому заголовок берём из первой физической строки текста и сопоставляем с таблицей `{формат: (разделитель, колонки)}` после `split(разделитель)`, `strip()`, `casefold()`. Пустой текст → `UnknownFormatError` без `line_no`; нераспознанный/несовпавший с `fmt` → с `line_no=1`. `detect_format` и `import_statement` используют общую внутреннюю функцию, чтобы не читать логику дважды.
3. **Номера строк.** Берём `reader.line_num` до чтения записи: номер начала записи = предыдущий `line_num` + 1. Это даёт физическую строку начала записи, в том числе после пустых строк и многострочных кавычек (согласуется с докстрингом `StatementError`). Альтернатива `enumerate` неверна для многострочных записей.
4. **Мусорные строки.** Запись считается мусором, если все поля после `strip()` пусты (покрывает `[]`, пробелы, `;;;`, `,,`). Проверка идёт до разбора, такие строки ни в какие счётчики не попадают. Если число полей неверное и среди них есть непустое — ошибка строки.
5. **Разбор значений.** Для «Новы» — переиспользуем текущую логику (`date.fromisoformat`, `parse_amount`). Для «Сферы» — дата по regex `^\d{2}\.\d{2}\.\d{4}$` (ASCII) + `date(y, m, d)`; сумма: убрать `" "`, U+00A0, U+202F, проверить regex `^[+-]?[0-9]+(,[0-9]{1,2})?$`, заменить `,`→`.`, дальше `parse_amount` (он же отсечёт ноль и лишние знаки через `Transaction`). Для `split`: регекс без знака, ровно одна заполненная колонка; расход — `-amount`. Любой `ValidationError`/`ValueError` превращается в `RowError`/`StatementRowError` с `line_no`. Заменить `\d` на `[0-9]` важно: `\d` принимает не-ASCII цифры.
6. **Дедупликация.** Строим `Counter` по ключам `(date, amount, normalize_description(description))` из `store.all()`. Для каждой строки файла: если счётчик ключа > 0 — уменьшаем и считаем дублем, иначе добавляем в пачку. Так повторный импорт идемпотентен, а две одинаковые покупки в одном файле не склеиваются. Альтернатива «множество» склеила бы настоящие повторные покупки и отвергнута; альтернатива «дубль и внутри файла» — отвергнута по той же причине.
7. **`normalize_description`.** Тонкая обёртка над `rules.normalize_text` (одна реализация сравнения, поведение не расходится). Циклического импорта нет: `importer` уже импортирует `rules`.
8. **Строгий режим.** При `strict=True` первая ошибка → `StatementRowError(message, line_no=...)` до обращения к хранилищу; иначе ошибки копятся. Запись — только в конце, одним `store.add_many(batch)` (если пачка не пуста).
9. **Категоризация и время.** `imported_at = clock.now()` один раз на вызов; категория — как в текущем коде, через `dataclasses.replace` либо пересборку; описание — `strip()`.
10. **`import_csv`.** `return import_statement(path, store, fmt="nova", strict=True, categorizer=..., clock=...).added`. Тонкая обёртка сохраняет сигнатуру, тип и существующие тесты (ошибка строки → `StatementError` с `line_no`; отсутствующая колонка → `UnknownFormatError` с `line_no=1`).
11. **Исключения.** `UnknownFormatError` и `StatementRowError` — наследники `StatementError` без доп. полей; `StatementRowError` требует `line_no` (параметр keyword-only обязательный), конструктор остаётся совместимым.

## Допущения (в задаче не определено)

- Дубли в пределах файла считаются поштучно (решение 6).
- Заголовок всегда в первой физической строке; ведущие пустые строки перед заголовком → `UnknownFormatError`.
- Названия колонок сравниваются без учёта регистра/краевых пробелов.
- Нечитаемая в обеих кодировках выписка → `UnknownFormatError`.
- `fmt` с неизвестным значением → `UnknownFormatError`.
- Дублем считается только совпадение с транзакциями, уже лежавшими в хранилище до вызова, плюс поштучное «гашение».
- Поведение `import_csv` меняется: дубли не считаются в результате, BOM читается, запись атомарна; это согласуется с целью задачи и не ломает существующие тесты.
- Описание не нормализуется при хранении.

## Risks / Trade-offs

- [`import_csv` теперь пропускает дубли и CLI покажет меньшее число] → документируем в README, это цель задачи.
- [Файл в cp1251, случайно валидный как UTF-8] → крайне маловероятно для кириллицы; принято по условию задачи.
- [Большие файлы читаются целиком в память] → выписки небольшие; принято.
- [Поштучная дедупликация: два реальных различных платежа с одинаковыми полями после ручного удаления одного из хранилища снова добавятся] → ожидаемо.


### proposal.md

## Why

Пользователи приносят выписки банка «Сфера», а импорт умеет только «Нову». Текущий `import_csv` к тому же хрупкий: повторный импорт задваивает операции, одна кривая строка роняет импорт посреди файла (часть строк уже записана), файлы из Excel (UTF-8 с BOM) не читаются. Нужен единый вход, который сам определяет формат, не задваивает операции и честно сообщает о строках, которые не удалось разобрать.

## What Changes

- Новый публичный API в `ledger/importer.py`:
  - `import_statement(path, store, *, fmt=None, strict=False, categorizer=None, clock=None) -> ImportResult`
  - `detect_format(path) -> str` — `"nova"` | `"sfera"` | `"sfera_split"`
  - `normalize_description(text: str) -> str`
  - `@dataclass(frozen=True) RowError(line_no: int, message: str)`
  - `@dataclass(frozen=True) ImportResult(format: str, encoding: str, added: int, duplicates: int, errors: list[RowError])`
- Новые исключения в `ledger/errors.py`, оба наследуют `StatementError`: `UnknownFormatError`, `StatementRowError` (`line_no` заполнен).
- Поддержка форматов «Сферы»: `sfera` (`Дата;Сумма;Описание`) и `sfera_split` (`Дата;Описание;Приход;Расход`), а также «Новы».
- Автоопределение формата по заголовку и кодировки (UTF-8 с BOM или без, иначе cp1251).
- Пропуск дублей (дата + сумма + нормализованное описание), учёт в `duplicates`.
- Некорректные строки не роняют импорт (попадают в `errors`); `strict=True` — `StatementRowError` на первой ошибочной строке, в хранилище не попадает ничего.
- Мусорные строки (пустые, из пробелов, из одних разделителей) пропускаются молча.
- Запись в хранилище одной атомарной операцией `add_many`.
- `import_csv(path, store, categorizer=None, clock=None) -> int` остаётся с прежней сигнатурой и типом результата, реализуется поверх нового кода (только «Нова», строгий режим). Поведение меняется в сторону исправления: дубли пропускаются и не входят в возвращаемое число, файл с BOM читается, при ошибке строки в хранилище не остаётся частичных данных.

Не затрагиваются: `ledger/cli.py`, `ledger/reports.py`, публичный API `Transaction`, хранилищ и `Categorizer`; внешних зависимостей нет (только стандартная библиотека).

## Capabilities

### New Capabilities
- `statement-import`: импорт банковских выписок «Нова» и «Сфера» — определение формата и кодировки, разбор строк, дедупликация, отчёт об ошибках, строгий режим, совместимый `import_csv`.

### Modified Capabilities

## Impact

- Код: `ledger/importer.py` (основная работа), `ledger/errors.py` (два класса), `README.md` (описание форматов), новые тесты в `tests/`. Существующие тесты не меняются.
- CLI получает новое поведение `import_csv` (дедупликация, BOM) без изменения `cli.py`; сообщение `Imported N transactions` считает только реально добавленные.
- Зависимостей нет.


### specs/statement-import/spec.md

## ADDED Requirements

### Requirement: Единый вход импорта
Модуль `ledger/importer.py` MUST предоставлять `import_statement(path, store, *, fmt=None, strict=False, categorizer=None, clock=None) -> ImportResult`, `detect_format(path) -> str` и `normalize_description(text: str) -> str`. `ImportResult` — `@dataclass(frozen=True)` с полями `format: str`, `encoding: str`, `added: int`, `duplicates: int`, `errors: list[RowError]`. `RowError` — `@dataclass(frozen=True)` с полями `line_no: int`, `message: str`. `ImportResult.format` MUST быть одним из `"nova"`, `"sfera"`, `"sfera_split"`; `ImportResult.encoding` — `"utf-8"` или `"cp1251"`.

#### Scenario: Успешный импорт возвращает сводку
- **WHEN** импортируется корректный файл «Сферы» из двух строк в пустое хранилище
- **THEN** `ImportResult` содержит `format="sfera"`, `encoding="utf-8"`, `added=2`, `duplicates=0`, `errors=[]`

### Requirement: Определение формата
`detect_format` и `import_statement` при `fmt=None` MUST определять формат по строке заголовка (строка 1): `date,amount,description` — `nova`; `Дата;Сумма;Описание` — `sfera`; `Дата;Описание;Приход;Расход` — `sfera_split`. Названия колонок сравниваются без учёта регистра и пробелов по краям. Если заголовок не распознан (в том числе файл пустой) или не соответствует явно указанному `fmt` (включая неизвестное значение `fmt`), MUST выбрасываться `UnknownFormatError` независимо от `strict`, и в хранилище ничего не сохраняется.

#### Scenario: Автоопределение
- **WHEN** `detect_format` вызывается для файла с заголовком `Дата;Описание;Приход;Расход`
- **THEN** возвращается `"sfera_split"`

#### Scenario: Пустой файл
- **WHEN** импортируется пустой файл
- **THEN** бросается `UnknownFormatError`, хранилище не изменено

#### Scenario: Заголовок не подходит к явному fmt
- **WHEN** файл «Новы» импортируется с `fmt="sfera"` и `strict=False`
- **THEN** бросается `UnknownFormatError`, хранилище не изменено

### Requirement: Определение кодировки
Кодировка MUST определяться так: если файл целиком декодируется как UTF-8 (BOM допустим и отбрасывается), это `"utf-8"`; иначе файл читается как `cp1251` и кодировка — `"cp1251"`. Если файл не декодируется и как `cp1251`, MUST выбрасываться `UnknownFormatError`.

#### Scenario: Файл из Excel с BOM
- **WHEN** файл начинается с BOM UTF-8
- **THEN** заголовок распознаётся, `encoding="utf-8"`

#### Scenario: Файл в cp1251
- **WHEN** файл не является корректным UTF-8
- **THEN** он читается как cp1251, `encoding="cp1251"`

### Requirement: Формат «Нова»
Для `nova` разбор MUST идти так: разделитель `,`, дата ISO `ГГГГ-ММ-ДД`, сумма разбирается через `parse_amount`; правила разбора совпадают с текущим `import_csv`.

#### Scenario: Строка «Новы»
- **WHEN** строка `2026-03-01,-350.00,Кофейня Зерно`
- **THEN** создаётся транзакция на 2026-03-01 с суммой `-350.00`

### Requirement: Формат «Сфера»
Для `sfera` разбор MUST идти так: разделитель `;`, дата `ДД.ММ.ГГГГ`, сумма — с десятичной запятой, тысячи разделены пробелом или неразрывным пробелом (U+00A0, также U+202F); расход с `-`, приход без знака или с `+`. Допустимы только ASCII-цифры. Сумма другого вида (например, с точкой) — ошибка строки.

#### Scenario: Расход с неразрывным пробелом
- **WHEN** строка `01.03.2026;-1<U+00A0>200,50;Магазин Лента`
- **THEN** создаётся транзакция на 2026-03-01 с суммой `-1200.50`

#### Scenario: Приход с плюсом
- **WHEN** строка `02.03.2026;+85 000,00;Зарплата`
- **THEN** сумма транзакции `85000.00`

### Requirement: Формат «Сфера, раздельные колонки»
Для `sfera_split` колонки: `Дата;Описание;Приход;Расход`. Суммы записаны без знака; знак `+` или `-` в сумме — ошибка строки. Ровно одна из колонок `Приход`/`Расход` MUST быть заполнена (значение из одних пробелов считается пустым); иначе — ошибка строки. Сумма из `Расход` становится отрицательной. Формат дат и сумм — как в `sfera`.

#### Scenario: Расход
- **WHEN** строка `01.03.2026;Магазин Лента;;1 200,50`
- **THEN** сумма транзакции `-1200.50`

#### Scenario: Заполнены обе колонки
- **WHEN** в строке заполнены и `Приход`, и `Расход`
- **THEN** строка является ошибочной

#### Scenario: Сумма со знаком
- **WHEN** в колонке `Расход` указано `-100,00`
- **THEN** строка является ошибочной

### Requirement: Пропуск мусорных строк
Строки после заголовка, состоящие только из пробельных символов или только из разделителей формата и пробелов (`;;;` для «Сферы», `,,` для «Новы»), включая полностью пустые, MUST пропускаться где бы они ни стояли. Они не считаются ни ошибкой, ни дублем, ни добавленной транзакцией.

#### Scenario: Мусор в середине и в конце
- **WHEN** между корректными строками и после них стоят пустая строка, строка `;;;` и строка из пробелов
- **THEN** `errors=[]`, `duplicates=0`, `added` равен числу корректных строк

### Requirement: Ошибочные строки
Ошибочной считается строка, из которой нельзя собрать корректную `Transaction` (неверная дата, сумма, нулевая сумма, пустое описание, неверное число полей, нарушение правил формата). При `strict=False` такая строка MUST попадать в `ImportResult.errors` как `RowError` с `line_no` по правилам `StatementError` (физическая строка файла, заголовок — строка 1, пустые строки учитываются, многострочная запись в кавычках — строка её начала); остальные строки импортируются. Ошибки идут в порядке следования строк.

#### Scenario: Кривая строка посреди файла
- **WHEN** третья строка файла содержит неверную дату, остальные корректны
- **THEN** `errors` содержит один `RowError` с `line_no=3`, остальные строки добавлены

#### Scenario: Номер строки после пустых строк
- **WHEN** перед ошибочной строкой стоят две пустые строки
- **THEN** `line_no` учитывает пустые строки

### Requirement: Строгий режим
При `strict=True` на первой ошибочной строке MUST выбрасываться `StatementRowError` с заполненным `line_no`, и из файла в хранилище MUST NOT попадать ничего — ни в память, ни в JSON-файл `JsonFileStore`. Дубли и мусорные строки ошибками не являются.

#### Scenario: Ошибка в конце файла
- **WHEN** в файле 10 корректных строк и ошибочная 11-я (физическая строка 12), `strict=True`
- **THEN** бросается `StatementRowError` с `line_no == 12`, `store.all()` пуст, JSON-файл не создан и не изменён

#### Scenario: Только дубли
- **WHEN** все строки файла уже есть в хранилище, `strict=True`
- **THEN** исключения нет, `added=0`, `duplicates` равно числу строк

### Requirement: Пропуск дублей
Транзакция из файла является дублем, если в хранилище есть транзакция с той же датой, суммой и равным по `normalize_description` описанием. `normalize_description(text)` MUST давать тот же результат, что `ledger.rules.normalize_text` (обрезка и схлопывание пробелов, `casefold()`, `ё`→`е`). Дубли не добавляются и учитываются в `ImportResult.duplicates`. Сопоставление поштучное: каждая существующая транзакция «гасит» не более одной строки файла, поэтому две одинаковые покупки в одном файле при пустом хранилище добавляются обе, а повторный импорт того же файла добавляет 0. Описание сохраняется как в файле (после `strip`), без нормализации.

#### Scenario: Повторный импорт
- **WHEN** один и тот же файл импортируется дважды
- **THEN** второй вызов возвращает `added=0`, `duplicates` равно числу транзакций файла, хранилище не изменилось

#### Scenario: Различие в регистре и ё
- **WHEN** в хранилище есть «Ёлки», а в файле « елки » с той же датой и суммой
- **THEN** строка считается дублем

#### Scenario: Две одинаковые покупки
- **WHEN** в файле две одинаковые строки, в хранилище такой нет
- **THEN** `added=2`, `duplicates=0`; при повторном импорте `added=0`, `duplicates=2`

### Requirement: Атомарная запись
Все добавляемые транзакции MUST записываться в хранилище одним вызовом `add_many`; при любом исключении хранилище остаётся неизменным. Категоризация, `imported_at` (одно значение `clock.now()` на импорт, по умолчанию `SystemClock`) и описание транзакции — как в текущем `import_csv`.

#### Scenario: Категоризация
- **WHEN** передан `categorizer`
- **THEN** добавленные транзакции получают категорию первого подходящего правила, `imported_at` равен `clock.now()`

### Requirement: Совместимость import_csv
`import_csv(path, store, categorizer=None, clock=None) -> int` MUST сохранить сигнатуру и тип результата. Она импортирует выписку «Новы» (`fmt="nova"`) в строгом режиме и возвращает число добавленных транзакций. Ошибки — `StatementError` (в т.ч. подклассы) с `line_no`, как раньше.

#### Scenario: Ошибка строки
- **WHEN** `import_csv` читает файл с ошибочной третьей строкой
- **THEN** бросается `StatementError` с `line_no == 3`, хранилище не изменено

#### Scenario: Повторный вызов
- **WHEN** `import_csv` вызывается дважды для одного файла
- **THEN** второй вызов возвращает `0`
