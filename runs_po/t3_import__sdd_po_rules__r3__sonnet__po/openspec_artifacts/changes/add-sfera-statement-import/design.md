## Context

Сейчас `ledger/importer.py` содержит один `import_csv` для «Новы»: читает файл как UTF-8 (BOM ломает заголовок), добавляет транзакции по одной через `store.add` (ошибка посреди файла оставляет часть записанной), дедупликации нет. Описания в проекте сравниваются через `rules.normalize_text`. `MemoryStore.add_many` атомарно добавляет пачку (одна запись на диск у `JsonFileStore`). Требования — в `specs/statement-import/spec.md`, мотивация — в proposal.md.

## Goals / Non-Goals

**Goals:**
- Один разборщик для трёх форматов, общий для `import_statement` и `import_csv`.
- Атомарность: разбор и дедупликация целиком в памяти, затем один `add_many`.

**Non-Goals:**
- Изменения `cli.py`, `reports.py`, `Transaction`, хранилищ, `Categorizer`.
- Новые флаги CLI, внешние зависимости, поддержка других банков/разделителей.

## Decisions

1. **Чтение файла.** `bytes = Path.read_bytes()`; пробуем `decode("utf-8-sig")` (строго), при `UnicodeDecodeError` — `decode("cp1251")`; если и он падает — `UnknownFormatError`. Потом `io.StringIO(text, newline="")` в `csv.reader`. Альтернатива (`chardet`) отвергнута: нужна только стандартная библиотека. Кодировка по умолчанию `utf-8` для файла из чистого ASCII — допустимо.
2. **Формат по заголовку.** Заголовок берём из первой физической строки текста и для каждого формата разбираем её своим разделителем (`csv.reader`), нормализуя названия через `strip()`/`casefold()`. Формат подходит, если все его нужные колонки есть в заголовке; колонки находятся по названию в любом порядке, лишние игнорируются, индексы нужных колонок запоминаются (при повторе — первая). Порядок проверки: `nova`, `sfera` (есть `Сумма`), затем `sfera_split`; так заголовок с `Сумма` и `Приход`/`Расход` однозначно считается `sfera`. Пустой текст → `UnknownFormatError` без `line_no`; нераспознанный/несовпавший с `fmt` → с `line_no=1`. `detect_format` и `import_statement` используют общую внутреннюю функцию, чтобы не читать логику дважды.
3. **Номера строк.** Берём `reader.line_num` до чтения записи: номер начала записи = предыдущий `line_num` + 1. Это даёт физическую строку начала записи, в том числе после пустых строк и многострочных кавычек (согласуется с докстрингом `StatementError`). Альтернатива `enumerate` неверна для многострочных записей.
4. **Мусорные строки.** Запись считается мусором, если все поля после `strip()` пусты (покрывает `[]`, пробелы, `;;;`, `,,`). Проверка идёт до разбора, такие строки ни в какие счётчики не попадают. Лишние поля сверх заголовка игнорируются; ошибка «неверное число полей» — только если в строке меньше полей, чем нужно, чтобы достать все нужные колонки (индекс самой правой нужной колонки).
5. **Разбор значений.** Для «Новы» — переиспользуем текущую логику (`date.fromisoformat`, `parse_amount`). Для «Сферы» — дата по regex `^\d{2}\.\d{2}\.\d{4}$` (ASCII) + `date(y, m, d)`; сумма: убрать `" "`, U+00A0, U+202F, проверить regex `^[+-]?[0-9]+(,[0-9]{1,2})?$`, заменить `,`→`.`, дальше `parse_amount` (он же отсечёт ноль и лишние знаки через `Transaction`). Для `split`: каждая из двух колонок — пусто/пробелы либо сумма без знака по регексу; значение, равное нулю, считается пустой колонкой. Ровно одна ненулевая колонка, иначе ошибка; расход — `-amount`. Любой `ValidationError`/`ValueError` превращается в `RowError`/`StatementRowError` с `line_no`. Заменить `\d` на `[0-9]` важно: `\d` принимает не-ASCII цифры.
6. **Дедупликация.** Строим `Counter` по ключам `(date, amount, normalize_description(description))` из `store.all()`. Для каждой строки файла: если счётчик ключа > 0 — уменьшаем и считаем дублем, иначе добавляем в пачку. Так повторный импорт идемпотентен, а две одинаковые покупки в одном файле не склеиваются. Альтернатива «множество» склеила бы настоящие повторные покупки и отвергнута; альтернатива «дубль и внутри файла» — отвергнута по той же причине.
7. **`normalize_description`.** Тонкая обёртка над `rules.normalize_text` (одна реализация сравнения, поведение не расходится). Циклического импорта нет: `importer` уже импортирует `rules`.
8. **Строгий режим.** При `strict=True` первая ошибка → `StatementRowError(message, line_no=...)` до обращения к хранилищу; иначе ошибки копятся. Запись — только в конце, одним `store.add_many(batch)` (если пачка не пуста).
9. **Категоризация и время.** `imported_at = clock.now()` один раз на вызов; категория — как в текущем коде, через `dataclasses.replace` либо пересборку; описание — `strip()`.
10. **`import_csv`.** `return import_statement(path, store, fmt="nova", strict=True, categorizer=..., clock=...).added`. Тонкая обёртка сохраняет сигнатуру, тип и существующие тесты (ошибка строки → `StatementError` с `line_no`; отсутствующая колонка → `UnknownFormatError` с `line_no=1`).
11. **Исключения.** `UnknownFormatError` и `StatementRowError` — наследники `StatementError` без доп. полей; `StatementRowError` требует `line_no` (параметр keyword-only обязательный), конструктор остаётся совместимым.

## Допущения (в задаче не определено)

- Дубли в пределах файла считаются поштучно (решение 6).
- Заголовок всегда в первой физической строке; ведущие пустые строки перед заголовком → `UnknownFormatError`.
- Названия колонок сравниваются без учёта регистра/краевых пробелов.
- Нечитаемая в обеих кодировках выписка → `UnknownFormatError`.
- `fmt` с неизвестным значением → `UnknownFormatError`.
- Дублем считается только совпадение с транзакциями, уже лежавшими в хранилище до вызова, плюс поштучное «гашение».
- Поведение `import_csv` меняется: дубли не считаются в результате, BOM читается, запись атомарна; это согласуется с целью задачи и не ломает существующие тесты.
- Описание не нормализуется при хранении.

## Risks / Trade-offs

- [`import_csv` теперь пропускает дубли и CLI покажет меньшее число] → документируем в README, это цель задачи.
- [Файл в cp1251, случайно валидный как UTF-8] → крайне маловероятно для кириллицы; принято по условию задачи.
- [Большие файлы читаются целиком в память] → выписки небольшие; принято.
- [Поштучная дедупликация: два реальных различных платежа с одинаковыми полями после ручного удаления одного из хранилища снова добавятся] → ожидаемо.
