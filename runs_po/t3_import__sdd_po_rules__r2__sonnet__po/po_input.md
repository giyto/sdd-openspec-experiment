### design.md

## Context

Сейчас `import_csv` читает только «Нову» в UTF-8 и кладёт строки по одной через `store.add` (для `JsonFileStore` — запись на диск на каждую), падая на первой ошибке. `MemoryStore.add_many` атомарен (все или ни одной, одна запись на диск). Сравнение описаний в проекте — `rules.normalize_text` (пробелы, `casefold`, ё/е). См. `proposal.md` — зачем.

## Goals / Non-Goals

**Goals:**
- Один конвейер для трёх форматов; атомарная запись в хранилище.
- `import_csv` — тонкая обёртка, существующие тесты проходят без правок.

**Non-Goals:**
- Правки `cli.py`, `reports.py`, моделей и хранилищ.
- Поддержка других банков/разделителей, автодетект разделителя вне трёх заголовков.

## Decisions

1. **Конвейер: байты → декодирование → заголовок → строки → план → одна запись.** Файл читается целиком как bytes; `utf-8-sig` пробуем первым (покрывает UTF-8 с BOM и без), при `UnicodeDecodeError` — cp1251; если и он не декодирует (нет в таблице байта) — `UnknownFormatError`. Альтернатива (`chardet`-подобные эвристики) отвергнута: ТЗ задаёт правило явно.
2. **Таблица форматов**: для каждого формата — разделитель, кортеж заголовка и функция `row -> Transaction`. `detect_format` сопоставляет первую физическую строку (после BOM, поля обрезаны по краям, регистр учитывается) с таблицей. Явный `fmt` проверяется тем же сравнением; неизвестное имя `fmt` — `ValueError`. Файл без распознанного заголовка, в том числе пустой, — `UnknownFormatError` (`line_no=1`, для пустого файла `None`).
3. **Нумерация строк**: данные читаются `csv.reader` поверх итератора по физическим строкам (`io.StringIO(text, newline="")`) с обёрткой-счётчиком. Номер записи — номер первой физической строки, прочитанной для неё после пропуска полностью пустых строк (их csv пропускает сам, но счётчик их учитывает). Это даёт правило `StatementError`: пустые строки считаются, многострочная запись нумеруется по началу.
4. **Мусорная строка** — запись, где все поля после `strip()` пусты (или запись пустая). Проверяется до разбора формата, поэтому `;;;` и `,,` не дают ни ошибки, ни дубля.
5. **Разбор строк** (любое отклонение → `RowError`/`StatementRowError` через внутреннее исключение с сообщением):
   - число полей должно равняться числу колонок формата;
   - `nova`: как сейчас (`date.fromisoformat`, `parse_amount`);
   - `sfera`/`sfera_split`: дата по регулярке `\d{2}\.\d{2}\.\d{4}` и `dt.date(y, m, d)`; сумма — после удаления пробелов, U+00A0 и U+202F регулярка `[+-]?\d+(,\d{1,2})?`, затем запятая → точка и `parse_amount`; в `sfera_split` знак запрещён, «Расход» отрицается; ровно одна заполненная колонка;
   - сборка `Transaction` ловит `ValidationError` (нулевая сумма, пустое описание и т. п.) и превращает его в ошибку строки.
6. **Дедупликация**: ключ `(date, amount, normalize_description(description))`. Множество ключей строится из `store.all()` один раз и пополняется по ходу файла, так что повтор внутри файла — тоже дубль (иначе импорт двух идентичных платежей за день сломал бы идемпотентность повторного запуска). `normalize_description` делегирует `rules.normalize_text`, единый источник правды.
7. **Атомарность**: в цикле копится список новых транзакций (с категориями и общим `imported_at`), затем один вызов `store.add_many`. В `strict` первая ошибка бросает `StatementRowError` до обращения к `add_many`, поэтому ни память, ни JSON не затрагиваются. В нестрогом режиме тоже один `add_many` (если есть что добавлять) — меньше записей на диск. Альтернатива «add по одной с откатом» отвергнута: у хранилищ нет API отката.
8. **Исключения**: `UnknownFormatError` и `StatementRowError` — пустые наследники `StatementError` в `errors.py`; `StatementRowError(message, line_no=...)` использует тот же конструктор.
9. **`import_csv`** = `import_statement(path, store, fmt="nova", strict=True, categorizer=..., clock=...).added`. Существующие тесты: кривая строка → `StatementRowError` (`StatementError`, `line_no=3`); неверные колонки → `UnknownFormatError` с `line_no=1`; нулевая сумма и пустое описание — строки-ошибки.
10. **Категоризация** — как раньше: `categorizer.categorize(tx)`, при не-`None` результате `replace`/пересборка транзакции с категорией. Применяется только к недублям.

## Допущения

- Заголовки сравниваются точно (без учёта регистра не нормализуем); первая строка файла — заголовок, ведущие пустые строки перед ним не допускаются.
- Точка в суммах «Сферы» (`100.50`) — ошибка строки; только запятая как десятичный разделитель. Дата «Сферы» строго `ДД.ММ.ГГГГ`.
- Повтор строки внутри одного файла — дубль (см. решение 6).
- `import_csv` теперь тоже пропускает дубли и читает BOM/cp1251; это согласуется с целью задачи, возвращаемое значение — число реально добавленных.
- Неизвестное имя `fmt` вне трёх допустимых — `ValueError` (ошибка программиста, не данных).
- Несколько RowError на одну строку не создаются: сообщается первая найденная проблема.
- `OSError` при чтении файла не оборачивается (как сейчас).
- Все ошибки внутри `errors` упорядочены по возрастанию `line_no`.

## Risks / Trade-offs

- [Файл целиком в памяти] → выписки малы; упрощает определение кодировки.
- [cp1251 принимает почти любые байты, ошибочно прочитанный не-UTF-8 мусор даст «кракозябры»] → ТЗ задаёт именно такое правило.
- [Дубль внутри файла скрывает легитимные одинаковые платежи] → осознанный компромисс ради идемпотентности; фиксируется в допущениях.
- [Заголовок `Сфера` с лишними пробелами/регистром отвергается] → строгий `UnknownFormatError` безопаснее угадывания.


### proposal.md

## Why

Пользователи приносят выписки банка «Сфера» (два формата), а проект умеет только «Нову». Текущий `import_csv` к тому же хрупкий: повторный импорт задваивает операции, одна кривая строка роняет импорт посреди файла (часть строк уже записана), файлы UTF-8 с BOM из Excel не читаются (LEDGER-58).

## What Changes

- Новый единый вход `import_statement(path, store, *, fmt=None, strict=False, categorizer=None, clock=None) -> ImportResult` в `ledger/importer.py`.
- `detect_format(path) -> str` (`"nova"` | `"sfera"` | `"sfera_split"`) и `normalize_description(text: str) -> str` в `ledger/importer.py`.
- Новые `@dataclass(frozen=True)` `RowError(line_no, message)` и `ImportResult(format, encoding, added, duplicates, errors)` в `ledger/importer.py`.
- Новые исключения в `ledger/errors.py`: `UnknownFormatError(StatementError)` и `StatementRowError(StatementError)` (`line_no` заполнен).
- Поддержка форматов «Сфера» (`Дата;Сумма;Описание`) и `sfera_split` (`Дата;Описание;Приход;Расход`) наряду с «Новой».
- Определение кодировки: UTF-8 (BOM допустим) или cp1251.
- Пропуск дублей (дата + сумма + `normalize_description`), счётчик `duplicates`.
- Кривые строки собираются в `errors`; при `strict=True` первая такая строка бросает `StatementRowError`, и в хранилище не попадает ничего.
- Пустые/мусорные строки (пробелы, `;;;`, `,,`) пропускаются молча.
- `import_csv(path, store, categorizer=None, clock=None) -> int` сохраняет сигнатуру и тип результата, делегирует в `import_statement`; CLI не меняется.
- Нет **BREAKING**-изменений публичного API. Наблюдаемое отличие `import_csv`: больше не задваивает существующие операции и читает UTF-8 с BOM и cp1251.

## Capabilities

### New Capabilities
- `statement-import`: импорт банковских выписок («Нова», «Сфера», «Сфера split»): определение формата и кодировки, разбор строк, дедупликация, отчёт об ошибках, атомарность strict-режима.

### Modified Capabilities

- Не трогаем: `ledger/cli.py`, `ledger/reports.py`, публичный API `Transaction`, хранилищ, `Categorizer`.

### specs/statement-import/spec.md

## Purpose

Определяет, как проект импортирует банковские выписки в хранилище транзакций: распознавание формата и кодировки, разбор строк, пропуск дублей, отчёт об ошибках и гарантии атомарности.

## ADDED Requirements

### Requirement: Единая точка импорта
Система SHALL предоставлять `import_statement(path, store, *, fmt=None, strict=False, categorizer=None, clock=None) -> ImportResult`, `detect_format(path) -> str` и `normalize_description(text: str) -> str` в `ledger/importer.py`. `ImportResult` и `RowError` SHALL быть `@dataclass(frozen=True)` с полями `ImportResult(format, encoding, added, duplicates, errors)` и `RowError(line_no, message)`. `ImportResult.format` ∈ {`"nova"`, `"sfera"`, `"sfera_split"`}, `encoding` ∈ {`"utf-8"`, `"cp1251"`}, `errors` — `list[RowError]`. `UnknownFormatError` и `StatementRowError` SHALL быть определены в `ledger/errors.py` и наследовать `StatementError`.

#### Scenario: Успешный импорт возвращает отчёт
- **WHEN** импортируется корректный файл «Сферы» из 2 строк в пустое хранилище
- **THEN** `ImportResult` содержит `format="sfera"`, `added=2`, `duplicates=0`, `errors=[]`, а в хранилище 2 транзакции

### Requirement: Определение формата
При `fmt=None` система SHALL определять формат по заголовку (первая строка файла, после отбрасывания BOM): `date,amount,description` — `nova`; `Дата;Сумма;Описание` — `sfera`; `Дата;Описание;Приход;Расход` — `sfera_split`. Если заголовок не распознан, файл пуст или заголовок не соответствует явно заданному `fmt`, система SHALL бросить `UnknownFormatError` независимо от `strict` и ничего не сохранить. `detect_format` SHALL возвращать имя формата или бросать `UnknownFormatError`.

#### Scenario: Автоопределение
- **WHEN** вызывается `detect_format` для файла с заголовком `Дата;Описание;Приход;Расход`
- **THEN** возвращается `"sfera_split"`

#### Scenario: Явный формат не совпал с заголовком
- **WHEN** `fmt="nova"`, а заголовок файла `Дата;Сумма;Описание`
- **THEN** бросается `UnknownFormatError`, хранилище не изменено

#### Scenario: Пустой файл
- **WHEN** импортируется файл нулевого размера при `strict=False`
- **THEN** бросается `UnknownFormatError`, хранилище не изменено

### Requirement: Определение кодировки
Если файл целиком декодируется как UTF-8 (BOM допустим), система SHALL считать кодировку `"utf-8"`; иначе SHALL декодировать файл как cp1251 и сообщить `"cp1251"`. BOM не должен попадать в имя первой колонки. Файл, не декодируемый и как cp1251, SHALL приводить к `UnknownFormatError`.

#### Scenario: UTF-8 с BOM
- **WHEN** файл сохранён из Excel как UTF-8 с BOM
- **THEN** формат определяется, `encoding="utf-8"`, строки импортируются

#### Scenario: cp1251
- **WHEN** файл закодирован в cp1251
- **THEN** `encoding="cp1251"`, кириллица в описаниях прочитана корректно

### Requirement: Формат «Сфера»
Для `sfera` (разделитель `;`, колонки `Дата;Сумма;Описание`) система SHALL разбирать дату как `ДД.ММ.ГГГГ`, а сумму — как десятичное число с запятой, где тысячи отделены пробелом или неразрывным пробелом (U+00A0); расход записан с `-`, приход — без знака или с `+`. Описание SHALL сохраняться как пришло, с обрезкой краевых пробелов.

#### Scenario: Суммы с пробельными разделителями
- **WHEN** строка `01.03.2026;-1 200,50;Магазин Лента` (разделитель тысяч — обычный пробел или U+00A0)
- **THEN** добавляется транзакция 2026-03-01 с суммой `-1200.50`

#### Scenario: Приход со знаком и без
- **WHEN** суммы `+85 000,00` и `85 000,00`
- **THEN** обе становятся `85000.00`

### Requirement: Формат «Сфера split»
Для `sfera_split` (`Дата;Описание;Приход;Расход`) суммы SHALL быть без знака; знак в колонке — ошибка строки. Значение из «Расход» SHALL становиться отрицательной суммой. Ровно одна из колонок «Приход»/«Расход» SHALL быть заполнена; обе заполнены или обе пусты — ошибка строки. Формат сумм и дат — как в `sfera`.

#### Scenario: Расход
- **WHEN** строка `02.03.2026;Кофе;;350,00`
- **THEN** сумма транзакции `-350.00`

#### Scenario: Обе колонки заполнены
- **WHEN** строка `02.03.2026;Кофе;100,00;350,00`
- **THEN** строка попадает в `errors`

#### Scenario: Знак в сумме
- **WHEN** строка `02.03.2026;Кофе;;-350,00`
- **THEN** строка попадает в `errors`

### Requirement: Формат «Нова»
Для `nova` система SHALL сохранять прежний разбор: разделитель `,`, дата ISO, сумма с точкой по правилам `parse_amount`, поддержка кавычек.

#### Scenario: Нова через новый вход
- **WHEN** `import_statement` читает файл «Новы» из существующих тестов
- **THEN** получены те же транзакции, что давал `import_csv`

### Requirement: Пропуск дублей
Система SHALL пропускать транзакцию, у которой совпадают дата, сумма и `normalize_description(описание)` с транзакцией, уже находящейся в хранилище или встреченной ранее в том же файле, и увеличивать `duplicates`. `normalize_description` SHALL быть тем же сравнением описаний, что используется в проекте (пробелы, регистр, ё/е). Описание хранимой транзакции SHALL оставаться ненормализованным. Дубли не являются ошибками, в том числе при `strict=True`.

#### Scenario: Повторный импорт
- **WHEN** один и тот же файл импортируется дважды
- **THEN** второй вызов возвращает `added=0`, `duplicates=N`, хранилище не меняется

#### Scenario: Описание отличается регистром и пробелами
- **WHEN** в хранилище есть «Магазин Лента», а в файле «магазин  лента» с той же датой и суммой
- **THEN** строка считается дублем

#### Scenario: Разная сумма — не дубль
- **WHEN** дата и описание совпадают, а сумма отличается
- **THEN** транзакция добавляется

### Requirement: Нестрогий режим собирает ошибки строк
При `strict=False` строка, из которой нельзя собрать корректную `Transaction` (неверное число полей, дата, сумма, нулевая сумма, пустое описание, нарушение правил формата), SHALL попадать в `errors` как `RowError` с `line_no` по правилам `StatementError` (физическая строка файла, заголовок — 1, пустые строки считаются, многострочная запись нумеруется по первой строке), остальные строки SHALL импортироваться.

#### Scenario: Кривая строка среди корректных
- **WHEN** в файле из трёх строк данных вторая содержит дату `31.02.2026`
- **THEN** `added=2`, `errors` содержит один `RowError` с `line_no=3`

#### Scenario: Номер строки после пустых строк
- **WHEN** между заголовком и ошибочной записью две пустые строки
- **THEN** `line_no` ошибочной записи учитывает пустые строки

### Requirement: Строгий режим атомарен
При `strict=True` система SHALL на первой ошибочной строке бросить `StatementRowError` с заполненным `line_no`, и из этого файла в хранилище (память и JSON-файл) SHALL не попасть ни одной транзакции, включая корректные строки до ошибки.

#### Scenario: Ошибка в середине файла
- **WHEN** `strict=True`, строка 2 корректна, строка 3 кривая
- **THEN** бросается `StatementRowError` с `line_no=3`, `store.all()` пуст, JSON-файл хранилища не создан и не изменён

#### Scenario: Дубли в строгом режиме
- **WHEN** `strict=True`, а файл содержит дубли и корректные строки
- **THEN** исключения нет, `duplicates` посчитан

### Requirement: Мусорные строки пропускаются
Система SHALL молча пропускать строки, пустые или состоящие только из пробелов и разделителей (`;;;`, `,,`), в любом месте файла. Такая строка не является ошибкой, дублем или добавленной транзакцией, но учитывается в нумерации строк.

#### Scenario: Хвост из мусора
- **WHEN** после данных идут строки пустая, из пробелов и `;;;`
- **THEN** `errors=[]`, `duplicates=0`, `added` равно числу реальных строк, даже при `strict=True`

### Requirement: Категоризация, время и описание
Система SHALL применять `categorizer` (если передан) к каждой добавляемой транзакции, проставлять всем добавленным `imported_at = clock.now()` (одно значение на импорт; `SystemClock` по умолчанию) и сохранять описание как в текущем импорте (обрезка краевых пробелов).

#### Scenario: Категория и время
- **WHEN** импорт с `Categorizer` и `FixedClock`
- **THEN** транзакции имеют категории по правилам и `imported_at`, равный времени часов

### Requirement: Совместимость import_csv
`import_csv(path, store, categorizer=None, clock=None) -> int` SHALL сохранить сигнатуру и возвращать число добавленных транзакций. Он SHALL импортировать только формат «Нова» и работать в строгом режиме: первая кривая строка — `StatementError` с `line_no`, незнакомый заголовок — `StatementError` с `line_no=1`.

#### Scenario: Прежнее поведение на ошибках
- **WHEN** `import_csv` читает файл «Новы» с кривой строкой 3
- **THEN** бросается `StatementError` с `line_no=3` и в хранилище ничего не добавлено

#### Scenario: Повторный import_csv
- **WHEN** `import_csv` вызывается дважды на одном файле
- **THEN** второй вызов возвращает `0`
