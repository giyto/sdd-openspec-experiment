## Why

Маркетинг запускает летнюю кампанию с промокодами (SHOP-412). Сейчас скидки вручную делает поддержка, и суммы расходятся с чеками. Нужна поддержка промокодов в расчёте и оформлении заказа, чтобы скидка попадала в итоги и построчно в чек (бухгалтерия считает налог по строкам).

## What Changes

- Новый модуль `shop/promo.py`: `DiscountKind`, `PromoCode`, `PromoRegistry` (реестр с внедрёнными часами и счётчиком использований).
- Новые исключения `PromoError` → `UnknownPromoCodeError`, `PromoExpiredError`, `PromoConditionsError` (три независимых наследника).
- `calculate_total` принимает необязательный `promo`; `LineTotal.discount` и `OrderTotal.discount` (по умолчанию `0.00`); скидка раскладывается по строкам без остатка, налог считается с суммы строки после скидки; порог бесплатной доставки сравнивается с суммой товаров после скидки.
- `OrderService` принимает `promos`, `quote`/`place_order` принимают `promo_code`; `Order.promo_code` хранит нормализованный код. Использование засчитывается только при успешном `place_order` и возвращается при отмене заказа (`cancel`).
- Обратная совместимость: старые вызовы дают прежние суммы. Не **BREAKING**.
- Вне рамок: `shop/cli.py`, `shop/reports.py` (отдельный тикет), существующие тесты не меняются.

## Capabilities

### New Capabilities
- `promo-codes`: определение промокода, его валидация, реестр, проверки существования/срока/лимита, учёт использований.
- `promo-pricing`: расчёт скидки, распределение по строкам, налог после скидки, условия заказа в `calculate_total`.
- `promo-orders`: передача кода в `quote`/`place_order`, обработка пустого кода, сохранение в заказе, учёт использования.

## Impact

- Код: `shop/promo.py` (новый), `shop/errors.py`, `shop/pricing.py`, `shop/orders.py`.
- Тесты: новые файлы в `tests/`, существующие не меняются.
- Зависимости: нет (только стандартная библиотека). Публичный API расширяется обратно-совместимо.
