## Why

Пользователи приносят выписки банка «Сфера» (два формата), а импорт умеет только «Нову». Текущий импорт к тому же хрупкий: повторный импорт задваивает операции, одна кривая строка роняет импорт посреди файла (часть строк уже записана), файлы из Excel (UTF-8 с BOM) не читаются. См. LEDGER-58.

## What Changes

- Новый единый вход `import_statement` (+ `detect_format`, `normalize_description`, `RowError`, `ImportResult`): сам определяет формат (`nova`, `sfera`, `sfera_split`) и кодировку (UTF-8 с BOM/без, cp1251).
- Пропуск дублей (дата + сумма + нормализованное описание) с подсчётом в `duplicates`; сверка с учётом идёт по количеству вхождений (мультимножество): уже сохранённые N одинаковых операций «гасят» не более N одинаковых строк файла.
- Кривые строки собираются в `errors`, остальное импортируется; режим `strict=True` — при первой ошибочной строке не сохраняется ничего.
- Пустые/пробельные/«только разделители» строки пропускаются молча, где бы ни стояли.
- Новые исключения `UnknownFormatError` и `StatementRowError` (наследники `StatementError`).
- `import_csv` сохраняет сигнатуру и возвращаемый `int`, но становится тонкой обёрткой над `import_statement` (строгий режим, автоопределение формата). Поведение меняется, не ломая существующие тесты: повторный импорт не задваивает операции, запись атомарна, CLI «из коробки» принимает выписки «Сферы». Строка «Imported N» показывает только реально добавленные.
