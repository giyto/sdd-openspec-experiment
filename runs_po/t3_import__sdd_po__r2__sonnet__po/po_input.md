### design.md

## Context

`ledger/importer.py` содержит только `import_csv` для «Новы»: читает UTF-8, пишет `store.add` построчно, на первой ошибке падает с частичной записью. Сравнение описаний в проекте — `rules.normalize_text`. `MemoryStore.add_many` атомарно добавляет пачку (в `JsonFileStore` — одна запись на диск). `cli.py` менять нельзя, он вызывает `import_csv`. Требования — в `specs/statement-import/spec.md`.

## Goals / Non-Goals

**Goals:** один вход `import_statement`; атомарная запись; обратная совместимость `import_csv` и существующих тестов.

**Non-Goals:** изменения CLI (вывод дублей/ошибок, флаг `--strict`), отчётов, моделей и хранилищ; другие банки; автоопределение произвольного разделителя.

## Decisions

1. **Конвейер «разобрать всё → потом записать».** Декодирование → поиск заголовка → разбор строк в результаты (`Transaction` или ошибка) → дедупликация → один `store.add_many`. Так `strict` не пишет ничего, а нестрогий режим не оставляет частичных записей. Если добавлять нечего, `add_many` не вызывается (JSON не переписывается и не создаётся).
2. **Кодировка:** `bytes.decode("utf-8-sig")`, при `UnicodeDecodeError` — `decode("cp1251")`; неудача и там — `UnknownFormatError`. Файл читается целиком. Эвристики (chardet) отвергнуты: нет сторонних библиотек, правило задано в задаче.
3. **CSV:** текст в `csv.reader(io.StringIO(text, newline=""))`; разделитель задан форматом. Номер строки записи = `reader.line_num` предыдущей записи + 1 (физическая нумерация, пустые строки учитываются, многострочная запись — по строке начала). `enumerate` по записям не подходит: `csv` пропускает пустые строки и счёт сбивается.
4. **Заголовок:** первая не мусорная запись. Для каждой схемы (`nova` с `,`, `sfera`/`sfera_split` с `;`) первая строка разбирается своим разделителем, требуемые колонки ищутся по имени (casefold + strip); порядок и лишние колонки допускаются (как было у `DictReader`). Наборы колонок `sfera` и `sfera_split` различаются, неоднозначности нет. `detect_format(path)` и импорт используют одну функцию. Нераспознанный заголовок непустого файла → `UnknownFormatError(line_no=1)` (требуется существующему тесту); для файла без непустых строк `line_no=None`.
5. **Мусорная строка** — все ячейки пусты после `strip()` (NBSP тоже пробельный). Проверяется до разбора полей, поэтому не может стать ошибкой или дублем.
6. **Разбор значений.** `nova` — как сейчас (`date.fromisoformat`, `parse_amount`). `sfera`: дата по `^\d{2}\.\d{2}\.\d{4}$`; сумма: регулярка `^[+-]?(\d{1,3}([  ]\d{3})+|\d+)(,\d{1,2})?$` на обрезанном тексте, затем пробелы убираются, `,`→`.`, дальше `parse_amount`. `sfera_split`: то же без знака, ровно одна колонка непуста, расход — отрицательный. Все `ValidationError` модели оборачиваются в ошибку строки. Недостаток полей — ошибка; лишние непустые ячейки — ошибка (не терять данные молча), лишние пустые игнорируются.
7. **Дедупликация:** множество ключей `(date, amount, normalize_description(description))` из `store.all()` на начало импорта. `normalize_description` делегирует `rules.normalize_text` — единственный источник правды. Ключи строк файла в множество не добавляются: две одинаковые покупки в одном файле легитимны, а повторный импорт всё равно идемпотентен. Альтернативы (мультимножество, добавление ключей по ходу) отвергнуты: требованием не заданы.
8. **Ошибки:** строка разбирается функцией, бросающей `StatementRowError`; в нестрогом режиме он ловится и превращается в `RowError(line_no, message)`, в строгом — пробрасывается сразу, до записи. `UnknownFormatError` и `StatementRowError` — наследники `StatementError`.
9. **`import_csv`** = `import_statement(path, store, strict=True, categorizer=..., clock=...).added`. Строгость сохраняет прежний контракт «плохая строка → `StatementError`»; автоопределение даёт CLI поддержку «Сферы» без правок `cli.py`.
10. **Категоризация и время:** `imported_at = clock.now()` один раз; категория через `Categorizer.categorize` и `dataclasses.replace`; описание `.strip()` как раньше. Логирование — через модульный `logger`.

## Risks / Trade-offs

- [`import_csv` теперь пропускает дубли, а CLI пишет «Imported N» без упоминания пропущенных] → допустимо рамками (CLI не трогаем); вынести в follow-up.
- [Легитимная повторяющаяся операция из нового файла совпадёт с уже сохранённой и станет дублем] → принятое ограничение определения «дубль» из тикета.
- [Строгое число полей отвергнет файлы с неэкранированным `;` в описании] → ошибка строки честнее тихого усечения.
- [Файл читается целиком в память] → выписки небольшие.

## Допущения (в тикете не определено)

- Мусорные строки пропускаются и до заголовка; файл только из мусора приравнен к пустому.
- Недекодируемый файл (ни UTF-8, ни cp1251) и неизвестное значение формата → `UnknownFormatError`.
- Разделители тысяч: пробел или U+00A0, группы по три цифры; прочие формы (точка, U+2212 и т. п.) — ошибка строки.
- Сообщение в `RowError` — без префикса `line N:`.
- Дубли внутри одного файла не считаются дублями (сверка только со снимком хранилища).


### proposal.md

## Why

Пользователи приносят выписки банка «Сфера» (два формата), а импорт умеет только «Нову». Текущий импорт к тому же хрупкий: повторный импорт задваивает операции, одна кривая строка роняет импорт посреди файла (часть строк уже записана), файлы из Excel (UTF-8 с BOM) не читаются. См. LEDGER-58.

## What Changes

- Новый единый вход `import_statement` (+ `detect_format`, `normalize_description`, `RowError`, `ImportResult`): сам определяет формат (`nova`, `sfera`, `sfera_split`) и кодировку (UTF-8 с BOM/без, cp1251).
- Пропуск дублей (дата + сумма + нормализованное описание) с подсчётом в `duplicates`.
- Кривые строки собираются в `errors`, остальное импортируется; режим `strict=True` — при первой ошибочной строке не сохраняется ничего.
- Пустые/пробельные/«только разделители» строки пропускаются молча, где бы ни стояли.
- Новые исключения `UnknownFormatError` и `StatementRowError` (наследники `StatementError`).
- `import_csv` сохраняет сигнатуру и возвращаемый `int`, но становится тонкой обёрткой над `import_statement` (строгий режим, автоопределение формата). Поведение меняется, не ломая существующие тесты: повторный импорт не задваивает операции, запись атомарна, CLI «из коробки» принимает выписки «Сферы». Строка «Imported N» показывает только реально добавленные.

## Capabilities

### New Capabilities
- `statement-import`: импорт банковских выписок (форматы, кодировка, дедупликация, обработка ошибок строк, атомарность).

### Modified Capabilities

## Impact

- Код: `ledger/importer.py`, `ledger/errors.py`, README (таблица модулей и описание форматов), новые тесты.
- Не трогаем: `ledger/cli.py`, `ledger/reports.py`; публичный API `Transaction`, хранилищ и `Categorizer` без изменений; только стандартная библиотека.
- Нет миграции данных хранилища.


### specs/statement-import/spec.md

## Purpose

Единый импорт банковских выписок («Нова», «Сфера», «Сфера» с разделёнными колонками) в хранилище транзакций: без дублей, с понятными ошибками и без частичной записи в строгом режиме.

## ADDED Requirements

### Requirement: Определение формата
Система SHALL определять формат выписки по строке заголовка. Поддерживаются `nova` (разделитель `,`, колонки `date,amount,description`), `sfera` (разделитель `;`, колонки `Дата;Сумма;Описание`) и `sfera_split` (разделитель `;`, колонки `Дата;Описание;Приход;Расход`). Имена колонок сравниваются без учёта регистра и крайних пробелов. Если формат указан явно, заголовок MUST ему соответствовать. Если заголовок не распознан, не соответствует явно указанному формату, значение формата неизвестно или файл не содержит ни одной непустой строки, система MUST бросить `UnknownFormatError` в любом режиме (`strict` или нет) и MUST NOT сохранять ничего.

#### Scenario: Автоопределение
- **WHEN** импортируется файл с заголовком `Дата;Описание;Приход;Расход` и формат не задан
- **THEN** формат результата — `sfera_split`

#### Scenario: Заголовок не подходит к явному формату
- **WHEN** файл «Новы» импортируется с явным форматом `sfera`
- **THEN** бросается `UnknownFormatError`, хранилище не меняется

#### Scenario: Пустой файл
- **WHEN** импортируется файл нулевой длины или состоящий только из пустых строк
- **THEN** бросается `UnknownFormatError` (в том числе при `strict=False`)

### Requirement: Определение кодировки
Система SHALL читать файл как UTF-8 (BOM допустим и отбрасывается), если он целиком декодируется как UTF-8, иначе как cp1251. В результате кодировка — `utf-8` или `cp1251`. Если файл не декодируется и как cp1251, система MUST бросить `UnknownFormatError` без сохранения.

#### Scenario: Файл из Excel
- **WHEN** файл «Сферы» сохранён в UTF-8 с BOM
- **THEN** заголовок распознаётся, кодировка результата `utf-8`

#### Scenario: Windows-кодировка
- **WHEN** файл сохранён в cp1251
- **THEN** описания читаются корректно, кодировка результата `cp1251`

### Requirement: Разбор формата «Сфера»
В формате `sfera` дата MUST иметь вид `ДД.ММ.ГГГГ`. Сумма: необязательный знак `+` или `-`, целая часть с необязательными разделителями тысяч (обычный или неразрывный пробел, группы по три цифры), необязательная дробная часть через запятую (1–2 цифры). Расход — отрицательная сумма, приход — положительная (знак `+` или отсутствие знака).

#### Scenario: Суммы с пробелами
- **WHEN** строка `01.03.2026;-1 200,50;Магазин Лента` (пробел может быть U+00A0)
- **THEN** добавляется транзакция от 2026-03-01 с суммой `-1200.50`

#### Scenario: Приход со знаком и без
- **WHEN** суммы `+85 000,00` и `85 000,00`
- **THEN** обе становятся `85000.00`

### Requirement: Разбор формата «Сфера» с разделёнными колонками
В формате `sfera_split` суммы в колонках `Приход` и `Расход` MUST быть без знака; наличие знака — ошибка строки. Ровно одна из двух колонок MUST быть заполнена, иначе строка ошибочна. Значение из `Расход` становится отрицательной суммой. Дата и формат числа — как в `sfera`.

#### Scenario: Расход
- **WHEN** строка `02.03.2026;Кофе;;350,00`
- **THEN** сумма транзакции `-350.00`

#### Scenario: Обе колонки или ни одной
- **WHEN** в строке заполнены обе колонки либо обе пусты (но строка не мусорная)
- **THEN** строка — ошибка

#### Scenario: Знак в сумме
- **WHEN** в колонке `Приход` стоит `+100,00` или в `Расход` стоит `-100,00`
- **THEN** строка — ошибка

### Requirement: Мусорные строки
Система SHALL молча пропускать строки, где все ячейки пусты после удаления крайних пробельных символов (пустая строка, пробелы, `;;;`, `,,`), на любой позиции файла, в том числе до заголовка. Такая строка не ошибка, не дубль и не добавленная транзакция; она не учитывается ни в одном счётчике.

#### Scenario: Мусор в конце и середине
- **WHEN** после данных или между ними идут строки `;;;`, пустые и из пробелов
- **THEN** список ошибок пуст, `duplicates` не растёт, `added` равен числу настоящих транзакций

### Requirement: Дедупликация
Система SHALL пропускать транзакцию, у которой в хранилище на момент начала импорта уже есть транзакция с той же датой, суммой и описанием, и считать её в `duplicates`. Описания сравниваются той же нормализацией, что и в остальном проекте (пробелы, регистр, «ё»/«е»). Транзакции внутри одного файла между собой дублями не считаются. Хранимое описание не нормализуется. Дубль не является ошибкой, в том числе при `strict=True`.

#### Scenario: Повторный импорт
- **WHEN** один и тот же файл импортируется дважды
- **THEN** второй раз `added == 0`, `duplicates` равен числу транзакций файла, хранилище не меняется

#### Scenario: Отличие только в регистре и пробелах
- **WHEN** в хранилище есть «Магазин  Лента», а в файле «магазин лента» с той же датой и суммой
- **THEN** строка считается дублем

### Requirement: Ошибки строк
Ошибочная строка — любая, из которой нельзя собрать корректную транзакцию (неверная дата или сумма, нулевая сумма, пустое описание, неверное число полей, нарушение правил формата). При `strict=False` такая строка MUST попасть в `errors` с номером строки и сообщением, а остальные строки импортируются. Номер строки — физический номер в файле: заголовок — 1, пустые строки считаются, многострочная запись нумеруется по строке начала.

#### Scenario: Кривая строка среди нормальных
- **WHEN** строка 3 содержит дату `31.02.2026`, остальные корректны
- **THEN** корректные строки добавлены, в `errors` одна запись с номером строки 3

### Requirement: Строгий режим
При `strict=True` система MUST бросить `StatementRowError` с заполненным номером строки на первой ошибочной строке, и из файла в хранилище MUST NOT попасть ничего — ни в память, ни в JSON-файл.

#### Scenario: Ошибка после валидных строк
- **WHEN** строки 2–4 корректны, строка 5 ошибочна, `strict=True`
- **THEN** бросается `StatementRowError` с номером строки 5, хранилище и JSON-файл не изменились

### Requirement: Атомарность и метаданные
Добавляемые транзакции SHALL записываться в хранилище одной пачкой. Все добавленные получают время импорта из переданных часов (один момент на весь импорт); категория определяется переданным категоризатором, если он задан; описание сохраняется обрезанным по краям, как в прежнем импорте.

#### Scenario: Категоризация
- **WHEN** задан категоризатор с подходящим правилом
- **THEN** транзакция сохраняется с категорией и временем импорта от часов

### Requirement: Совместимость прежнего импорта
Прежняя функция импорта CSV SHALL сохранить сигнатуру и возвращать число добавленных транзакций (целое). Она работает в строгом режиме с автоопределением формата: повторный импорт не задваивает операции, ошибки выписки поднимаются как `StatementError` (нераспознанный заголовок непустого файла — с номером строки 1).

#### Scenario: Повторный импорт через прежний вход
- **WHEN** один файл импортируется дважды прежней функцией
- **THEN** первый вызов возвращает число транзакций файла, второй — `0`
