### design.md

## Context

Сейчас `ledger/importer.py` читает только «Нову» через `csv.DictReader` и пишет транзакции по одной (`store.add`) — отсюда частичная запись при ошибке. В `MemoryStore`/`JsonFileStore` уже есть `add_many` — всё-или-ничего, одна запись на диск. Сравнение описаний в проекте — `rules.normalize_text`. Нумерация строк — по `StatementError`. Мотивация — см. proposal.md.

## Goals / Non-Goals

**Goals:** один путь импорта для всех форматов; атомарная запись; детерминированный отчёт.

**Non-Goals:** правки `cli.py`, `reports.py`, моделей и хранилищ; вывод `ImportResult` в CLI; новые зависимости.

## Decisions

1. **Конвейер «разобрать всё → решить → записать одной пачкой».** Разбираем весь файл в память по порядку, собираем новые транзакции, ошибки и счётчик дублей. Если `strict` и есть ошибка — бросаем `StatementRowError` для первой до обращения к записи. Иначе один вызов `store.add_many(new)`; при пустом списке не вызываем, чтобы не создавать JSON-файл зря. Альтернатива — `add` по строке с откатом: у хранилищ отката нет.
2. **Кодировка:** читаем байты; `decode("utf-8-sig")`, при `UnicodeDecodeError` — `decode("cp1251")`; если и это падает (недопределённые байты) — `UnknownFormatError`. В результате имя `utf-8` либо `cp1251`.
3. **Текст → записи:** `csv.reader(io.StringIO(text, newline=""), delimiter=...)`; начало записи = `reader.line_num` до чтения + 1, что даёт физические номера с учётом пустых строк и многострочных кавычек. `csv.Error` на записи → `RowError` на этой строке, чтение продолжается.
4. **Формат по заголовку:** первая запись, ячейки `strip().casefold()`. `nova` — разделитель `,`, обязательные колонки в любом порядке, лишние допускаются (как в прежнем `DictReader`); `sfera`/`sfera_split` — `;` и точное совпадение последовательности колонок. Строки данных `nova` с числом полей меньше заголовка — ошибка (как раньше «not enough fields»); для «Сферы» число полей должно совпасть точно. `detect_format` и `import_statement` используют одну внутреннюю функцию. Неизвестное значение `fmt` → `UnknownFormatError`.
5. **Мусор:** запись мусорная, если после удаления из всех ячеек пробельных символов (включая U+00A0), `;` и `,` ничего не остаётся. Проверка раньше разбора, поэтому `,,` в файле «Сферы» и `;;;` в «Нове» тоже мусор.
6. **Суммы «Сферы»:** регулярка `^[+-]?(\d{1,3}([   ]\d{3})+|\d+)(,\d{1,2})?$` (для `sfera_split` — без знака), затем пробелы убираются, `,`→`.` и вызывается `parse_amount`. Ноль, пустое описание и т.п. ловятся конструктором `Transaction`; `ValidationError` → ошибка строки. Даты «Сферы» — строго `ДД.ММ.ГГГГ`, «Новы» — как раньше `fromisoformat`. Минус U+2212 и точка как десятичный разделитель не принимаются — строка ошибочна (честнее, чем угадывать).
7. **Дедупликация — мультимножество:** ключ `(date, amount, normalize_description(description))`; `Counter` по снимку `store.all()` до импорта, каждое совпадение уменьшает счётчик. Повторный импорт идемпотентен, а две реальные одинаковые покупки в одном файле не склеиваются. Альтернатива «множество» теряла бы легитимные операции.
8. **`normalize_description`** — тонкая обёртка над `rules.normalize_text` (единый источник правды; `importer` уже импортирует `rules`).
9. **Исключения:** `UnknownFormatError(StatementError)`; `StatementRowError(StatementError)` с обязательным `line_no`. `RowError.message` — исходное сообщение без префикса `line N:`.
10. **`import_csv`** = `import_statement(path, store, strict=True, categorizer=..., clock=...).added`.
11. **Категоризация** — как раньше: `categorizer.categorize(tx)`, при результате — `dataclasses.replace`; `imported_at` берётся один раз из `clock.now()`.

## Risks / Trade-offs

- [Изменение поведения `import_csv`: дубли пропускаются, принимаются форматы «Сферы»] → описано в proposal; существующие тесты проходят без правок (ошибки строк по-прежнему `StatementError` с теми же `line_no`).
- [Мультимножество вместо множества для дублей — спорный момент для продакта] → решение принято и зафиксировано в спеке; смена — локальная правка.
- [Весь файл в памяти] → выписки малы; взамен проще атомарность.
- [Файл «Новы» с BOM теперь читается, раньше падал] → ожидаемо.

## Open Questions

- Нужно ли показывать `duplicates`/`errors` в CLI? Вне рамок (CLI не трогаем); отдельная задача.


### proposal.md

## Why

Пользователи приносят выписки банка «Сфера» (два формата), а импорт умеет только «Нову». Текущий импорт к тому же хрупкий: повторный импорт задваивает операции, одна кривая строка роняет импорт посередине (часть строк уже записана), файлы из Excel (UTF-8 с BOM) не читаются. Задача LEDGER-58.

## What Changes

- Новый единый вход `import_statement` в `ledger/importer.py`: сам определяет формат (`nova`, `sfera`, `sfera_split`) по заголовку и кодировку (UTF-8 с BOM или без / cp1251), возвращает `ImportResult` (формат, кодировка, `added`, `duplicates`, `errors`).
- Новые `detect_format` и `normalize_description` (последняя — то же сравнение описаний, что `rules.normalize_text`).
- Пропуск дублей (дата + сумма + нормализованное описание) относительно того, что уже в хранилище.
- Мусорные строки (пустые, из пробелов, из одних разделителей) пропускаются молча, где бы ни стояли.
- Кривые строки: в обычном режиме собираются в `errors`, остальное импортируется; при `strict=True` — `StatementRowError` на первой, в хранилище не попадает ничего (запись одной пачкой).
- Новые исключения `UnknownFormatError` и `StatementRowError` (наследники `StatementError`).
- `import_csv` сохраняет сигнатуру и возврат `int` (число добавленных), но делегирует в `import_statement` (автоопределение формата, `strict=True`). **Поведенческое отличие**: повторный импорт больше не задваивает операции, импорт атомарен, поддержаны BOM/cp1251, а форматы «Сферы» становятся доступны и CLI без правок `cli.py`.
- Не меняются: `ledger/cli.py`, `ledger/reports.py`, существующие тесты, публичный API `Transaction`/хранилищ/`Categorizer`. Только стандартная библиотека.

### specs/statement-import/spec.md

## Purpose

Импорт банковских выписок («Нова», «Сфера») в хранилище транзакций: определение формата и кодировки, защита от дублей, честный отчёт о строках, которые не удалось разобрать.

## ADDED Requirements

### Requirement: Определение формата по заголовку
Система SHALL определять формат выписки по заголовку (первая физическая строка): `nova` (`date,amount,description`, разделитель `,`), `sfera` (`Дата;Сумма;Описание`), `sfera_split` (`Дата;Описание;Приход;Расход`). Названия колонок сравниваются без учёта регистра и пробелов по краям; BOM в начале файла не мешает. Если формат передан явно, а заголовок ему не соответствует, либо заголовок не распознан (в том числе файл пустой), система SHALL бросить `UnknownFormatError` независимо от `strict` и ничего не сохранить. У `UnknownFormatError` `line_no` равен 1, если в файле есть непустая первая строка, иначе `None`.

#### Scenario: Автоопределение
- **WHEN** импортируется файл с заголовком `Дата;Описание;Приход;Расход` и формат не задан
- **THEN** результат имеет формат `sfera_split`

#### Scenario: Явный формат не подходит
- **WHEN** файл «Сферы» импортируется с явным форматом `nova`
- **THEN** бросается `UnknownFormatError`, хранилище не изменено

#### Scenario: Пустой файл
- **WHEN** импортируется файл нулевой длины
- **THEN** бросается `UnknownFormatError` с `line_no=None`

#### Scenario: Нераспознанный заголовок
- **WHEN** заголовок `foo,bar`
- **THEN** бросается `UnknownFormatError` с `line_no=1`, в обычном и в строгом режиме

### Requirement: Определение кодировки
Система SHALL считать кодировку `utf-8`, если весь файл читается как UTF-8 (BOM допустим), иначе `cp1251`. Файл, не читающийся ни так, ни так, приводит к `UnknownFormatError` без изменений в хранилище. Выбранная кодировка возвращается в результате.

#### Scenario: UTF-8 с BOM
- **WHEN** файл сохранён из Excel как UTF-8 с BOM
- **THEN** он читается, заголовок распознаётся, кодировка в результате — `utf-8`

#### Scenario: cp1251
- **WHEN** файл закодирован в cp1251
- **THEN** кириллица читается корректно, кодировка в результате — `cp1251`

### Requirement: Разбор формата «Сфера»
Для `sfera` система SHALL разбирать дату как `ДД.ММ.ГГГГ`, сумму как число с десятичной запятой и необязательным знаком (`-` расход, `+` или без знака приход); тысячи отделяются обычным пробелом или U+00A0 (группы по три цифры). Описание хранится с обрезанными краевыми пробелами, как в импорте «Новы». Строка, из которой не собирается корректная транзакция (неверная дата, сумма, нулевая сумма, пустое описание, неверное число полей), является ошибочной.

#### Scenario: Сумма с неразрывным пробелом
- **WHEN** строка `01.03.2026;-1 200,50;Магазин Лента` (разделитель тысяч U+00A0)
- **THEN** добавляется расход `-1200.50` на 2026-03-01

#### Scenario: Приход со знаком плюс
- **WHEN** строка `02.03.2026;+85 000,00;Зарплата`
- **THEN** добавляется приход `85000.00`

#### Scenario: Некорректная сумма
- **WHEN** сумма равна `1,234,50`, `12 34,00` или `abc`
- **THEN** строка попадает в ошибки

### Requirement: Разбор формата «Сфера» с раздельными колонками
Для `sfera_split` система SHALL брать сумму из колонки «Приход» (положительная) или «Расход» (становится отрицательной). Суммы пишутся без знака; знак `+`/`-` — ошибка строки. Заполнена должна быть ровно одна из двух колонок; обе заполнены или обе пусты — ошибка строки. Дата, разделители тысяч и описание — как в `sfera`.

#### Scenario: Расход
- **WHEN** строка `03.03.2026;Кофейня;;350,00`
- **THEN** добавляется сумма `-350.00`

#### Scenario: Знак в сумме
- **WHEN** строка `03.03.2026;Кофейня;;-350,00`
- **THEN** строка ошибочна

#### Scenario: Обе колонки
- **WHEN** заполнены и «Приход», и «Расход»
- **THEN** строка ошибочна

### Requirement: Мусорные строки пропускаются
Система SHALL пропускать строки, в которых нет ничего, кроме пробельных символов и разделителей (`;`, `,`): пустые, из пробелов, `;;;`, `,,` — в любом месте файла. Такая строка не является ошибкой, дублем или добавленной транзакцией; номера последующих строк при этом не сдвигаются.

#### Scenario: Мусор в середине и в конце
- **WHEN** файл содержит пустую строку, строку `;;;` и строку из пробелов между валидными строками и после них
- **THEN** список ошибок пуст, число дублей не растёт, число добавленных равно числу валидных строк

### Requirement: Пропуск дублей
Система SHALL пропускать транзакцию, если в хранилище до начала импорта уже есть транзакция с той же датой, суммой и описанием; описания сравниваются так же, как везде в проекте (пробелы, регистр, ё/е), пропущенные строки считаются в числе дублей. Каждая транзакция хранилища «гасит» не более одной строки файла: две одинаковые строки в файле при одной такой записи в хранилище дают одну добавленную и один дубль. Категория в сравнении не участвует. Описание в хранилище сохраняется как пришло.

#### Scenario: Повторный импорт
- **WHEN** один и тот же файл импортируется дважды
- **THEN** второй импорт добавляет 0, число дублей равно числу валидных строк, хранилище не изменилось

#### Scenario: Различия в написании описания
- **WHEN** в хранилище «Магазин Лента», а в файле «магазин  лента»
- **THEN** строка — дубль

#### Scenario: Две одинаковые покупки в одном файле
- **WHEN** в пустое хранилище импортируется файл с двумя одинаковыми строками
- **THEN** добавлены обе, дублей 0

### Requirement: Кривые строки в обычном режиме
При `strict=False` система SHALL не прерывать импорт на ошибочной строке: она попадает в список ошибок с физическим номером строки по правилам `StatementError` (заголовок — 1, пустые строки считаются, запись в кавычках на нескольких строках — строка её начала), остальные строки импортируются.

#### Scenario: Ошибка посередине
- **WHEN** третья строка файла ошибочна, остальные валидны
- **THEN** валидные добавлены, список ошибок содержит одну запись с номером строки 3

### Requirement: Строгий режим атомарен
При `strict=True` система SHALL на первой ошибочной строке (по порядку файла) бросить `StatementRowError` с заполненным `line_no`; из файла в хранилище (память и JSON-файл) не попадает ничего. Дубли ошибками не считаются.

#### Scenario: Ошибка после валидных строк
- **WHEN** строки 2–3 валидны, строка 4 ошибочна
- **THEN** бросается `StatementRowError` с `line_no=4`, хранилище и JSON-файл не изменились

#### Scenario: Дубли в строгом режиме
- **WHEN** все строки валидны, часть — дубли
- **THEN** ошибки нет, дубли посчитаны, новые добавлены

### Requirement: Категоризация и время импорта
Система SHALL применять переданный категоризатор к добавляемым транзакциям и проставлять всем им одинаковое время импорта, полученное от переданных часов (по умолчанию системных), — так же, как текущий импорт.

#### Scenario: Категоризация
- **WHEN** передан категоризатор с подходящим правилом
- **THEN** добавленная транзакция получает категорию, время импорта равно показанию часов

### Requirement: Совместимость прежнего `import_csv`
`import_csv(path, store, categorizer=None, clock=None)` SHALL сохранить сигнатуру и возвращать `int` — число добавленных транзакций. Он работает как импорт с автоопределением формата в строгом режиме: ошибочная строка приводит к `StatementError` (или подклассу) с `line_no`, дубли пропускаются.

#### Scenario: Старый импорт «Новы»
- **WHEN** импортируется корректный файл «Новы» через `import_csv`
- **THEN** возвращается число добавленных транзакций, как раньше

#### Scenario: Ошибка строки в import_csv
- **WHEN** в файле «Новы» строка 3 ошибочна
- **THEN** бросается `StatementError` с `line_no=3` и ничего не сохранено
