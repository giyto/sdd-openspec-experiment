# Разработка на основе спецификаций (OpenSpec) и управляемость ИИ-агента: материалы эксперимента

Материалы к статье «Разработка на основе спецификаций как способ повышения управляемости генерации
кода ИИ-агентами» (Рябов Н.В., Ефимова Е.В., РГЭУ (РИНХ), 2026). Здесь лежат задачи, тикеты, эталонные
решения, скрытые тесты, тексты инструкций, скрипты стенда и сырые результаты всех прогонов.

## Что сравнивалось

ИИ-агент Claude Code (2.1.296, неинтерактивный режим `claude -p`) на моделях Claude Sonnet 5.5 и
Claude Haiku 5.5 дорабатывал существующие проекты на Python по тикету в двух условиях:

- **baseline** – агент получает тикет и выполняет задачу в одной сессии;
- **sdd** – OpenSpec 1.11.0: одна сессия создаёт proposal / specs / design / tasks по инструкции
  `/opsx:propose`, другая (с чистым контекстом, видит только артефакты) реализует их по `/opsx:apply`.

Разведочный вариант **sdd_rules** – то же, что sdd, плюс правило проекта в `openspec/config.yaml`
(перенос публичного API из задачи в спецификацию дословно, см. `harness/prompts/openspec_rules.yaml`).
Правило записано 18.10.2026 в 20:07 после анализа эксперимента 1 и первых 9 прогонов эксперимента 3
и после этого не менялось; все прогоны с ним выполнены позже.

Каждый прогон шёл в отдельной временной копии проекта в режиме `--safe-mode`, со slash-командами
отключёнными, с инструментами `Bash, Read, Edit, Write, Glob, Grep`. Все прогоны – 18 октября 2026 г.

| Эксперимент | Что проверяет | Каталог результатов | Прогонов |
|---|---|---|---|
| 1 | одиночная задача по тикету | `runs/` (метка `v2`) | 60 |
| 2 | запрос на изменение в новой сессии поверх результата эксперимента 1 | `runs_cr/` | 59 |
| 3 | неполная постановка: 4–5 решений знает только владелец продукта, один раунд его замечаний (до кода в SDD, после кода в baseline) | `runs_po/` | 36 |

Пилот на исчерпывающих тикетах первой версии – `runs/*__v1` и `pilot_v1/`. Один прогон эксперимента 2
исключён из-за сбоя окружения – `results/excluded/` (причина описана в README там же).

## Структура

```
tasks/<задача>/             t1_promo, t2_reserve, t3_import, t4_retry
  repo/                     проект, который получает агент
  reference/, reference_cr/ эталонные решения (эксперимент 1/3 и эксперимент 2)
  hidden_tests/             скрытые приёмочные тесты эксперимента 1/3 (агент их не видит)
  hidden_tests_cr/          скрытые тесты запроса на изменение (эксперимент 2)
  ticket_v1.md              исчерпывающий тикет (пилот)
  ticket.md                 тикет эксперимента 1 (тело + переписка + соглашения проекта)
  cr_ticket.md              запрос на изменение (эксперимент 2)
  ticket_po.md, po_decisions.md   тикет без решений владельца и сами решения (эксперимент 3)
  requirements.json, cr_requirements.json, po_meta.json, meta.json, cr_meta.json, NOTES.md
harness/
  run_trial.py, run_cr.py, run_po.py         запуск прогонов
  run_batch.py, run_cr_batch.py, run_po_batch.py   серии прогонов
  evaluate.py, evaluate_cr.py, evaluate_po.py      оценка прогона (скрытые тесты, регрессии, рамки, сложность, стоимость)
  aggregate.py                сводка и перестановочный тест
  classify_failures.py        «нарушение интерфейса» против «неверного поведения»
  judge_agreement.py          согласованность двух слепых экспертов
  make_report.py              таблицы отчёта
  prompts/                    тексты инструкций OpenSpec (propose.md, apply.md) и правило проекта
  _private/judge_map.json     соответствие обезличенных решений прогонам (после завершения оценки)
runs/, runs_cr/, runs_po/<прогон>/
  trial.json                  параметры прогона, стоимость и время сессий
  log_*.jsonl                 журналы сессий агента (stream-json)
  agent.diff                  итоговые изменения агента (без каталога openspec/)
  openspec_artifacts/         артефакты OpenSpec (для условий SDD)
  eval.json                   оценка
results/
  summary_*.json, report_tables.txt, failure_classes.json
  judge_input/, judge_output/, judge_output_2/, judge_scores.json, judge_agreement.json
*_FORMAT.md, TICKET_V2.md, JUDGE_PROMPT.md   задания, по которым готовились задачи и экспертиза
```

Имя прогона: `<задача>__<условие>__r<повтор>__<модель>__<метка>`.

## Как воспроизвести

Нужны Python 3.13 с pytest, Claude Code и OpenSpec (`npm i -g @fission-ai/openspec`), git.

```bash
python -I harness/run_batch.py --tasks t1_promo,t2_reserve,t3_import,t4_retry --conds baseline,sdd --reps 1-3 --jobs 4 --model sonnet --tag v2
python -I harness/run_cr_batch.py --model sonnet --tag v2 --jobs 4
python -I harness/run_po_batch.py --tasks t1_promo,t2_reserve,t3_import,t4_retry --reps 1-3 --jobs 4
python -I harness/aggregate.py --exp 1 --model sonnet
python -I harness/classify_failures.py
```

Рабочие копии создаются во временном каталоге системы (`sdd_runs`), вне каталога эксперимента, чтобы
агент не мог прочитать скрытые тесты. Стоимость в `trial.json` и `eval.json` – по тарифам API.

Проверка задач без агента: скопировать `hidden_tests/` в `reference/tests_hidden/` и выполнить
`python -m pytest -q tests_hidden` – эталон проходит 100 % скрытых тестов, исходный `repo/` –
только тесты обратной совместимости `test_API_*`.

## Основные результаты

| | baseline | SDD | SDD + правило |
|---|---|---|---|
| Эксп. 1, Sonnet: скрытые тесты, % | 99,6 | 95,5 | 99,2 |
| Эксп. 1, Haiku: скрытые тесты, % | 99,6 | 99,2 | – |
| Эксп. 2, Sonnet: тесты запроса на изменение, % | 99,5 | 96,9 | 99,7 |
| Эксп. 3, Sonnet: выполненные решения владельца, % | 90,0 | 96,7 (p = 0,25) | 100 (p = 0,04) |

Почти все потери SDD вызваны искажением интерфейса из тикета на этапе спецификации (27 тестов в двух
прогонах эксперимента 1 и 27 в трёх прогонах эксперимента 3); правило проекта устранило этот класс ошибок.

## Ограничения и известные проблемы

- Задачи, тесты, владелец продукта (эксп. 3) и эксперты – модели семейства Claude, как и испытуемый агент.
- По 12 прогонов на условие; поправка на множественные сравнения не применялась.
- В экспериментах 1 и 2 спецификацию не проверял человек.
- Несколько временных рабочих каталогов опустели после оценки; оценки сделаны раньше, классификация
  ошибок для таких прогонов выполнена на коде, восстановленном из `agent.diff`.
- В путях журналов имя пользователя заменено на `<user>`.
