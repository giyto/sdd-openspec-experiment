# SHOP-447. Промокоды: правки после летней кампании

Летняя кампания прошла, финансы подвели итоги. Промокоды работают, но кое-что оказалось дорогим:
люди брали фиксированные коды на мелкие заказы, а возвратом использования при отмене пользовались,
чтобы гонять один лимитированный код по кругу. Для осенней кампании маркетингу нужны два новых
вида ограничений и промокод на бесплатную доставку.

## Что меняем в действующих правилах

* **Порог бесплатной доставки.** Летом договорились сравнивать порог с суммой товаров после скидки.
  От этого отказываемся: порог снова считается от суммы товаров до скидки.
* **Фиксированная скидка** теперь не больше 30 % суммы участвующих товаров. Долю считаем и округляем
  как любые деньги в проекте.
* **Возврат использования при отмене.** Сейчас при отмене заказа использование промокода
  возвращается всегда. Теперь оно возвращается, только если заказ отменён в течение 24 часов с
  момента оформления (по часам сервиса заказов). Если отменили позже, использование сгорает.

## Новое

* **Промокод на бесплатную доставку** (`DiscountKind.FREE_SHIPPING`). Скидки на товары не даёт,
  стоимость доставки обнуляет. `value` у такого кода равно `Decimal("0")`, иначе `ValidationError`.
  Сколько клиент сэкономил на доставке, показываем в новом поле `OrderTotal.shipping_discount`. Если
  экономить было нечего или код другого вида, там `Decimal("0.00")`.
* **Потолок процентной скидки** (`max_discount`): процентная скидка не может превысить эту сумму.
  Поле допустимо только у `PERCENT` и должно быть больше нуля, иначе `ValidationError`.
* **Лимит на клиента** (`max_uses_per_customer`; `None` — без лимита, иначе >= 1). В `quote` и
  `place_order` появляется `customer_id`, заказ его запоминает. Код с лимитом на клиента без
  `customer_id` не применяется, и исчерпанный клиентом лимит тоже даёт `PromoConditionsError`.
  `customer_id` — внутренний идентификатор учётной записи, его сравниваем как есть.

```python
class DiscountKind(StrEnum): PERCENT, FIXED, FREE_SHIPPING

@dataclass(frozen=True)
class PromoCode:
    ...                                       # прежние поля без изменений, новые — в конце
    max_discount: Decimal | None = None
    max_uses_per_customer: int | None = None

PromoRegistry.resolve(code: str, customer_id: str | None = None) -> PromoCode
PromoRegistry.uses(code: str, customer_id: str | None = None) -> int  # с customer_id — сколько раз использовал этот клиент

OrderTotal.shipping_discount: Decimal
OrderService.quote(cart, promo_code=None, *, customer_id: str | None = None)
OrderService.place_order(cart, promo_code=None, *, customer_id: str | None = None)
Order.customer_id: str | None
```

## Рамки

Те же, что раньше: `shop/cli.py` и `shop/reports.py` не трогаем, существующие тесты не меняем,
старые вызовы работают, новых зависимостей нет.
