# shop — расчёт заказов интернет-магазина

Небольшая библиотека, на которой живут корзина, расчёт итогов заказа и бэк-офисные отчёты.
Используется HTTP-слоем (в другом репозитории) и утилитой для поддержки `python -m shop.cli`.

## Структура

| Модуль | Что внутри |
|---|---|
| `shop/money.py` | деньги: `to_money`, `quantize_money`, `sum_money`, `format_money`, константы `CENT`, `ZERO` |
| `shop/errors.py` | иерархия исключений, корень — `ShopError` |
| `shop/clock.py` | источники времени: `Clock` (протокол), `SystemClock`, `FixedClock` |
| `shop/catalog.py` | `Category`, `Product`, `Catalog`, корзина `Cart`/`CartLine` |
| `shop/pricing.py` | `TaxPolicy`, `ShippingPolicy`, `LineTotal`, `OrderTotal`, `calculate_total` |
| `shop/orders.py` | `Order`, `OrderStore`, `OrderService` |
| `shop/reports.py` | отчёт о продажах для бэк-офиса |
| `shop/cli.py` | CLI для сотрудников поддержки |

## Правила расчёта

* Сумма строки = цена × количество.
* Налог начисляется сверху, построчно, по ставке категории товара (книги и еда — 10 %,
  подарочные сертификаты — 0 %, остальное — 20 %), округляется в каждой строке отдельно.
  Налог заказа — сумма налогов строк.
* Доставка — фиксированные 299.00, бесплатно от 3000.00 по сумме товаров. Если в корзине только
  подарочные сертификаты (`Category.GIFT_CARD`), доставки нет вовсе. Доставка налогом не облагается.
* Подарочный сертификат — это предоплата, а не товар: налога на него нет, доставки нет, и на него
  никогда не распространяются скидки и акции.
* `total = subtotal + shipping + tax`.

## Соглашения

* **Деньги** — только `Decimal`, два знака после запятой, округление только `ROUND_HALF_UP`
  через `shop.money.quantize_money`. `float` для денег запрещён (`to_money` его отвергает).
* **Ошибки** — только наследники `ShopError` из `shop/errors.py`. Некорректные входные данные —
  `ValidationError`. Голые `ValueError`/`KeyError` наружу не выпускаем.
* **Время** — никогда не вызываем `datetime.now()` напрямую: всё, что зависит от времени, получает
  `Clock` через конструктор. Все `datetime` — aware, UTC. В тестах — `FixedClock`.
* **Модели** — `@dataclass(frozen=True)`, инварианты проверяются в `__post_init__`.
* **Коды, которые вводят люди** (SKU и т.п.), регистронезависимы: и при создании объекта, и при
  поиске обрезаем пробелы по краям и приводим к верхнему регистру (`normalize_key`). Повторное
  добавление того же ключа — `ValidationError`.
* **Интервалы времени** везде полуоткрытые `[начало, конец)`: начало включительно, конец
  исключительно; граница `None` — без ограничения. Если начало не раньше конца — `ValidationError`.
* **Логирование** — модульный логгер `logger = logging.getLogger(__name__)`, никаких `print`
  вне `cli.py`.
* Порядок строк корзины — порядок первого добавления товара; от него зависят чеки и отчёты.
* Только стандартная библиотека. Тесты — pytest.
