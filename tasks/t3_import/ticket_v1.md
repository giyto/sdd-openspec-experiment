# LEDGER-58: Импорт выписок банка «Сфера», дедупликация и отчёт об ошибках

## Зачем

Сейчас `ledger` умеет импортировать только CSV банка «Нова», и делает это довольно
хрупко: первая кривая строка роняет импорт посередине (часть строк уже записана,
часть нет), повторный импорт той же выписки задваивает все операции, а файл,
сохранённый из Excel (UTF-8 с BOM), вообще не читается. Пользователи всё чаще
приносят выписки банка «Сфера», которые выглядят иначе. Хотим один нормальный
вход для импорта: сам понимает, что за файл, не задваивает операции и честно
рассказывает, что не смог разобрать.

## Что сделать

Новая функция в `ledger/importer.py`:

```python
def import_statement(
    path, store, *, fmt=None, strict=False, categorizer=None, clock=None
) -> ImportResult
```

- `path` — путь к CSV-файлу, `store` — хранилище (`MemoryStore` / `JsonFileStore`),
  `categorizer` — `Categorizer` или `None`, `clock` — часы проекта (по умолчанию `SystemClock`).
- `fmt` — имя формата: `"nova"`, `"sfera"` или `"sfera_split"`; `None` — определить автоматически.
- Результат — `ImportResult` (frozen dataclass в `ledger/importer.py`) с полями:
  `format: str` (какой формат был разобран), `encoding: str` (`"utf-8"` или `"cp1251"`),
  `added: int` (сколько транзакций добавлено в хранилище), `duplicates: int`
  (сколько строк пропущено как уже импортированные), `errors: list[RowError]`.
- `RowError` — frozen dataclass в `ledger/importer.py`: `line_no: int`, `message: str`
  (текст сообщения на ваше усмотрение).
- Новые исключения в `ledger/errors.py`: `UnknownFormatError` и `StatementRowError`,
  оба — наследники `StatementError` (у `StatementRowError` заполнен `line_no`).

### Форматы

1. **`nova`** — существующий формат (см. README), ничего в нём не меняется.
2. **`sfera`** — колонки `Дата;Сумма;Описание`. Разделитель `;`, дата `ДД.ММ.ГГГГ`,
   десятичная запятая, тысячи могут разделяться пробелом или неразрывным пробелом
   (U+00A0): `-1 234,56`. Расход — со знаком минус, приход — без знака или с `+`.
   Дробная часть — не больше двух знаков; точка в сумме для этого формата — ошибка
   строки (`1 234.56` мы не угадываем).
3. **`sfera_split`** — новая выгрузка той же «Сферы»: колонки
   `Дата;Описание;Приход;Расход`, всё остальное как в `sfera`. Суммы в `Приход`/`Расход`
   пишутся без знака; расход в транзакции становится отрицательной суммой. В строке
   должна быть заполнена ровно одна из двух колонок, иначе это ошибка строки; знак
   в этих колонках — тоже ошибка строки. Банк иногда пишет `0,00` в неиспользуемую
   колонку — это то же самое, что пусто.

### Определение формата и кодировки

4. Если `fmt=None`, формат определяется по строке заголовка. Названия колонок
   сравниваются без учёта регистра и пробелов по краям, порядок колонок может быть
   любым, лишние колонки (например, `Номер карты`) игнорируются. Не распознали
   заголовок, файл пустой, или `fmt` указан явно, а заголовок ему не подходит —
   `UnknownFormatError` (в любом режиме), в хранилище при этом ничего не попадает.
   Отдельно нужна функция `detect_format(path) -> str`, которая возвращает имя
   формата файла или бросает `UnknownFormatError`.
5. Файл может быть в UTF-8 (с BOM или без) или в cp1251. Правило простое: если файл
   целиком читается как UTF-8 — это `"utf-8"`, иначе `"cp1251"`. Кодировка определяется
   для файла целиком, а не по заголовку.

### Дедупликация

6. Транзакция считается уже импортированной, если в хранилище есть транзакция с тем же
   ключом (дата, сумма, нормализованное описание). Нормализация — функция
   `normalize_description(text: str) -> str` в `ledger/importer.py`: убрать пробелы по краям,
   любые последовательности пробельных символов внутри заменить одним пробелом,
   привести к нижнему регистру через `casefold()` и заменить `ё` на `е`. Нормализация
   нужна только для сравнения: в хранилище описание сохраняется как в файле (с обрезанными
   пробелами по краям), ничего не приводим к нижнему регистру.
7. Одинаковые строки внутри одного файла — **не** дубли: два кофе за 150 в один день —
   это два кофе. Сравниваем только с тем, что было в хранилище до начала импорта, и по
   количеству: если в хранилище уже есть k транзакций с данным ключом, а в файле n строк
   с этим ключом, то первые min(k, n) строк файла — дубли, остальные добавляются. В итоге
   повторный импорт той же выписки ничего не добавляет, а выписка за пересекающийся
   период добавляет только новое.

### Ошибки и режим strict

8. По умолчанию (`strict=False`) ошибочная строка не прерывает импорт: она попадает в
   `errors`, остальные строки импортируются. Ошибка строки — всё, из чего не получается
   корректная `Transaction`: не та дата, не та сумма, не хватает полей, нулевая сумма,
   пустое описание и т.д. `line_no` — номер физической строки в файле, заголовок —
   строка 1, первая строка данных — строка 2, пустые строки тоже учитываются в нумерации.
   Ошибки в `errors` идут в порядке строк файла.
9. `strict=True`: на первой же ошибочной строке бросается `StatementRowError` с `line_no`
   этой строки, и в хранилище не попадает **ничего** из этого файла (ни в память, ни в
   JSON-файл `JsonFileStore`). Дубли и пустые строки ошибками не считаются ни в каком режиме.
10. Пустые строки — без символов или только из пробелов и разделителей (`;;;`, `,,`,
    ` ; ; `) — пропускаются в любом месте файла, особенно часто они бывают в конце выгрузки.
    Они не ошибки, не дубли и не добавленные.

### Прочее

11. Импортированным транзакциям, как и раньше, проставляется категория через `categorizer`
    (если передан и правило сработало) и `imported_at = clock.now()` — одно значение на
    весь импорт.
12. Старый `import_csv(path, store, categorizer=None, clock=None) -> int` должен остаться:
    сигнатура и тип результата прежние, CLI на нём работает. Пусть теперь он работает через
    новый механизм как строгий импорт формата `nova`: то есть дедупликация, BOM/cp1251 и
    атомарность к нему тоже относятся, а возвращает он число добавленных транзакций.
    Ошибки — по-прежнему `StatementError` (наследники подходят).

Кстати, если описание в кавычках занимает несколько строк файла (бывает в «Сфере»,
когда в назначении платежа перевод строки), `line_no` такой записи — строка, где она
начинается.

## Рамки

- `ledger/cli.py` и `ledger/reports.py` не трогаем.
- Существующие тесты в `tests/` не меняем (новые файлы тестов добавлять можно и нужно).
- Публичный API `Transaction`, `MemoryStore`/`JsonFileStore`, `Categorizer` не ломаем.
- Новых зависимостей не добавляем, только стандартная библиотека.
