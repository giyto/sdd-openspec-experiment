# WH-231: Резервы — доработки после запуска

**Автор:** Анна Белова · 09.11.2026 11:00

## Зачем

Резервы под заказы работают месяц. Поддержка и склад собрали список того, что мешает: покупатели
меняют корзину, оформляют возвраты, а поддержке не видно, какие резервы истекли. Часть прежних
договорённостей меняем, часть добавляем.

## Что меняем

1. **Пересборка корзины.** Раньше договорились, что повторный `reserve` на заказ с активным резервом —
   ошибка. Теперь это замена: новый резерв заменяет активный. Товар заменяемого резерва при проверке
   наличия считается свободным. В журнале замена выглядит так: сначала `RESERVE_CANCEL` по старому
   резерву, затем `RESERVE` по строкам нового. Подтверждённый заказ так заменить по-прежнему нельзя.
2. **Возвраты.** Раньше подтверждённый заказ отменить было нельзя. Теперь `cancel` подтверждённого
   заказа — это возврат: товар по всем строкам возвращается на те же склады, статус `CANCELLED`.
   В журнале — обычный приход (`RECEIVE`) по каждой строке с `ref` = номер заказа, затем `RESERVE_CANCEL`.
3. **TTL по умолчанию** — 20 минут вместо 15.
4. **Предельный срок резерва.** `expires_at` не может быть позже `created_at + MAX_RESERVATION_LIFETIME`
   (один час). `reserve` с `ttl` больше предела — `ValidationError`. `extend` сверх предела —
   не ошибка: срок ставится ровно на предел.

## Что добавляем

```python
# warehouse/models.py
@dataclass(frozen=True)
class Availability:
    warehouse: str
    sku: str
    on_hand: int
    reserved: int
    available: int

# warehouse/reservations.py
MAX_RESERVATION_LIFETIME: timedelta

# новые методы Inventory
def reservations(self, status: ReservationStatus | None = None) -> list[Reservation]: ...
def availability(self, warehouse: str | None = None) -> list[Availability]: ...
def sweep_expired(self) -> list[str]: ...
```

5. `reservations()` — снимки текущих резервов (по одному на заказ), по `created_at`, затем по
   `order_id`. С `status` — только резервы с этим статусом на текущий момент.
6. `availability()` — строка на каждую позицию, где есть физический остаток или активный резерв.
   `on_hand`, `reserved`, `available` — те же значения, что дают одноимённые методы. Порядок
   и фильтр по складу — как у `stock_levels`.
7. `sweep_expired()` — для дашборда поддержки. Находит истёкшие резервы, о которых ещё не писали,
   пишет по каждому событие `RESERVE_EXPIRE` (`order`, `expires`) и возвращает их `order_id`
   в порядке `expires_at`, затем `order_id`. О каждом резерве пишем один раз. Статусы и остатки
   метод не меняет. Вызывать его будет внешний планировщик, внутри сервиса фоновых процессов
   по-прежнему нет.

## Рамки

- `warehouse/cli.py` и `warehouse/reports.py` не трогаем, существующие тесты не меняем,
  новых зависимостей не добавляем.
- Остальные правила резервов и старый API остаются как есть.
