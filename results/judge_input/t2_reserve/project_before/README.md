# warehouse

Небольшой сервис складского учёта: справочник SKU, физические остатки по складам,
приход / расход / перемещение / инвентаризация и журнал событий.

```
warehouse/
  errors.py     иерархия исключений (всё наследуется от WarehouseError)
  clock.py      источники времени: SystemClock, ManualClock (для тестов)
  models.py     неизменяемые датаклассы предметной области
  events.py     журнал событий и его строковый формат
  storage.py    хранилище в памяти
  inventory.py  сервис Inventory — вся бизнес-логика
  reports.py    отчёты (только чтение)
  cli.py        командная строка: прогон JSON-сценария
```

## Соглашения

* **Только стандартная библиотека.** Python 3.13, тесты — pytest.
* **Время** берётся только из внедрённых часов (`Inventory(clock=...)`), никаких
  `datetime.now()` в бизнес-коде. Все datetime — aware, в UTC.
* **Количества** — целые положительные `int`; `bool`, дробные и строки отклоняются
  `InvalidQuantityError`.
* **Ошибки** — только наследники `WarehouseError` из `warehouse/errors.py`.
  Ошибки входных данных — `ValidationError` и её наследники. Запросы по позиции
  (`on_hand` и т.п.) для незарегистрированного SKU бросают `UnknownSkuError`,
  для зарегистрированного SKU без остатка возвращают 0.
* **Атомарность.** Операция либо выполняется целиком, либо не меняет ничего —
  ни состояния сервиса, ни журнала: сначала все проверки, потом изменения.
* **Журнал.** Каждая операция, меняющая остатки, пишет событие в `EventLog`.
  Формат строки описан в `events.py` и используется внешней выгрузкой — не менять.
  Время в полях событий пишется тем же форматом, что и время события.
* **Логирование** — модульный логгер `logging.getLogger(__name__)`, без `print`
  (кроме `cli.py`).
* **Модели** — `@dataclass(frozen=True)`; наружу сервис отдаёт снимки, а не
  внутренние изменяемые объекты.

## Запуск

```
python -m pytest -q
python -m warehouse.cli run scenario.json --show log
```
