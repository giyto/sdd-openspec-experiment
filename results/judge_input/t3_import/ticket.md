# LEDGER-58: импорт выписок «Сферы»

## Зачем

Пользователи всё чаще приносят выписки банка «Сфера», а мы умеем только «Нову». Текущий
импорт к тому же хрупкий: повторный импорт задваивает операции, кривая строка роняет
импорт на середине (часть строк уже записана), а файлы, сохранённые из Excel (UTF-8 с BOM),
не читаются. Нужен один вход для импорта, который сам понимает, что за файл, не задваивает
операции и честно говорит, что не смог разобрать.

## Что сделать

```python
# ledger/importer.py
def import_statement(path, store, *, fmt=None, strict=False,
                     categorizer=None, clock=None) -> ImportResult: ...
def detect_format(path) -> str: ...          # "nova" | "sfera" | "sfera_split"
def normalize_description(text: str) -> str: ...

@dataclass(frozen=True)
class RowError:
    line_no: int
    message: str

@dataclass(frozen=True)
class ImportResult:
    format: str           # "nova" | "sfera" | "sfera_split"
    encoding: str         # "utf-8" (с BOM или без) | "cp1251"
    added: int
    duplicates: int
    errors: list[RowError]

# ledger/errors.py, оба наследуют StatementError
class UnknownFormatError(StatementError): ...
class StatementRowError(StatementError): ...  # line_no заполнен
```

Формат `sfera`:

```
Дата;Сумма;Описание
01.03.2026;-1 200,50;Магазин Лента
02.03.2026;+85 000,00;Зарплата
```

Тысячи отделяются пробелом (в реальных файлах часто неразрывным, U+00A0), расход идёт
с минусом, приход без знака или с плюсом. Формат `sfera_split` — новая выгрузка того же банка:
`Дата;Описание;Приход;Расход`. Суммы там пишутся без знака (знак — ошибка строки), расход
становится отрицательной суммой, заполнена должна быть ровно одна колонка из двух.

- `fmt=None` — формат определяем по заголовку. Если заголовок не распознан (в том числе
  файл пустой) или не подходит к явно указанному `fmt` — `UnknownFormatError` в любом режиме,
  ничего не сохраняем.
- Кодировка: если файл целиком читается как UTF-8 (BOM допустим) — это utf-8, иначе cp1251.
- Транзакции, которые уже есть в хранилище, пропускаем и считаем в `duplicates`. Дубль — та же
  дата, сумма и описание; описания сравниваем так же, как везде в проекте, `normalize_description`
  и есть это сравнение.
- Кривая строка не роняет импорт: она попадает в `errors` с `line_no` по правилам
  `StatementError`, остальное импортируется. Ошибка строки — всё, из чего не собирается
  корректная `Transaction`.
- `strict=True`: на первой ошибочной строке бросаем `StatementRowError`, и из файла в хранилище
  не попадает ничего — ни в память, ни в JSON. Дубли ошибками не считаются.
- Категоризация, `imported_at` и описание транзакции — как в текущем импорте.
- `import_csv(path, store, categorizer=None, clock=None) -> int` остаётся для совместимости:
  сигнатура и `int` прежние, на нём работает CLI.

## Рамки

- `ledger/cli.py` и `ledger/reports.py` не трогаем.
- Существующие тесты не меняем, новые добавлять можно.
- Публичный API `Transaction`, хранилищ и `Categorizer` не ломаем, только стандартная библиотека.
