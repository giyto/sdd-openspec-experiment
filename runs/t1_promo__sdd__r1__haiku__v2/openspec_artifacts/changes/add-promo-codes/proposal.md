## Why

Маркетинг запускает летнюю кампанию с промокодами (SHOP-412). Сейчас скидки делает поддержка вручную,
и суммы регулярно расходятся с чеками. Нужно, чтобы покупатель мог передать промокод при расчёте
(`quote`) и при оформлении (`place_order`), а скидка честно попадала в итоги и раскладывалась по
строкам заказа: бухгалтерия считает налог построчно.

## What Changes

- Новый модуль `shop/promo.py`: `PromoCode` (процентный или фиксированный), `DiscountKind`,
  `PromoRegistry` с проверкой существования, срока действия и лимита использований.
- Новые исключения в `shop/errors.py`: `PromoError` и три независимых наследника —
  `UnknownPromoCodeError`, `PromoExpiredError`, `PromoConditionsError`.
- `calculate_total` принимает необязательный `promo` (только по ключевому слову). Скидка действует
  только на участвующие строки, раскладывается по строкам так, что сумма строк в точности равна общей скидке, налог
  строки считается с суммы после скидки, доставка скидкой не уменьшается. Порог бесплатной доставки
  сравнивается с суммой товаров после скидки.
- `LineTotal.discount` и `OrderTotal.discount` (по умолчанию `0.00`); `total = subtotal - discount +
  shipping + tax`.
- `OrderService` получает необязательный `promos: PromoRegistry`; `quote` и `place_order` принимают
  `promo_code`. Пустой или пробельный код означает «без промокода». Использование счётчика
  увеличивается только при успешном `place_order`; при `cancel` промокод заказа возвращается.
- `Order.promo_code` хранит нормализованный код либо `None`.
- Старые вызовы `calculate_total(cart)`, `calculate_total(cart, shipping, tax)`, `quote(cart)`,
  `place_order(cart)` ведут себя как раньше и дают те же суммы.

Вне объёма: `shop/cli.py` и `shop/reports.py` не меняются; скидки в CLI и отчётах — отдельный тикет.
Существующие тесты не меняются; новые тесты — в отдельных файлах. Новых зависимостей нет.

## Capabilities

### New Capabilities
- `promo-codes`: жизненный цикл промокода — регистрация, нормализация кода, проверка существования,
  срока действия и лимита использований, учёт использований при оформлении и отмене заказа.
- `promo-discounts`: расчёт скидки по промокоду в итогах заказа — участвующие строки, минимальная
  сумма, процентная и фиксированная скидка, раскладка по строкам, налог и доставка.

### Modified Capabilities
- Нет. В `openspec/specs/` пока нет утверждённых спецификаций; поведение без промокода не меняется
  и описано в README, поэтому отдельных дельт для существующих возможностей не создаётся.

## Impact

- Код: `shop/promo.py` (новый), `shop/errors.py`, `shop/pricing.py`, `shop/orders.py`.
- Публичный API: новые поля `LineTotal.discount`, `OrderTotal.discount`, `Order.promo_code`
  и параметры `promo`/`promo_code`/`promos` — все с значениями по умолчанию, обратно совместимо.
- Тесты: новые файлы `tests/test_promo*.py`, существующие тесты не трогаются.
- Документация: README получает раздел о промокодах (правила расчёта).
- Зависимости: нет.
