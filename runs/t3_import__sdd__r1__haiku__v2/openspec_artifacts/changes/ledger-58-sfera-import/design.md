## Context

`ledger/importer.py` сейчас содержит `import_csv`: открывает файл как UTF-8, читает `csv.DictReader`,
построчно разбирает строки и вызывает `store.add` на каждую. Отсюда три проблемы из задачи: дубли при
повторном импорте, частичная запись при ошибке посреди файла и невозможность прочитать BOM/cp1251.

Ограничения из проекта (`README.md`): деньги только `Decimal` через `to_money`/`Transaction`, исключения
только из `ledger.errors`, описания сравниваются через `rules.normalize_text`, время приходит через `clock`,
только стандартная библиотека. `ledger/cli.py` и `ledger/reports.py` не меняются. Хранилище `add_many`
уже атомарно (одна запись на диск), поэтому атомарность импорта строится на одном вызове `add_many`.

## Goals / Non-Goals

**Goals**
- Один вход `import_statement` для трёх форматов, с определением формата и кодировки.
- Дедупликация по количеству относительно хранилища до импорта.
- Нестрогий режим: ошибки строк собираются, импорт продолжается; строгий: ничего не пишем при первой ошибке.
- `import_csv` становится строгой обёрткой над `import_statement(fmt="nova")`, сигнатура и `int` сохраняются.

**Non-Goals**
- Изменения CLI (`--format` и т.п.) и отчётов.
- Чтение выписок из других банков, поддержка XLSX.
- Миграция уже записанных дублей в хранилище.
- Изменение `Transaction`, хранилищ, `Categorizer`.

## Decisions

### 1. Структура модуля
Всё остаётся в `ledger/importer.py`, без нового пакета. Внутри:
- `_read_text(path) -> tuple[str, str]` — читает байты, возвращает `(text, encoding)`. Декодирует UTF-8
  (строгий режим `errors="strict"`), при `UnicodeDecodeError` пробует `cp1251`. BOM снимается (`text.lstrip("﻿")`
  только в начале). Если и cp1251 не декодируется — `UnknownFormatError`.
- `_FORMATS` — спецификация каждого формата: разделитель, обязательные колонки (нормализованные имена),
  функция разбора строки. Формат описан данными, а не отдельными ветками кода.
- `_read_records(text, delimiter)` — `csv.reader(io.StringIO(text, newline=""), delimiter=...)`, отдаёт пары
  `(start_line, row)`. Номер строки начала записи берётся как `reader.line_num` до чтения записи плюс единица
  (важно для записей с переводами строк внутри кавычек).
- `_detect(text) -> (format_name, delimiter, header_index_map)` — берёт первую непустую строку, пробует оба
  разделителя `;` и `,`, нормализует имена колонок (`strip().casefold()`), ищет совпадение с форматами.

Публичные функции: `import_statement`, `detect_format`, `normalize_description`, `import_csv`.
`detect_format(path)` вызывает `_read_text` и `_detect`, возвращает имя формата.

### 2. Определение формата
Заголовок — первая непустая строка файла. Совпадение проверяется по множеству нормализованных имён колонок:
`nova` ⇔ {date, amount, description} ⊆ колонки; `sfera` ⇔ {дата, сумма, описание} ⊆ колонки;
`sfera_split` ⇔ {дата, описание, приход, расход} ⊆ колонки. Если совпало ноль или больше одного формата —
`UnknownFormatError`. Если задан `fmt`, проверяется только он; неизвестное значение `fmt` тоже даёт
`UnknownFormatError`. Ошибки заголовка создаются с `line_no=1`, если заголовок есть (это нужно текущему тесту
`test_import_missing_column`, который ожидает `line_no == 1`), и без `line_no` для пустого файла.

### 3. Разбор ячеек
- Сумма `sfera`: `re.fullmatch(r"([+-]?)(\d{1,3}(?:[  ]\d{3})*|\d+)(?:,(\d{1,2}))?", text.strip())`
  — группы по три цифры строго, дробная часть до двух знаков. Результат собирается в строку `"-1200.50"` и
  передаётся в `parse_amount` (тот же контроль, что для `nova`). Точка, три знака после запятой и любой
  другой вид — ошибка строки.
- Сумма `sfera_split`: та же функция без знака (знак в ячейке — ошибка). Значение `0,00` приравнивается к пустому
  (проверка по `Decimal == 0` после разбора). Ровно одна из двух ячеек должна быть ненулевой; расход
  инвертируется в отрицательную сумму.
- Дата `sfera`/`sfera_split`: `re.fullmatch(r"\d{2}\.\d{2}\.\d{4}")` и `dt.date(int(y), int(m), int(d))` —
  `ValueError` превращается в ошибку строки.
- Дата `nova`: `dt.date.fromisoformat`, как сейчас.

### 4. Пустые строки
Строка считается мусорной, если все её ячейки после `strip()` пусты. Это покрывает пустую строку (`[]`),
строку пробелов и строки из одних разделителей. Такие строки пропускаются до разбора полей, не попадают
в `errors`, в `duplicates` и в `added`.

### 5. Строки с лишними или недостающими полями
Если строка короче, чем максимальный индекс нужной колонки, — ошибка «not enough fields». Если в строке есть
непустые ячейки после последней колонки заголовка — ошибка «too many fields». Лишние колонки внутри заголовка
(«Номер карты», «Остаток») игнорируются.

### 6. Дедупликация
Ключ: `(date, amount, normalize_description(description))`. До разбора файла строится `Counter` ключей по
`store.all()`; это `k` для каждого ключа. Затем валидные строки файла в порядке следования: для ключа,
которого ещё осталось `k > 0` в счётчике, строка считается дублем и счётчик уменьшается; иначе строка
добавляется. Так дубли внутри файла между собой не схлопываются, а первые `min(k, n)` совпадений — дубли.
`normalize_description` — тонкая обёртка над `rules.normalize_text`, чтобы имя было публичным и сравнение
осталось одним местом.

### 7. Атомарность и порядок записи
Вся работа с файлом (декодирование, разбор, дедупликация) выполняется до любого обращения к `store`
на запись. Далее:
- `strict=True`: на первой ошибке (в порядке файла) — `StatementRowError(msg, line_no=n)`; `store` не трогается.
- `strict=False`: ошибки накапливаются в `errors`; все новые транзакции (после категоризации) записываются
  одним вызовом `store.add_many(...)`, если список непуст. Вызов `add_many` атомарен (см. `storage.py`),
  поэтому при сбое записи в хранилище не остаётся частичных данных. Если `added == 0`, запись не вызывается,
  чтобы JSON-файл не переписывался.

`imported_at = clock.now()` вызывается один раз в начале импорта (как сейчас). Категоризация применяется
только к новым транзакциям, как в текущем `import_csv`.

### 8. Ошибки строки
Ошибка строки — любое исключение `ValidationError`, `ValueError` или несоответствие формату, возникшее при
сборке `Transaction`. Они конвертируются в `RowError(line_no, message)` (нестрогий режим) или в
`StatementRowError` (строгий). Сообщение строки — текст без префикса «line N:», префикс добавляет
`StatementError.__init__`, но `RowError.message` хранится отдельно.

### 9. Совместимость `import_csv`
`import_csv(path, store, categorizer=None, clock=None) -> int` вызывает
`import_statement(path, store, fmt="nova", strict=True, categorizer=categorizer, clock=clock).added`.
Существующие тесты проверяют значения сумм и `line_no` в ошибках — они сохраняются. Единственное отличие
по типу: ошибки заголовка теперь `UnknownFormatError`, который наследует `StatementError`, а не голый
`StatementError`, поэтому `except StatementError` в вызывающем коде продолжает работать.

## Risks / Trade-offs

- **Нестандартный пробел в суммах**: допускаются только U+0020 и U+00A0. Другие пробелы (U+202F, узкий NBSP)
  дадут ошибку строки, а не молчаливое чтение. Это безопасно, но может потребовать расширения, если банк
  начнёт их использовать.
- **Дедупликация по количеству**: если пользователь удалил одну из двух одинаковых операций в хранилище,
  повторный импорт вернёт её. Это ожидаемо по решению продукта (счётчик k).
- **Потоковое чтение не используется**: файл читается целиком, чтобы решить кодировку и не начинать запись
  до конца разбора. Для выписок за период это приемлемо.
- **OSError** при открытии несуществующего файла пробрасывается как есть (как сейчас в `import_csv`);
  в `LedgerError` он не оборачивается. Это сохраняет поведение CLI.

## Assumptions

- Заголовок — первая непустая строка; пустые строки до заголовка пропускаются, но номера строк физические.
- Группировка тысяч строгая: `1 234,56` валидно, `12 34,00` — ошибка строки.
- `fmt` со значением вне трёх форматов — `UnknownFormatError`.
- Пустая строка данных, у которой есть только дата (без суммы и описания), — ошибка строки, а не мусор.
- Нулевая сумма (`0,00` в `sfera`, `0.00` в `nova`) — ошибка строки, потому что `Transaction` её не принимает.

## Решения при реализации

- `ImportResult.errors` — `tuple[RowError, ...]`, а не список: результат полностью неизменяем.
- Снятие BOM делает кодек `utf-8-sig` при декодировании, а не `lstrip`; `encoding` при этом `"utf-8"`.
- Заголовок ищется как первая непустая *запись* CSV (с учётом кавычек), для каждого из двух разделителей;
  формат выбирается по разделителю, который совпал с заголовком.
- Ошибка заголовка (`UnknownFormatError`) всегда несёт `line_no=1`, даже если перед заголовком есть пустые
  строки (требование спецификации). Для пустого файла и для неизвестного `fmt` `line_no` не задаётся.
- `detect_format` разбирает только заголовок файла через тот же `_layout`, что и импорт.
- Строки данных — все записи после заголовка с номером строки начала записи; мусорные строки пропускаются
  в цикле импорта, до разбора полей.
- Вся запись в хранилище — один вызов `store.add_many` со всеми новыми транзакциями (после категоризации);
  при `added == 0` вызова нет.
- `import_csv` сохраняет поведение: `fmt="nova"`, `strict=True`; ошибки заголовка приходят как `UnknownFormatError`.
