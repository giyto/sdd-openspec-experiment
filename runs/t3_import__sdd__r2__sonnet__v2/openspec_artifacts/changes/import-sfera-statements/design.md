## Context

`ledger/importer.py` содержит только `import_csv` для «Новы» (utf-8, пишет по одной строке через `store.add`). Описания в проекте сравниваются через `rules.normalize_text`. `MemoryStore.add_many` атомарен (JsonFileStore пишет файл через temp + replace). Существующие тесты требуют: неверный заголовок → `StatementError` с `line_no == 1`, ошибка строки → `line_no` физической строки. Мотивация — см. proposal.md.

## Goals / Non-Goals

**Goals:** один вход `import_statement`; `import_csv` — тонкая обёртка; атомарность через один `add_many`.

**Non-Goals:** правки `cli.py`/`reports.py`, новые флаги CLI, изменения моделей и хранилищ, сторонние библиотеки, угадывание форматов сумм.

## Decisions

1. **Конвейер**: читать байты → декодировать (`utf-8-sig`, при `UnicodeDecodeError` — `cp1251`; если и он не декодирует — `StatementError`) → `csv.reader` по `io.StringIO(text, newline="")` → заголовок → разбор строк в `Transaction` → дедупликация → один `add_many`. Ничего не пишется до конца разбора, поэтому strict и атомарность получаются сами. Альтернатива (писать по ходу и откатывать) отвергнута: у хранилищ нет отката.
2. **Заголовок**: нормализация `strip().casefold()`; для каждого формата свой разделитель (`nova` — `,`, `sfera*` — `;`) и набор обязательных колонок; формат подходит, если все обязательные колонки присутствуют ровно по разу. `sfera` и `sfera_split` различаются по `сумма` против `приход`/`расход`; заголовок, подходящий обоим, — неизвестный формат. Индексы колонок запоминаем, лишние игнорируем. `detect_format` и `import_statement` используют одну функцию разбора заголовка. Допущение: регистронезависимость и обрезка пробелов распространяются и на `nova` (надмножество прежнего поведения).
3. **`UnknownFormatError.line_no`**: 1 для непустого файла (иначе сломается существующий тест с заголовком `date,sum,description`), `None` для пустого. Неизвестное значение `fmt` — тоже `UnknownFormatError` (код бросает только наследников `LedgerError`).
4. **Нумерация строк**: `reader.line_num` после предыдущей записи + 1 = начало текущей; пустые строки csv отдаёт как `[]`, так что физическая нумерация и «начало многострочной записи» сохраняются.
5. **Мусор**: запись, у которой все поля пусты после `strip()` (включая `[]`), пропускается до любых проверок.
6. **Суммы «Сферы»**: `strip` → необязательный знак → тело `[0-9]+` либо `[0-9]{1,3}([  ][0-9]{3})+`, затем необязательно `,` и 1–2 цифры → `Decimal` → `Transaction` (ноль и прочее ловит модель). Точка, иные разделители и >2 знаков — ошибка строки. Для `sfera_split` знак запрещён; колонка считается пустой, если пуста или равна нулю (`0,00`); непустой должна быть ровно одна; расход инвертируется. Дата: `[0-9]{2}\.[0-9]{2}\.[0-9]{4}` + `strptime` (один `strptime` принял бы `1.3.2026`). `nova` — как раньше (`fromisoformat`, `parse_amount`).
7. **Недостаток полей**: если в записи нет колонки по нужному индексу — ошибка строки «not enough fields».
8. **Дубли**: `Counter` по ключу `(date, amount, normalize_description(description))` от `store.all()` до импорта; для каждой валидной строки файла по порядку: счётчик > 0 → уменьшить и считать дублем, иначе добавить. Строки файла в счётчик не попадают, поэтому одинаковые строки внутри файла дублями не считаются. `normalize_description` делегирует `rules.normalize_text` (единый источник правды, реализацию не копируем).
9. **Режимы**: ошибка строки → strict: `StatementRowError(message, line_no=...)` сразу; иначе `RowError` в список. Дубли ошибок не порождают. Если добавлять нечего, `add_many` не вызываем (не создаём пустой JSON-файл).
10. **Категоризация**: к добавляемым транзакциям, как в текущем коде (новая `Transaction` с категорией, если она не `None`); `imported_at` — один `clock.now()` на импорт.
11. **`import_csv`**: `import_statement(path, store, fmt="nova", strict=True, categorizer=..., clock=...).added`. Ошибки открытия файла (`OSError`) остаются как раньше и не оборачиваются: CLI не меняется, это вне тикета.
12. Новые исключения в `errors.py` без нового конструктора: наследуют `StatementError`.

## Risks / Trade-offs

- [Для CLI меняется поведение `import` (дедупликация, пустые строки)] → ожидаемо по тикету; «Imported N» теперь считает только новые.
- [Файл целиком в памяти] → выписки малы; упрощает определение кодировки «файл целиком читается как UTF-8».
- [Допущение о группировке тысяч по 3 цифры] → строго, но так пишет банк; ошибка строки видна пользователю, неверные данные не попадают.
- [cp1251-файл с неопределёнными байтами] → `StatementError` без записи.

## Implementation notes

- `detect_format(text)` принимает уже декодированный текст (BOM отбрасывается).
- Неизвестное значение `fmt` для пустого файла даёт `UnknownFormatError` с `line_no=None` (проверка пустоты первая).
- Новые тесты вынесены в `tests/test_import_statement.py`; существующие не менялись.
