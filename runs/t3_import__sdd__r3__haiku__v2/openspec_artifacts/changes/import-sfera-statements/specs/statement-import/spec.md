## Purpose

Импорт банковских выписок («Нова», «Сфера», «Сфера» с раздельными колонками прихода и расхода)
в хранилище транзакций: определение формата и кодировки, разбор строк, защита от повторного
импорта уже сохранённых операций, понятные ошибки строк и строгий режим без частичной записи.

## ADDED Requirements

### Requirement: Format detection by header
Импорт SHALL определять формат выписки по первой строке файла (заголовку, строка 1). Заголовок
распознаётся, если в нём есть все обязательные колонки формата. Названия колонок сравниваются без
учёта регистра и пробелов по краям; порядок колонок и лишние колонки SHALL NOT влиять на
распознавание. Форматы: `nova` (разделитель `,`, колонки `date`, `amount`, `description`), `sfera`
(разделитель `;`, колонки `Дата`, `Сумма`, `Описание`), `sfera_split` (разделитель `;`, колонки
`Дата`, `Описание`, `Приход`, `Расход`). Если заголовок не распознан, импорт MUST бросить
`UnknownFormatError` без записи в хранилище.

#### Scenario: Sfera header with different case and spacing
- **WHEN** первая строка файла равна `ДАТА; Сумма ;Описание;Номер карты`
- **THEN** `detect_format` возвращает `"sfera"`, а лишняя колонка `Номер карты` игнорируется

#### Scenario: Split header is recognized
- **WHEN** первая строка файла равна `Дата;Описание;Приход;Расход`
- **THEN** `detect_format` возвращает `"sfera_split"`

#### Scenario: Unknown header
- **WHEN** первая строка файла равна `date,sum,description`
- **THEN** импорт бросает `UnknownFormatError` с `line_no` равным 1, и хранилище не меняется

#### Scenario: Empty file
- **WHEN** файл пустой
- **THEN** импорт бросает `UnknownFormatError`, и хранилище не меняется

#### Scenario: Header with a duplicated required column
- **WHEN** заголовок содержит две колонки `Сумма`
- **THEN** импорт бросает `UnknownFormatError`, потому что колонка неоднозначна

### Requirement: Explicit format must match the header
Если вызывающий код передаёт `fmt`, импорт SHALL использовать только этот формат. Если заголовок
не подходит к `fmt` или `fmt` не является одним из `nova`, `sfera`, `sfera_split`, импорт MUST
бросить `UnknownFormatError` без записи в хранилище, в любом режиме `strict`.

#### Scenario: Header does not match the explicit format
- **WHEN** вызван `import_statement(path, store, fmt="nova")` и заголовок файла равен `Дата;Сумма;Описание`
- **THEN** импорт бросает `UnknownFormatError` и ничего не записывает

#### Scenario: Explicit format matches
- **WHEN** вызван `import_statement(path, store, fmt="sfera")` и заголовок файла распознан как `sfera`
- **THEN** импорт использует формат `sfera`

### Requirement: Encoding detection
Импорт SHALL читать файл целиком как UTF-8; BOM в начале допустим и игнорируется. Если файл не
читается как UTF-8, импорт SHALL читать его как cp1251. Результат MUST содержать `encoding`
со значением `"utf-8"` или `"cp1251"`. Если файл не декодируется ни одной из кодировок, импорт
MUST бросить `UnknownFormatError`.

#### Scenario: UTF-8 with BOM from Excel
- **WHEN** файл сохранён в UTF-8 с BOM и заголовок `Дата;Сумма;Описание`
- **THEN** заголовок распознаётся, а `ImportResult.encoding` равен `"utf-8"`

#### Scenario: Windows-1251 file
- **WHEN** файл сохранён в cp1251, содержит кириллический заголовок и описания
- **THEN** импорт читает файл как cp1251, а `ImportResult.encoding` равен `"cp1251"`

### Requirement: Sfera amounts and dates
Для формата `sfera` дата SHALL быть строго в виде `ДД.ММ.ГГГГ` и соответствовать реальной дате.
Сумма SHALL состоять из необязательного знака (`+` или `-`), цифр, где тысячи отделяются пробелом
или неразрывным пробелом (U+00A0), и необязательной дробной части из одного или двух знаков после
запятой. Приход без знака или со знаком `+`, расход со знаком `-`. Точка как разделитель дробной части
и дробная часть длиннее двух знаков SHALL быть ошибкой строки; сумма SHALL NOT округляться.

#### Scenario: Expense and income with thousands separators
- **WHEN** строки `01.03.2026;-1 200,50;Магазин Лента` и `02.03.2026;+85 000,00;Зарплата`, где пробел между тысячами неразрывный
- **THEN** импортируются транзакции `-1200.50` и `85000.00` с датами 2026-03-01 и 2026-03-02

#### Scenario: Dot as decimal separator
- **WHEN** сумма равна `1 234.56`
- **THEN** строка становится ошибкой с `line_no` этой строки, и сумма не угадывается

#### Scenario: More than two decimal places
- **WHEN** сумма равна `-1,500`
- **THEN** строка становится ошибкой, а не округляется до `-1.50`

#### Scenario: Invalid date format
- **WHEN** дата равна `2026-03-01` или `31.02.2026`
- **THEN** строка становится ошибкой строки

#### Scenario: Zero amount
- **WHEN** сумма равна `-0,00`
- **THEN** строка становится ошибкой, потому что нулевая транзакция недопустима

### Requirement: Sfera split amounts
Для формата `sfera_split` суммы в колонках `Приход` и `Расход` SHALL быть без знака, в том же
числовом формате, что и `sfera`. Заполнена ровно одна из двух колонок: значение `Приход` даёт
положительную сумму, значение `Расход` даёт отрицательную. Знак в любой из колонок, обе заполненные
колонки или ни одной заполненной колонки SHALL быть ошибкой строки. Значение `0,00` SHALL считаться
пустым.

#### Scenario: Expense goes negative
- **WHEN** строка `03.03.2026;Кофе;;150,00` (колонка `Приход` пуста, `Расход` равен `150,00`)
- **THEN** импортируется транзакция `-150.00`

#### Scenario: Zero in the unused column
- **WHEN** строка `03.03.2026;Зарплата;85 000,00;0,00`
- **THEN** импортируется транзакция `85000.00`, потому что `0,00` в `Расход` равно пустой колонке

#### Scenario: Both columns filled
- **WHEN** строка `03.03.2026;Странно;10,00;10,00`
- **THEN** строка становится ошибкой строки

#### Scenario: Sign in a split column
- **WHEN** строка `03.03.2026;Кофе;;-150,00`
- **THEN** строка становится ошибкой строки

### Requirement: Junk rows are skipped
Строки, в которых все ячейки пусты или состоят из пробельных символов (включая строки из одних
разделителей `;;;` или `,,`), SHALL пропускаться в любом месте файла. Такие строки SHALL NOT попадать
в `errors`, в `duplicates` или в `added`.

#### Scenario: Trailing junk from a Sfera export
- **WHEN** в конце файла есть пустая строка, строка из пробелов и строка `;;;`
- **THEN** эти строки пропускаются, а `errors` остаётся пустым

#### Scenario: Junk row in the middle
- **WHEN** Nova-выписка содержит строку `,,` между двумя корректными строками
- **THEN** строка `,,` пропускается, а две корректные строки импортируются

### Requirement: Row errors do not stop a non-strict import
Если `strict` равен `False` (значение по умолчанию), ошибочная строка SHALL попасть в
`ImportResult.errors` как `RowError` с `line_no` по правилам `StatementError` (номер физической строки
файла, заголовок — строка 1), а остальные строки SHALL импортироваться. Ошибкой строки является
всё, из чего не собирается корректная `Transaction`, включая пустое описание, неверную дату,
неверную сумму и недостающие ячейки.

#### Scenario: One broken row among valid rows
- **WHEN** в файле из трёх строк вторая строка содержит дату `2026-13-01`
- **THEN** `errors` содержит одну запись с `line_no` равным 3, а первая и третья строки добавляются

#### Scenario: Multi-line quoted record
- **WHEN** запись в кавычках занимает строки 4–5 и ошибочна
- **THEN** `RowError.line_no` равен 4, то есть строке, с которой запись начинается

### Requirement: Strict mode is atomic
Если `strict` равен `True`, импорт SHALL бросить `StatementRowError` с заполненным `line_no` на
первой ошибочной строке. В этом случае в хранилище и в файл хранилища SHALL NOT попасть никакие
транзакции из файла. Дубли при этом ошибками не считаются.

#### Scenario: Error in the last line
- **WHEN** в файле 100 корректных строк и ошибка в строке 101, вызван `strict=True`
- **THEN** бросается `StatementRowError` с `line_no` равным 101, и `store.all()` не меняется

#### Scenario: Duplicates in strict mode
- **WHEN** все строки файла уже есть в хранилище и вызван `strict=True`
- **THEN** импорт завершается без исключения, `duplicates` равен числу строк, `added` равен 0

### Requirement: Duplicate detection against the existing store
Транзакция из файла SHALL считаться дублем, если в хранилище есть транзакция с той же датой, той же
суммой и тем же нормализованным описанием. Сравнение SHALL выполняться только с транзакциями, которые
были в хранилище до начала импорта. Если в хранилище уже есть `k` таких транзакций, а в файле `n`
подходящих строк, то первые `min(k, n)` строк файла SHALL считаться дублями (в `duplicates`), остальные
SHALL добавляться. Одинаковые строки внутри одного файла дублями SHALL NOT считаться, если их больше,
чем уже есть в хранилище.

#### Scenario: Repeated import adds nothing
- **WHEN** выписка из трёх строк импортирована дважды подряд
- **THEN** второй импорт возвращает `added` равным 0 и `duplicates` равным 3

#### Scenario: Overlapping period adds only new rows
- **WHEN** в хранилище есть операции за 1–10 марта, и импортируется выписка за 5–15 марта
- **THEN** операции за 5–10 марта считаются дублями, а операции за 11–15 марта добавляются

#### Scenario: Two identical purchases in one file
- **WHEN** файл содержит две строки `02.03.2026;-150,00;Кофе` и в хранилище таких операций нет
- **THEN** обе строки добавляются, и `duplicates` равен 0

#### Scenario: Identical purchase already stored once
- **WHEN** в хранилище есть одна операция `Кофе` за 02.03.2026 на -150.00, а файл содержит две такие строки
- **THEN** первая строка считается дублем, вторая добавляется

### Requirement: Normalized description comparison
Описания при сравнении на дубли SHALL сравниваться через `normalize_description`, которая совпадает
с нормализацией, используемой в проекте для правил категоризации. Сохраняемое описание SHALL оставаться
таким, каким оно пришло, с обрезанными пробелами по краям.

#### Scenario: Case, spacing and yo/ye differences
- **WHEN** в хранилище есть описание `  Кофейня   Зерно`, а в файле `кофейня зерно`
- **THEN** строка из файла считается дублем, если дата и сумма совпадают

#### Scenario: Stored description is not normalized
- **WHEN** импортируется строка с описанием `Магазин  Лента`
- **THEN** сохранённое описание равно `Магазин  Лента` с сохранёнными внутренними пробелами

### Requirement: Categorization and import timestamp
Импорт SHALL применять `categorizer` только к добавляемым транзакциям, а не к дублям. Все транзакции
одного импорта SHALL получать одинаковое значение `imported_at`, равное `clock.now()`, вызванному один раз
в начале импорта.

#### Scenario: Duplicates are not categorized
- **WHEN** импорт с категоризатором пропускает дубль
- **THEN** категоризатор не вызывается для этой строки

#### Scenario: Shared imported_at
- **WHEN** импортируются три транзакции с `FixedClock`
- **THEN** у всех трёх `imported_at` равен времени часов

### Requirement: Import_csv compatibility
`import_csv(path, store, categorizer=None, clock=None)` SHALL сохранять сигнатуру и возвращать `int`
— число добавленных транзакций. Внутри она SHALL вызывать `import_statement` с `fmt="nova"` и
`strict=True`, поэтому она дедуплицирует, принимает BOM и cp1251, пропускает пустые строки и
атомарна. Ошибки SHALL быть `StatementError` или его наследниками, а не голыми исключениями
файловой системы.

#### Scenario: Repeated CLI import does not duplicate
- **WHEN** `import_csv` вызван дважды с одним и тем же файлом Nova
- **THEN** второй вызов возвращает 0, а хранилище содержит операции только один раз

#### Scenario: Bad Nova row keeps the store unchanged
- **WHEN** в файле Nova строка 3 содержит `0.00` как сумму
- **THEN** `import_csv` бросает `StatementRowError` с `line_no` равным 3, и хранилище не меняется

#### Scenario: Missing file
- **WHEN** путь к файлу не существует
- **THEN** бросается `StatementError`, а не `FileNotFoundError`
