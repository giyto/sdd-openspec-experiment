## Why

Сейчас товар списывается только при отгрузке. Пока покупатель оформляет и оплачивает заказ,
тот же товар успевают продать второй раз, и склад потом извиняется перед клиентом.
Нужно резервировать товар под заказ в момент оформления. Неоплаченный резерв должен сам
перестать действовать по TTL. Фоновых задач в сервисе нет и не будет, поэтому истечение
резерва определяется по часам сервиса в момент обращения (`Inventory.clock`), без записи в журнал.

## What Changes

- Добавляется резервирование товара под заказ в `Inventory`: `reserve`, `confirm`, `cancel`,
  `extend`, `get_reservation`, `available`, `reserved`.
- Резерв держит товар по всем строкам заказа (строки могут быть на разных складах) и не меняет
  физический остаток. Срок по умолчанию — `DEFAULT_RESERVATION_TTL = 15 минут`.
- Резерв со статусом `ACTIVE` перестаёт действовать в момент `expires_at`: в снимке он показывается
  как `EXPIRED`, в `available`/`reserved` не учитывается. Запись в журнал при истечении не пишется.
- `confirm` превращает активный резерв в отгрузку: физический остаток списывается по строкам,
  пишутся события `ISSUE` (с `ref` = номер заказа) и `RESERVE_CONFIRM`.
- `cancel` освобождает резерв; повторная отмена и отмена истёкшего резерва — no-op без событий.
- `extend` продлевает активный резерв до `now + ttl`, срок никогда не сокращается.
- Новые модели `ReservationStatus`, `ReservationLine`, `Reservation` (`warehouse/models.py`)
  и новые исключения `ReservationError` и наследники (`warehouse/errors.py`).
- **BREAKING** (для поведения сверх прежнего API): `issue` и `transfer` (как расход со склада-источника)
  больше не могут забрать товар, зарезервированный в активных резервах. Запрос сверх доступного
  остатка даёт `InsufficientStockError`. Для кода без резервов поведение не меняется.
- Журнал: новые типы событий `RESERVE`, `RESERVE_CONFIRM`, `RESERVE_CANCEL`, `RESERVE_EXTEND`
  (формат строки журнала не меняется).

## Capabilities

### New Capabilities
- `inventory/reservations`: резервирование товара под заказы — жизненный цикл резерва
  (активный, истёкший, подтверждённый, отменённый), TTL по часам сервиса, расчёт доступного и
  зарезервированного количества, события журнала по резервам, а также правило доступности
  для `issue` и `transfer`.

## Impact

- Код: `warehouse/models.py`, `warehouse/errors.py`, новый модуль `warehouse/reservations.py`
  (константа TTL), `warehouse/inventory.py` (новые методы, проверка доступности в `issue`/`transfer`),
  `warehouse/storage.py` (хранение резервов по `order_id`).
- Не трогаем: `warehouse/cli.py`, `warehouse/reports.py`, существующие тесты, зависимости
  (остаётся только стандартная библиотека).
- Тесты: новый файл с тестами резервов; существующие тесты не меняются.
- API: старые методы `receive/issue/transfer/adjust/on_hand/stock_levels` сохраняют сигнатуры;
  `on_hand` и `stock_levels` продолжают показывать физический остаток.
