## Context

Импорт сейчас живёт в `ledger/importer.py`: `import_csv` жёстко читает UTF-8 CSV с колонками
`date,amount,description`, пишет строки по одной через `store.add` и бросает на первой кривой строке,
оставляя уже записанную часть. Хранилища (`MemoryStore`, `JsonFileStore`) умеют атомарную пачку
через `add_many`, а `JsonFileStore` пишет файл один раз на вызов. Нормализация описаний для сравнения
уже есть: `rules.normalize_text`. См. proposal.md — Why; требования — specs/statement-import/spec.md.

Ограничения проекта: только стандартная библиотека; `ledger/cli.py` и `ledger/reports.py` не трогаем;
публичный API `Transaction`, хранилищ и `Categorizer` не меняем; существующие тесты в
`tests/test_importer.py` и `tests/test_cli.py` не меняем и они должны проходить без правок.

## Goals / Non-Goals

**Goals:**
- Один вход `import_statement` для всех трёх форматов с автоопределением формата и кодировки.
- Разбор всех строк файла с отчётом по каждой ошибочной строке, без частичной записи в строгом режиме.
- Дедупликация с хранилищем по правилу «min(k, n)» из спецификации, одна запись в хранилище на импорт.
- `import_csv` становится тонкой обёрткой над `import_statement` (`nova`, `strict=True`).

**Non-Goals:**
- Не меняем формат хранения JSON, `Transaction`, `Categorizer`, CLI и отчёты.
- Не поддерживаем Excel-файлы (`.xlsx`) и другие форматы, кроме трёх перечисленных.
- Не нормализуем сохраняемые описания (только сравнение).
- Не добавляем вывод ошибок в CLI: `cli.py` не трогаем.

## Decisions

**Один модуль, таблица форматов.** Вся логика остаётся в `ledger/importer.py`. Каждый формат описан
записью `_Format(name, delimiter, required_columns, parse_row)`; `nova`, `sfera`, `sfera_split` отличаются
только разбором строки. Альтернатива — отдельный пакет `ledger/formats/` — отвергнута: форматов три,
а публичный API модуля `ledger.importer` должен остаться тем же.

**Два прохода: разбор, затем запись.** Сначала читаем файл и для каждой непустой строки получаем либо
`Transaction`, либо `RowError`. Затем, уже в памяти: в строгом режиме при первой ошибке бросаем
`StatementRowError` (ничего не записано); иначе отбираем дубли и вызываем `store.add_many` один раз.
Так гарантируется «ничего не попадает в память и в JSON» при ошибке и одна запись на диск. Альтернатива —
писать построчно с откатом — отвергнута: откат поверх `add_many` сложнее и хуже ложится на `JsonFileStore`.

**Сопоставление заголовка.** Имена колонок сравниваются через `strip().casefold()`. Заголовок ищется
в первой непустой строке файла. Для каждого формата проверяется, что все обязательные колонки
присутствуют; лишние колонки игнорируются. Если подходят несколько форматов или ни один, — `UnknownFormatError`.
Допущение: регистронезависимое сопоставление применяем и к `nova` (раньше было точное совпадение) —
это не сужает то, что уже работало. Разделитель задаётся форматом (`,` для nova, `;` для sfera), поэтому
заголовок другого формата не распознаётся как «наш» и даёт `UnknownFormatError`.

**`UnknownFormatError.line_no`.** Для нераспознанного заголовка выставляем `line_no=1` — это нужно,
чтобы сохранить текущий тест `test_import_missing_column` (он проверяет `line_no == 1`). Для пустого файла
`line_no=None`. Это решение записано в спецификации.

**Номер строки.** Используем `csv.reader` поверх декодированного текста (`io.StringIO`, `newline=""`).
Начало записи = `reader.line_num` предыдущей записи + 1; так пустые строки и многострочные кавычки учитываются
как в докстринге `StatementError`.

**Кодировка.** Файл читается целиком в байты. Сначала строгий `decode("utf-8-sig")` (BOM снимается; `encoding`
в результате всё равно `"utf-8"`), при ошибке — строгий `cp1251`. Если и cp1251 не декодируется, —
`UnknownFormatError` (`line_no=None`).

**Разбор сумм.** `nova` — существующий `parse_amount` (точка, без разделителей). `sfera` / `sfera_split` —
собственный разбор: регулярка `^[+-]?(\d{1,3}([  ]\d{3})+|\d+)(,\d{1,2})?$` после `strip()`, затем удаляем
пробелы-разделители и заменяем запятую точкой, далее `Decimal` через `to_money`. Точка в сумме отклоняется
регуляркой; «0,00» (и любой ноль) проверяется через `Transaction` (`amount must be non-zero`) или, для
`sfera_split`, считается пустым ячейкой до проверки. Отсутствие дробной части (`1200`) принимаем как целое —
допущение, которое стоит проверить с аналитиком.

**Дубли.** До импорта строим `Counter` по ключу `(date, amount, normalize_description(description))` из
`store.all()`. Проходим валидные строки файла по порядку: если счётчик по ключу > 0 — дубль, счётчик уменьшаем;
иначе строка идёт в запись. Это и есть правило min(k, n). Счётчик строится по состоянию хранилища до импорта,
поэтому дубли внутри файла между собой не сравниваются.

**Мусорные строки.** Строка, все ячейки которой пусты после `strip()` (`str.strip` убирает и U+00A0), пропускается
до разбора формата. Лишние непустые ячейки сверх заголовка — ошибка строки (признак смещения колонок).

**`imported_at` и категоризация.** `clock.now()` вызывается один раз в начале импорта; категоризатор
применяется к каждой добавляемой транзакции, как в текущем `import_csv`.

**`import_csv` через `import_statement`.** Сигнатура и `int` сохраняются; возвращаем `result.added`.
Поскольку `import_csv` теперь строгий, CLI при кривой строке выводит `error: line N: ...` и ничего не пишет —
это изменение поведения CLI без правок `cli.py`, согласовано в задаче. Альтернатива — оставить старый
частичный импорт в `import_csv` — отвергнута в обсуждении.

**`csv.Error`.** Ошибки самого модуля `csv` (например, NUL в строке) считаем ошибкой записи с `line_no`
начала записи. Дальше разбор останавливаем: восстанавливать позицию после ошибки `csv` не берёмся.
В `errors` попадает одна запись с номером строки начала записи; строки после неё не импортируются
(ограничение зафиксировано в рисках). В строгом режиме — `StatementRowError`, как для любой ошибки строки.

## Risks / Trade-offs

- **Остаток файла после `csv.Error` не импортируется** → Ошибка возникает только на экзотическом вводе
  (NUL-байты и подобное); отчёт в `errors` указывает строку, пользователь видит, где обрыв. Тест фиксирует это поведение.
- **Строгий `import_csv` меняет поведение CLI** (раньше частичный импорт, теперь ничего не записывается при ошибке)
  → Это целевое поведение из задачи; описано в proposal.md как BREAKING и покрыто тестами `import_csv`.
- **Допущение про целые суммы без запятой (`1200`) в `sfera`** → Если аналитик решит иначе, это правка одной
  регулярки и одного теста.
- **Сравнение по `Decimal` и дате** → `Transaction` квантует суммы до сотых, поэтому `Decimal("-1200.5")` и
  `Decimal("-1200.50")` совпадают в `Counter`; проверяется тестом.
- **Производительность**: `Counter` строится за один проход по хранилищу, импорт — O(n + m). Для личных выписок
  это достаточно; для `JsonFileStore` запись по-прежнему одна.
- **Сохранение исходного описания без нормализации** → дубли находятся через `normalize_description`, но в
  `Transaction` попадает описание после `strip()`, как и раньше.

## Migration Plan

Миграции данных нет: формат JSON-хранилища не меняется. Выкатка — обычный релиз пакета.
Откат — revert коммита; старый `import_csv` восстанавливается целиком.

## Решения, принятые при реализации

Принято без участия пользователя, при реализации (задача велась автономно):

- **Номер строки заголовка.** Любая ошибка заголовка (нераспознан, не совпал с `fmt`, неоднозначен)
  несёт `line_no=1`, как и требует спецификация, даже если перед заголовком есть пустые строки.
  Для пустого файла и файла из одних пустых строк — `line_no=None`.
- **`nova` дата строго `YYYY-MM-DD`.** Раньше допускалось всё, что принимает `date.fromisoformat`
  (например, `20260301`); теперь регулярка, как требует спецификация.
- **Пустая запись в хранилище не делается.** Если после дедупликации нечего добавлять, `store.add_many`
  не вызывается: повторный импорт не переписывает JSON-файл. Если есть что добавить, вызов один.
- **`ImportResult.errors` — кортеж** (`tuple[RowError, ...]`), чтобы датакласс оставался неизменяемым.
- **Тест `csv.Error` (задача 3.2).** В задаче указан NUL-байт, но на Python 3.13 `csv.reader` NUL
  не отвергает (проверено: строка читается как данные). Поэтому тест вызывает `csv.Error` превышением
  `csv.field_size_limit()`. Поведение обработки (номер строки начала записи, остановка разбора,
  атомарность в строгом режиме) то же самое.
- **Суммы `sfera` без дробной части** (`1200`) принимаются как целые — допущение из раздела «Решения»
  выше, проверить с аналитиком.
