## Context

Сейчас `ledger/importer.py` содержит только `import_csv` для «Новы»: читает файл как UTF-8 без BOM, добавляет строки по одной (`store.add`), падает на первой плохой строке, оставляя уже записанные. Хранилища (`MemoryStore`, `JsonFileStore`) имеют атомарный `add_many` — «все или ни одной»; `JsonFileStore._commit` пишет JSON до обновления памяти. Сравнение описаний в проекте — `ledger.rules.normalize_text`. Требования — в `specs/statement-import/spec.md`, мотивация — в `proposal.md`.

## Goals / Non-Goals

**Goals:**
- Один механизм (`import_statement`) для трёх форматов; `import_csv` — тонкая обёртка.
- Атомарность через единственный вызов `store.add_many`.
- Только стандартная библиотека; публичный API задачи не меняется.

**Non-Goals:**
- Изменения `cli.py`, `reports.py`, `Transaction`, хранилищ, `Categorizer`.
- Автоопределение разделителя за пределами трёх известных заголовков; округление и «угадывание» сумм.

## Decisions

1. **Конвейер**: прочитать байты → декодировать → найти заголовок → разобрать записи → построить список новых транзакций → один `add_many`. Ничего не пишется до конца разбора, поэтому `strict`-ошибка не оставляет следов, а сбой `add_many` (`StorageError`) — тоже. Если список пуст, `add_many` не вызывается (иначе `JsonFileStore` создал бы или перезаписал файл). Альтернатива — `store.add` по строкам с откатом: хрупко, откат JSON невозможен.
2. **Кодировка**: `decode("utf-8-sig")`; при `UnicodeDecodeError` — `decode("cp1251")`; при ошибке и здесь (например, байт 0x98) и при `OSError` — `StatementError` без `line_no`. Имя в результате — `"utf-8"` / `"cp1251"`. Пустой файл — utf-8.
3. **Разбор записей**: `csv.reader(io.StringIO(text, newline=""), delimiter=...)`. Номер начала записи — `reader.line_num` до чтения + 1 (физическая нумерация, корректна для многострочных записей в кавычках). Разделитель зависит от формата (`,` для nova, `;` для sfera*), поэтому при автоопределении заголовок (первая непустая запись) разбирается обоими разделителями.
4. **Заголовок**: таблица `FORMATS = {имя: (разделитель, нужные колонки)}`. Названия нормализуются `strip().casefold()` (nbsp срезается `str.strip`). Кандидаты — форматы, у которых каждая нужная колонка присутствует ровно один раз. При `fmt=None` нужен ровно один кандидат; при явном `fmt` — этот формат должен подходить. Иначе `UnknownFormatError(line_no=<строка заголовка>)` (для пустого файла `None`). `detect_format` использует ту же функцию без разбора строк.
5. **Мусорные строки**: запись пропускается, если `all(not cell.strip() for cell in row)` (включая `[]`). Так `;;;` в sfera и `,,` в nova пропускаются естественно; `,,` в sfera — одно непустое поле, то есть ошибка строки (мусор определяется разделителем формата).
6. **Ошибки строк**: нужная колонка за концом записи → «not enough fields»; непустые поля сверх длины заголовка → «too many fields» (иначе неэкранированный `;` в описании молча обрежет описание); пустые хвостовые поля допустимы. Разбор строки бросает `StatementRowError`; в нестрогом режиме он перехватывается и превращается в `RowError(line_no, exc.message)`, в строгом — пробрасывается. `csv.Error` — ошибка строки с номером начала записи, после неё разбор останавливается (ресинхронизация невозможна).
7. **Суммы и даты sfera**: ASCII-регулярки (не `\d` без `re.ASCII`, чтобы не принять юникодные цифры): `^[+-]?([0-9]{1,3}([  ][0-9]{3})+|[0-9]+)(,[0-9]{1,2})?$` для `sfera`, то же без знака для `sfera_split`; затем `Decimal` из строки с `.` вместо `,` и без пробелов, `to_money`. Дата — `^[0-9]{2}\.[0-9]{2}\.[0-9]{4}$` + `dt.date(y, m, d)` (`strptime` принимает `1.3.2026`, поэтому не подходит). Нулевую сумму и пустое описание отсекает `Transaction.__post_init__` (`ValidationError` → ошибка строки). Для `sfera_split` значение колонки «пусто» = пустая строка после `strip` или валидная нулевая сумма; ровно одна колонка должна быть непустой.
8. **nova**: строка разбирается как раньше (`date.fromisoformat`, `parse_amount`, `strip` описания) — существующие тесты и поведение не меняются.
9. **Дедупликация**: `Counter` по ключу `(date, amount, normalize_description(description))` из снимка `store.all()` до импорта. Идём по корректным строкам файла по порядку: если `counter[key] > 0` — уменьшаем, `duplicates += 1`; иначе строка идёт в добавление, счётчик не увеличивается (внутрифайловые повторы не дубли). `normalize_description` делегирует `ledger.rules.normalize_text`, чтобы не появилось второго определения сравнения.
10. **Категория и время**: `clock.now()` вызывается один раз; категоризатор применяется только к добавляемым строкам через `dataclasses.replace(tx, category=...)`, когда результат не `None`.
11. **`import_csv`**: `import_statement(path, store, fmt="nova", strict=True, categorizer=categorizer, clock=clock).added`. Старые тесты сохраняются: заголовок `date,sum,description` → `UnknownFormatError` с `line_no=1`, плохая строка → `StatementRowError` с `line_no=3`; CLI ловит `LedgerError` и печатает ошибку как раньше.
12. **Неизвестное значение `fmt`** → `UnknownFormatError`; нечитаемый файл → `StatementError`, чтобы CLI (ловит только `LedgerError`) не падал трассировкой.

## Risks / Trade-offs

- [Повторный `import_csv` теперь возвращает 0 вместо задвоения] → согласовано в задаче, зафиксировано в спеке.
- [Строгая проверка групп тысяч: `12 00,50` — ошибка; U+202F не принимается] → ошибка строки вместо тихо неверной суммы.
- [`csv.Error` останавливает разбор остатка файла] → ошибка видна в `errors`, строки до неё импортируются.
- [Ключ дубля без категории] → категория не часть идентичности операции.
- [Файл читается в память целиком] → выписки малы; нужно для «читается целиком как UTF-8» и атомарности.

## Допущения (неоднозначности из задачи)

- Заголовок — первая непустая запись; пустые строки перед ним допустимы.
- Правила сопоставления заголовка (регистр, пробелы, лишние колонки, любой порядок) применяются ко всем трём форматам, включая nova.
- Двусмысленный заголовок и повторяющиеся названия нужных колонок — `UnknownFormatError`.
- Ошибка чтения или декодирования файла — `StatementError` без `line_no`.
- Строка длиннее заголовка с непустыми лишними полями — ошибка строки.

- При реализации `csv.reader` создаётся с `strict=True`, чтобы незакрытая кавычка давала `csv.Error` (ошибку строки), а не молча поглощала остаток файла.
