## Purpose

Описывает dead-letter: хранение заданий, исчерпавших попытки, просмотр в порядке попадания и осознанный возврат в работу.

## ADDED Requirements

### Requirement: Просмотр dead-letter
Очередь SHALL отдавать список записей dead-letter в порядке попадания. Запись содержит идентификатор и тип задания, число попыток на момент попадания, текст последней ошибки и момент попадания (по часам очереди). Возвращаемый список SHALL быть копией: его изменение не влияет на очередь.

#### Scenario: Порядок
- **WHEN** в dead-letter последовательно попали задания B, затем A
- **THEN** записи идут в порядке B, A

#### Scenario: Содержимое записи
- **WHEN** задание типа `email` исчерпало 3 попытки с ошибкой `TimeoutError: gateway`
- **THEN** запись содержит его id, тип `email`, `attempts=3`, ошибку `TimeoutError: gateway` и время попадания

#### Scenario: Пусто
- **WHEN** заданий в dead-letter нет
- **THEN** возвращается пустой список

### Requirement: Возврат из dead-letter
Возврат SHALL работать по идентификатору, переводить то же задание (новое не создаётся) в `PENDING` с `run_at` = текущее время, очищать `error`, обнулять `attempts` и `finished_at`, удалять запись из dead-letter и увеличивать `jobs.requeued`. Число попыток до возврата сохраняется только в логе. Для неизвестного идентификатора SHALL выбрасываться ошибка «задание не найдено», для задания не в dead-letter — ошибка недопустимого перехода; состояние при этом не меняется. После возврата задание SHALL получить полный набор попыток по действующей политике.

#### Scenario: Успешный возврат
- **WHEN** возвращается задание из dead-letter
- **THEN** это тот же объект: `PENDING`, `run_at` = сейчас, `error=None`, `attempts=0`, записи в dead-letter нет, воркер может его взять

#### Scenario: Первая ошибка после возврата
- **WHEN** возвращённое задание снова упало один раз при `max_attempts=3`
- **THEN** оно уходит в `RETRY_SCHEDULED`, а не в dead-letter

#### Scenario: Не в dead-letter
- **WHEN** возвращается задание со статусом `PENDING`
- **THEN** ошибка недопустимого перехода, счётчик `jobs.requeued` не меняется

#### Scenario: Неизвестный идентификатор
- **WHEN** возвращается несуществующее задание
- **THEN** ошибка «задание не найдено»

### Requirement: Единственный выход из dead-letter
Задание в `DEAD_LETTERED` SHALL не выбираться воркером, не отменяться и не удаляться очисткой завершённых заданий (`purge_finished`) при любом возрасте. Единственный способ вернуть его в работу — возврат из dead-letter.

#### Scenario: Отмена запрещена
- **WHEN** отменяется задание в `DEAD_LETTERED`
- **THEN** ошибка недопустимого перехода, статус не меняется

#### Scenario: Очистка
- **WHEN** выполняется `purge_finished` с `older_than=0` спустя длительное время
- **THEN** задания в dead-letter остаются в хранилище, записи сохраняются

#### Scenario: Воркер
- **WHEN** у задания в dead-letter давно наступил `run_at`
- **THEN** воркер его не берёт
