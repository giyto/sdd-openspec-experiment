## Why

Маркетинг запускает летнюю кампанию с промокодами. Сейчас скидки делает поддержка вручную, и суммы
расходятся с чеками. Нужно, чтобы промокод передавался при расчёте (`quote`) и оформлении заказа
(`place_order`), а скидка честно отражалась в итогах и построчно в чеке: бухгалтерия считает налог
по строкам (SHOP-412).

## What Changes

- Новый модуль `shop/promo.py`: `DiscountKind` (PERCENT, FIXED), `PromoCode` (неизменяемая модель с
  проверкой инвариантов), `PromoRegistry` (хранение кодов, проверка существования, срока действия и
  лимита использований, счётчик использований).
- Новые исключения в `shop/errors.py`: `PromoError(ShopError)` и три независимых наследника —
  `UnknownPromoCodeError`, `PromoExpiredError`, `PromoConditionsError`.
- `shop/pricing.py`: `calculate_total(..., *, promo=None)` распределяет скидку по участвующим строкам
  (`LineTotal.discount`, `OrderTotal.discount`), налог строки считается с суммы после скидки,
  доставка порога бесплатной доставки использует сумму товаров после скидки, но стоимость доставки
  скидка не уменьшает.
- `shop/orders.py`: `OrderService(..., promos=None)`, `quote(cart, promo_code=None)`,
  `place_order(cart, promo_code=None)`, `Order.promo_code`. Использование считается только при
  успешном `place_order`; при `cancel` использование возвращается (счётчик уменьшается на один).
- Пустой или пробельный код означает «кода нет». Любой ненулевой код без реестра — неизвестный.
- Старые вызовы `calculate_total(cart)`, `calculate_total(cart, shipping, tax)`, `quote(cart)`,
  `place_order(cart)`, `cancel(order_id)` работают как раньше и дают те же суммы.
- Новые тесты кладутся отдельными файлами; существующие тесты не меняются.

Не входит в change: `shop/cli.py`, `shop/reports.py` (скидки в CLI и отчётах — отдельным тикетом),
изменения README, новые зависимости.

## Capabilities

### New Capabilities
- `promo-codes`: модель промокода, нормализация кода, реестр (существование, срок действия
  `[starts_at, expires_at)`, лимит использований), ошибки промокодов, учёт использований при
  оформлении и возврате при отмене.
- `checkout-discounts`: применение промокода при расчёте итогов заказа — участвующие строки, минимальная
  сумма, распределение скидки по строкам с копейками, налог и доставка с учётом скидки, интеграция с
  `OrderService` (`quote`, `place_order`, `cancel`).

### Modified Capabilities
- Нет. В `openspec/specs/` пока нет утверждённых спецификаций; существующее поведение расчёта и
  заказов сохраняется без изменения требований для вызовов без промокода.

## Impact

- Код: `shop/promo.py` (новый), `shop/errors.py`, `shop/pricing.py`, `shop/orders.py`.
- Модели: `LineTotal` и `OrderTotal` получают поле `discount` (по умолчанию `0.00`); `Order` получает
  `promo_code` (по умолчанию `None`). Все новые поля добавляются в конец с значениями по умолчанию,
  позиционные вызовы не ломаются.
- Публичное API `shop`: новые имена и параметры с умолчанием; `cli.py` и `reports.py` не меняются.
- Зависимости: не добавляются (только стандартная библиотека и pytest).
- Тесты: новые файлы в `tests/`, существующие не меняются.
