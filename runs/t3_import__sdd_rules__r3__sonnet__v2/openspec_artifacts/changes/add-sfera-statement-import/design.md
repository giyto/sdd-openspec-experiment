## Context

Сейчас `ledger/importer.py` содержит только `import_csv` для «Новы»: читает файл в UTF-8, пишет каждую строку через `store.add` (не атомарно), падает на первой ошибке. `StatementError` уже задаёт нумерацию `line_no` (физические строки, заголовок — 1, пустые считаются, многострочная запись — по строке начала). `rules.normalize_text` — общее сравнение описаний. `MemoryStore.add_many` атомарен (JsonFileStore пишет файл до смены памяти). Мотивация — см. proposal.md, требования — specs/statement-import/spec.md.

## Goals / Non-Goals

**Goals:**
- Один механизм (`import_statement`) под всеми форматами; `import_csv` — тонкая обёртка.
- Атомарность через «сначала разобрать всё, потом одна запись `add_many`».

**Non-Goals:**
- Изменения `cli.py`, `reports.py`, моделей, хранилищ, `Categorizer`.
- Сторонние зависимости, потоковое чтение больших файлов (выписки малы).

## Decisions

1. **Чтение файла целиком как байты.** `bytes → decode('utf-8-sig')`, при `UnicodeDecodeError` — `decode('cp1251')`; ошибка и там → `UnknownFormatError`. Альтернатива «угадывать по первым байтам» отвергнута: требование «целиком читается как UTF-8». Текст оборачивается в `io.StringIO(text, newline="")` и читается `csv.reader`: `reader.line_num` даёт физическую нумерацию, номер начала записи = `line_num` перед `next()` + 1. `splitlines()` не используется (режет по лишним символам вроде U+2028).
2. **Описание форматов таблицей** (разделитель, обязательные колонки, функция сборки `(date, amount, description)` из ячеек). Колонки ищутся по `name.strip().casefold()`; маппинг имя→индекс. Заголовок парсится разделителем каждого формата; подходящих должно быть ровно одно (при `fmt` — именно он), иначе `UnknownFormatError` (`line_no` строки заголовка). Альтернатива «общий парсер с авто-разделителем» отвергнута: `sniff` ненадёжен.
3. **Мусорная строка** — все ячейки после `strip()` пусты (включая `[]`). Проверяется до разбора и до заголовка.
4. **Суммы «Сферы»** — регэксп на ASCII-цифрах `^[+-]?(\d{1,3}([  ]\d{3})+|\d+)(,\d{1,2})?$` (`re.ASCII`/`[0-9]`), затем замена пробелов и запятой и `to_money(Decimal(...))`. Для `sfera_split` знак запрещён отдельной проверкой. `Decimal` и `\d` без ASCII приняли бы нелатинские цифры — запрещено намеренно. Дата — `^[0-9]{2}\.[0-9]{2}\.[0-9]{4}$` + `dt.date(...)`. `nova` использует прежние `date.fromisoformat` и `parse_amount`.
5. **Ошибка строки** = `ValidationError`/`ValueError`/ошибка разбора при сборке `Transaction` и нехватка ячеек; превращается в `RowError(line_no, message)`. `csv.Error` на записи — тоже ошибка строки (assumption).
6. **Дедупликация:** `Counter` по ключу `(date, amount, normalize_description(description))` от `store.all()` до импорта; для каждой валидной строки в порядке файла: счётчик > 0 → уменьшить, `duplicates += 1`; иначе в список на добавление. Внутрифайловые повторы не пополняют счётчик. `normalize_description = rules.normalize_text` (обёртка-делегат, без копии логики).
7. **Запись:** категоризация до записи; `imported_at = clock.now()` один раз; один вызов `store.add_many(new)`, и только если `new` непусто. `strict=True` — `StatementRowError` на первой ошибке, до записи. Альтернатива «откат после `add`» отвергнута: у хранилищ нет отката.
8. **`import_csv`** = `import_statement(path, store, fmt="nova", strict=True, categorizer=..., clock=...).added`.
9. **Исключения:** `UnknownFormatError` и `StatementRowError` — простые подклассы `StatementError` в `errors.py`; `StatementRowError` требует `line_no` (проверка в конструкторе не нужна — всегда передаётся).

## Допущения (неоднозначности задачи, решены автономно)

- Заголовок — первая немусорная строка (мусор перед ним допустим); пустой файл или только мусор → `UnknownFormatError` с `line_no=None`.
- `UnknownFormatError` для нераспознанного заголовка несёт `line_no` строки заголовка (нужно, чтобы существующий тест `test_import_missing_column` с `line_no == 1` остался зелёным).
- Нечитаемый ни как UTF-8, ни как cp1251 файл (байты, не определённые в cp1251) и неизвестное значение `fmt` → `UnknownFormatError`.
- Правила гибкого поиска колонок (регистр, пробелы, порядок, лишние) применяются ко всем трём форматам, включая `nova` (надмножество прежнего поведения).
- Тысячи — только группами по три цифры с пробелом/U+00A0; `1 20,00` — ошибка. Целая сумма без запятой допустима. Знак — только ASCII `+`/`-`. Юникодный минус — ошибка.
- В `sfera_split` «ноль» = любое корректное число с нулевым значением (`0`, `0,0`, `0,00`); прочее содержимое неиспользуемой колонки — ошибка.
- Строка длиннее/короче заголовка: лишние ячейки справа игнорируются; нехватка ячейки нужной колонки — ошибка («not enough fields»).
- Если добавлять нечего, `add_many` не вызывается (JSON-файл не создаётся и не перезаписывается).
- Нет файла/нет прав — `OSError` как раньше (не `StatementError`); CLI это не меняется.

## Risks / Trade-offs

- [`import_csv` теперь пропускает дубли — CLI-вывод «Imported N» уменьшится при повторе] → это целевое поведение тикета, зафиксировано в README.
- [Чтение файла целиком в память] → выписки малы; принято.
- [Строгая проверка групп тысяч может отвергнуть экзотику] → ошибка строки видна пользователю, а не молча искажает сумму.
- [Дедуп по количеству зависит от порядка строк файла] → поведение определено продактом (первые min(k, n) строк).
