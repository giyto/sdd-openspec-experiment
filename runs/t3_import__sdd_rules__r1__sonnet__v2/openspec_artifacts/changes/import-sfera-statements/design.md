## Context

Сейчас `ledger/importer.py` содержит только `import_csv` для «Новы»: читает файл как UTF-8, пишет транзакции по одной через `store.add` и падает на первой кривой строке. Хранилища уже умеют атомарную пачку — `add_many` (одна запись на диск, всё или ничего). Сравнение описаний «как везде в проекте» — `rules.normalize_text`. Мотивация и границы — в proposal.md, требования — в specs/statement-import/spec.md. Публичный API из тикета не меняется.

## Goals / Non-Goals

**Goals:**
- Один конвейер для всех форматов; `import_csv` — тонкая обёртка над ним.
- Атомарность за счёт «сначала разобрать весь файл, потом одна запись `add_many`».

**Non-Goals:**
- Правки `cli.py`, `reports.py`, моделей, хранилищ, `Categorizer`.
- Угадывание данных (точка в сумме, округление, другие форматы дат).
- Новые зависимости.

## Decisions

1. **Конвейер**: прочитать байты → декодировать → найти формат по заголовку → разобрать все записи в список `(line_no, Transaction | ошибка)` → дедупликация → (`strict`: первая ошибка → `StatementRowError`) → одна `store.add_many(new)` → `ImportResult`. Ничего не пишется до конца разбора, поэтому strict и «упало на середине» не оставляют следов. Если добавлять нечего, `add_many` не вызывается (JSON-файл не пересоздаётся зря).
2. **Кодировка**: `data.decode("utf-8-sig")` → `"utf-8"`; при `UnicodeDecodeError` — `data.decode("cp1251")` → `"cp1251"`; если и это не удалось (байты вроде 0x98) — `UnknownFormatError`. Текст отдаётся в `csv.reader(io.StringIO(text, newline=""))`. Альтернатива (`open(..., encoding=...)` построчно) отвергнута: нужна проверка файла целиком до разбора.
3. **Нумерация строк**: `line_no` записи = `reader.line_num` перед чтением следующей записи + 1 (номер строки, где запись начинается); так выполняются правила `StatementError` для пустых строк и многострочных кавычек. `csv.Error` при чтении записи трактуется как ошибка этой строки.
4. **Заголовок и формат**: первая запись файла; имена нормализуются `strip().casefold()`. Для каждого формата — свой разделитель (`,` для nova, `;` для «Сферы»), набор обязательных колонок и карта «колонка → индекс». `nova` — точные имена (поведение как раньше), «Сфера» — без регистра/краевых пробелов. Формат подходит, если все обязательные колонки найдены ровно по одному разу. Подошли ≥2 формата (например, есть и «Сумма», и «Приход/Расход») или ни одного → `UnknownFormatError`. `detect_format` и `import_statement` используют одну функцию-разборщик заголовка. Явный `fmt`: проверяется только он, неизвестное значение или несовпадение → `UnknownFormatError`. Для `UnknownFormatError` непустого файла `line_no=1` (этого требует существующий тест `import_csv`), для пустого файла и ошибки декодирования — `None`.
5. **Мусорные строки**: запись, где все поля после `strip()` пусты (включая `[]`), пропускается до любой другой проверки.
6. **Недостаток полей**: если в строке нет поля с индексом хотя бы одной обязательной колонки — ошибка «not enough fields» (как раньше для nova). Лишние поля в конце игнорируются.
7. **Суммы «Сферы»**: регулярное выражение с `re.ASCII`: `[+-]?(\d{1,3}([  ]\d{3})+|\d+)(,\d{1,2})?`, после `strip()`. Запятая → точка, затем `Decimal` и `to_money`. Для `sfera_split` знак запрещён, значение `0` = пусто; ровно одна заполненная колонка. Даты — `[0-9]{2}\.[0-9]{2}\.[0-9]{4}` + `dt.date`. Ошибки `Transaction` (`ValidationError`) превращаются в ошибку строки с текстом исключения. Парсер сумм «Сферы» живёт в `importer.py`; `models.parse_amount` не меняется (nova его использует как раньше).
8. **Дедупликация**: `Counter` по ключу `(date, amount, normalize_description(description))` строится из `store.all()` один раз до разбора. Для каждой валидной строки по порядку файла: если счётчик ключа > 0 — уменьшить и посчитать дубль, иначе добавить. Добавленные в этом же файле строки в счётчик не попадают (идентичные строки одного файла — не дубли). `normalize_description` = обёртка над `rules.normalize_text` (единственное место определения сравнения — не копируем логику).
9. **Категоризация и время**: `imported_at = clock.now()` берётся один раз; категория применяется к недублям через `dataclasses.replace`, как в текущем коде.
10. **`import_csv`**: `import_statement(path, store, fmt="nova", strict=True, categorizer=..., clock=...).added`. Исключения не переоборачиваются. Ошибки ввода-вывода (`OSError` при чтении файла) пробрасываются как раньше.
11. **Ошибки**: `UnknownFormatError(StatementError)`; `StatementRowError(StatementError)` с обязательным `line_no` (keyword-only аргумент передаётся в базовый конструктор). `RowError.message` — «голое» сообщение без префикса `line N:`, `StatementRowError` строится из того же сообщения.

## Допущения (в тикете не определено)

- Заголовок ищется в первой записи файла; пустые строки перед ним → формат не распознан.
- Одновременное совпадение заголовка с `sfera` и `sfera_split`, а также дубль нужной колонки — `UnknownFormatError`.
- Колонки `nova` ищутся по точным именам; регистронезависимость относится только к «Сфере».
- Строка со слишком малым числом полей — ошибка строки, а не «пусто».
- Файл, не декодируемый ни как UTF-8, ни как cp1251, — `UnknownFormatError`.
- Группы тысяч — ровно по три цифры; другие позиции пробелов — ошибка строки. Неразрывный пробел U+202F не принимается.
- Нулевая сумма в `sfera` — ошибка строки (`Transaction` запрещает ноль).

## Risks / Trade-offs

- [Весь файл читается в память] → выписки небольшие; взамен простая атомарность.
- [Строгий разбор сумм может отвергнуть экзотичную, но «живую» запись] → такие строки видны в `errors` с номером; угадывание запрещено тикетом.
- [Изменение поведения `import_csv`/CLI: повторный импорт возвращает 0] → это целевое поведение тикета; существующие тесты проверяются прогоном.
- [Ключ дубля по нормализованному описанию склеивает «Кофе» и «кофе»] → задано тикетом.

## Migration Plan

Миграции данных нет. Откат — возврат старой реализации `import_csv` (хранилища и формат JSON не меняются).
