## Why

SHOP-412. Маркетинг запускает летнюю кампанию с промокодами, а скидки сейчас вручную делает поддержка, из-за чего суммы расходятся с чеками. Нужны промокоды, которые передаются при расчёте и оформлении заказа, а скидка честно отражается в итогах и построчно (бухгалтерия считает налог по строкам).

## What Changes

- Новый модуль `shop/promo.py`: `DiscountKind` (`PERCENT`, `FIXED`), `PromoCode` (frozen dataclass с инвариантами в `__post_init__`), `PromoRegistry(clock)` с `add`, `resolve`, `uses`. Реестр сам проверяет существование, срок действия `[starts_at, expires_at)` и лимит использований; время берёт только из внедрённых часов.
- `shop/errors.py`: `PromoError(ShopError)` и три независимых наследника `UnknownPromoCodeError`, `PromoExpiredError`, `PromoConditionsError`.
- `shop/pricing.py`: `calculate_total(cart, shipping=None, tax=None, *, promo=None)`; проверяет только условия заказа (минимальная сумма, наличие участвующих товаров), раскладывает скидку по строкам (метод наибольшего остатка, как в учёте), считает налог строки с суммы после скидки. Новые поля `LineTotal.discount` и `OrderTotal.discount`; `total = subtotal - discount + shipping + tax`.
- Порог бесплатной доставки сравнивается с суммой товаров **после** скидки (поправка О. Смирновой от 14.10); стоимость доставки скидка не уменьшает.
- `shop/orders.py`: `OrderService(..., promos=None)`, `quote(cart, promo_code=None)`, `place_order(cart, promo_code=None)`, `Order.promo_code`. Использование засчитывается только при успешном оформлении заказа; `cancel` возвращает использование (счётчик −1) (UPD А. Лебедевой от 14.10).
- Пустой или пробельный `promo_code` в `quote`/`place_order` означает «без кода»; `resolve("")` — неизвестный код.
- Код нормализуется как другие вводимые людьми коды (`normalize_key`: обрезка пробелов, верхний регистр) при создании `PromoCode` и при любом поиске.

Не меняется: вызовы без промокода (`calculate_total(cart)`, `calculate_total(cart, shipping, tax)`, `quote(cart)`, `place_order(cart)`) дают прежние суммы; `shop/cli.py`, `shop/reports.py` и существующие тесты не трогаем.

## Capabilities

### New Capabilities
- `promo-codes`: модель промокода, реестр (нормализация, срок, лимит, учёт использований), иерархия ошибок.
- `promo-pricing`: применение промокода в расчёте итогов: участвующие товары, процент/фикс, условия заказа, построчная раскладка, налог, доставка.
- `promo-orders`: промокод в `quote`/`place_order`/`cancel`: порядок проверок, учёт и возврат использований, `Order.promo_code`.

### Modified Capabilities

(нет: в `openspec/specs/` пока нет спецификаций; поведение без промокода сохраняется и зафиксировано как требование совместимости в новых спецификациях)

## Impact

- Код: `shop/promo.py` (новый), `shop/errors.py`, `shop/pricing.py`, `shop/orders.py`, экспорты в `shop/__init__.py`. Новые тесты — отдельными файлами в `tests/`.
- Публичный API: только расширение (необязательные параметры и поля со значениями по умолчанию в конце); `OrderTotal`/`LineTotal`/`Order` остаются конструируемыми по-старому.
- Зависимости: новых нет (только стандартная библиотека).
- README: правила расчёта дополняются описанием скидок (в рамках реализации).

## Допущения

Приняты без уточнения (пользователь недоступен); обоснование в `design.md`:
- Реестр получает дополнительные методы `consume(code)` и `release(code)` для учёта использований (заданный API дополняется, не меняется).
- `uses(code)` для неизвестного кода — `UnknownPromoCodeError`.
- `LineTotal.amount` и `OrderTotal.subtotal` остаются суммами до скидки.
- Пустая корзина даёт `EmptyCartError` раньше любых проверок промокода.
- Фиксированная и минимальная суммы — не более двух знаков после запятой, иначе `ValidationError`.
