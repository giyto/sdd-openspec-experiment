## Context

Импорт живёт в `ledger/importer.py`: `import_statement` делает два прохода (разбор строк, затем дедупликация
и одна запись через `store.add_many`). Сейчас строгий режим бросает `StatementRowError` сразу на первой
ошибке внутри `_record_error`. Суммы `sfera` разбираются регуляркой `_SFERA_UNSIGNED_AMOUNT` только с запятой;
`sfera_split` считает нулевую колонку пустой, и строка с нулями в обеих колонках даёт ошибку. Описание
обрезается через `strip()`. `RowError` и `ImportResult` — frozen-датаклассы. `StatementRowError` в
`ledger/errors.py` несёт только `line_no`. См. proposal.md — Why; требования — specs/statement-import/spec.md.

Ограничения: только стандартная библиотека; `ledger/cli.py`, `ledger/reports.py` не трогаем; `Transaction`,
хранилища и `Categorizer` не меняем; `ledger/errors.py` не импортирует `ledger.importer` во время выполнения
(цикл импорта).

## Goals / Non-Goals

**Goals:**
- Строгий режим собирает все ошибки строк файла и возвращает их списком в `StatementRowError.errors`.
- Превью `dry_run` использует тот же путь, что и реальный импорт, и отличается только последним шагом записи.
- `raw` содержит запись из файла с физическими строками, соединёнными через `\n`.
- Суммы `sfera` принимают точку и запятую; служебные нулевые строки `sfera_split` пропускаются.

**Non-Goals:**
- Не меняем `ledger/cli.py` (вывод ошибок строк в CLI остаётся как есть).
- Не меняем `Transaction`, формат JSON-хранилища и `Categorizer`.
- Не меняем разбор `nova`, кроме нормализации описания (см. Decisions).
- Не восстанавливаем разбор после `csv.Error` (как и раньше).

## Decisions

**Сбор ошибок вместо немедленного `raise`.** `_record_error` убираем: цикл разбора всегда добавляет
`RowError` в список. После цикла, если `strict` и ошибки есть, бросаем `StatementRowError(errors[0].message,
line_no=errors[0].line_no, errors=errors)`. Запись до этого момента не происходит, поэтому атомарность
не меняется. Альтернатива — собирать ошибки и продолжать, но бросать в конце из `import_csv` — отвергнута:
`import_csv` и `import_statement` должны вести себя одинаково.

**`StatementRowError.errors` без импорта `importer`.** `errors.py` объявляет `errors` как `list[RowError]`
через `TYPE_CHECKING`-импорт из `ledger.importer`; в рантайме импорта нет. Конструктор принимает
`errors: Iterable[...] | None = None` и сохраняет `list(errors or [])`, поэтому старые вызовы
`StatementRowError(message, line_no=...)` продолжают работать (с пустым списком).

**Сумма: точка или запятая, одна регулярка.** `_SFERA_UNSIGNED_AMOUNT` становится
`(\d{1,3}(?:[  ]\d{3})+|\d+)([,.]\d{1,2})?`. Один разделитель в группе делает смесь
`1 234,5.6` и `1.234,56` несовпадением, то есть ошибкой строки. Перед `Decimal` разделители тысяч
удаляются, запятая заменяется точкой. Регулярка по-прежнему отвергает `1.234` (три знака после точки)
и `-10.555`.

**Служебные строки `sfera_split`.** `_parse_split_column` возвращает `Decimal` для любого числового значения
(включая ноль) и `None` для пустой ячейки. Затем: оба нуля → парсер возвращает `None`, и цикл разбора
пропускает строку без дубликата и без записи; оба пустые, либо ноль с пустой → ошибка; оба ненулевых → ошибка.
Чтобы это выразить, `_Format.parse` может вернуть `None` («пропустить»), тип поля меняется на
`Callable[..., tuple[...] | None]`. Знак в колонке остаётся ошибкой, в том числе `-0,00`.

**Описание.** Одна функция `_clean_description(text)`: `re.sub(r"\s+", " ", text).strip()` (без `re.ASCII`,
чтобы NBSP и прочие Unicode-пробелы считались пробелами). Применяется во всех трёх парсерах вместо `.strip()`.
Для `nova` это тоже меняет сохраняемое описание; это следует из формулировки «при импорте» в задаче.
Сравнение дублей не меняется: оно по-прежнему идёт через `normalize_description`.

**`raw`.** Физические строки берутся через `io.StringIO(text, newline="").readlines()`: при `newline=""`
разделителями являются только `\n`, `\r` и `\r\n`, в отличие от `str.splitlines`, который режет и по `\x0c`,
`\x1c`, ` `. Запись занимает физические строки с `start` по `reader.line_num` (включительно). Текст
склеивается, `\r\n` и `\r` заменяются на `\n`, один хвостовой `\n` убирается (`str.removesuffix`). BOM не
попадает в `raw`: он снимается при декодировании `utf-8-sig`, а строка 1 — заголовок, который не порождает
`RowError`. Для `csv.Error` `raw` строится так же, до `reader.line_num` после ошибки.

**`dry_run` и `transactions`.** Общий путь: дедупликация и категоризация одинаковы. Если `to_add` не пуст и
`dry_run` равен `False`, вызывается `store.add_many(to_add)`, и `transactions` берётся из его результата
(с `id`). При `dry_run` `transactions = to_add` (`id` равен `None`). Поле `ImportResult.transactions`
имеет тип `list[Transaction]` с `field(default_factory=list)`, как в задаче; `ImportResult` остаётся frozen.

**Допущение: `\s` и Unicode.** Пробельные символы — то, что возвращает `\s` для `str` (включая NBSP, табы,
переводы строк). Символы нулевой ширины (например, U+200B) пробелами не считаются.

**Тесты.** Существующие тесты в `tests/test_importer.py` меняются только там, где они фиксируют старое
поведение пунктов 1–4: точка в сумме (`1 234.56` и тест на `Decimal`), нули в обеих колонках `sfera_split`,
сохранённое описание с кратными пробелами, ожидание первой ошибки в строгом режиме. Тесты `tests/test_cli.py`
не меняются. Это уточнение к задаче: «существующие тесты не трогаем» понимаем как «не трогаем тесты, которые
не проверяют пункты 1–4».

## Risks / Trade-offs

- **`csv.Error` останавливает разбор** → строки после ошибки не попадают ни в `errors`, ни в `added`, и
  равенство `added + duplicates + len(errors) == строк` для такого файла не выполняется. Это прежнее ограничение;
  прежнее поведение, его сохраняем. Mitigation: `raw` и `line_no` ошибки `csv` показывают точку остановки; тест на `csv.Error` фиксирует поведение.
- **Строгий режим теперь разбирает весь файл** → на больших файлах дольше, но памяти больше не требуется
  (списки и так строятся). Риска для личных выписок нет.
- **Служебная строка `0,00;0,00` пропускается молча** → если банк начнёт присылать нули как настоящие
  операции, они будут терять учёт. Mitigation: правило описано в spec и покрыто тестом; при необходимости
  правка одной ветки.
- **Описание коллапсируется и для `nova`** → сохранённые описания старых импортов не меняются (дедупликация
  по нормализованной форме не зависит от этого), но новые импорты дадут другой текст при кратных пробелах.
  Mitigation: в отчёт вынесено как Decision выше.
- **`dry_run` и реальный импорт расходятся, если между ними меняется хранилище** → превью считается по
  состоянию на момент вызова; это ожидаемо, цифры совпадают при том же состоянии (проверяется тестом).
- **`ImportResult.transactions` — list внутри frozen-датакласса** → объект нельзя хешировать; `ImportResult`
  и раньше не использовался как ключ. Риска нет.

## Migration Plan

Миграции данных нет: JSON-хранилище не меняется. Откат — revert коммита. Вызывающий код, который ловит
`StatementRowError` и смотрит на `line_no`, работает без изменений; код, который ожидал частичного импорта
в строгом режиме, уже был изменён в LEDGER-58.

## Implementation notes

- В `_parse_sfera_split` дата проверяется раньше правила служебной строки: служебная строка с неверной датой — ошибка строки, а не молча пропущенная строка.
- Тест `test_stored_description_is_trimmed_not_normalized` переименован в `test_stored_description_is_trimmed_and_collapsed`: он теперь проверяет схлопывание пробелов, а не его отсутствие.
