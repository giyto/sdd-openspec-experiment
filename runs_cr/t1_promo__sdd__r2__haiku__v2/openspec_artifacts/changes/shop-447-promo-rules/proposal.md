## Why

После летней кампании (SHOP-447) финансы увидели дорогие сценарии: фиксированные коды брали на мелкие
заказы, а возврат использования при отмене позволял гонять один лимитированный код по кругу. Для
осенней кампании маркетингу нужны два новых ограничения (потолок процентной скидки и лимит на клиента)
и промокод на бесплатную доставку. Одновременно пересматриваются правила, принятые летом: порог
бесплатной доставки, потолок фиксированной скидки, возврат использования при отмене и раскладка копеек.

## What Changes

- **BREAKING** Порог бесплатной доставки снова сравнивается с суммой товаров **до** скидки
  (отменяется правило «после скидки» из летней кампании).
- **BREAKING** Фиксированная скидка не может превышать 50 % суммы участвующих строк (доля считается и
  округляется до копеек как денежная величина). Сумма скидки ограничивается потолком, ошибка не возникает.
  Поправка маркетинга от 22.10: потолок 50 %, а не 30 %.
- **BREAKING** Использование промокода возвращается при отмене только если заказ отменён строго раньше
  чем через 24 часа после оформления (по часам сервиса заказов). Позже использование сгорает.
- **BREAKING** Раскладка копеек: при равных остатках лишняя копейка получает строка с большей суммой,
  и только при равенстве сумм — строка, которая раньше в корзине. Остаток по-прежнему решает первым.
- Новый вид промокода `DiscountKind.FREE_SHIPPING`: не даёт скидки на товары, обнуляет стоимость
  доставки; `value` должен быть `Decimal("0")`.
- Новое поле `OrderTotal.shipping_discount` (сумма, на которую уменьшена доставка; `0.00`, если экономить
  было нечего или код другого вида).
- Потолок процентной скидки `PromoCode.max_discount`: допустим только для `PERCENT`, должен быть больше нуля.
- Лимит на клиента `PromoCode.max_uses_per_customer` (`None` — без лимита, иначе не меньше 1). `quote`,
  `place_order` принимают `customer_id` (keyword-only), заказ хранит его в `Order.customer_id`;
  `PromoRegistry.resolve` и `PromoRegistry.uses` принимают `customer_id`. Код с лимитом на клиента без
  `customer_id` не применяется (`PromoConditionsError`).
- Существующие вызовы без новых параметров продолжают работать и дают те же суммы, кроме случаев,
  явно перечисленных выше (порог доставки, потолок фиксированной скидки, раскладка при равных остатках).

## Capabilities

### New Capabilities
- Нет.

### Modified Capabilities
- `promo-codes`: виды промокодов (добавляется `FREE_SHIPPING`), потолок скидки и лимит на клиента,
  правила доставки и порога, потолок фиксированной скидки, раскладка копеек, условие возврата использования
  при отмене, передача `customer_id` при расчёте и оформлении.

## Impact

- Код: `shop/promo.py` (новый вид, `max_discount`, `max_uses_per_customer`, учёт по клиенту),
  `shop/pricing.py` (расчёт скидки, потолки, раскладка, порог доставки, `shipping_discount`),
  `shop/orders.py` (`customer_id`, окно 24 часа при отмене), `shop/errors.py` — без изменений.
- API: новые необязательные параметры и поля с значениями по умолчанию; поведение изменяется только
  в перечисленных выше правилах.
- Тесты: новые тесты в `tests/`; существующие тесты не меняются, за одним исключением, описанным в design.md
  (тест летнего правила порога доставки в `tests/test_promo_pricing.py`).
- Не затрагиваются: `shop/cli.py`, `shop/reports.py`, HTTP-слой (другой репозиторий). Новых зависимостей нет.
