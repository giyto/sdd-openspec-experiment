## Context

Мотивация — `proposal.md`, требования — дельта `specs/statement-import/spec.md`. `import_statement` читает файл целиком, разбирает все строки в память и пишет одним `add_many` (он возвращает сохранённые транзакции с `id`). Описания сравниваются через `rules.normalize_text`. `csv.reader` не отдаёт исходный текст записи, только поля и `line_num`.

## Goals / Non-Goals

**Goals:** правки только в `ledger/importer.py` и `ledger/errors.py`; сигнатуры, порядок прежних полей `ImportResult` и `import_csv` сохраняются; результат `dry_run` строится тем же кодом, что и реальный импорт.

**Non-Goals:** `cli.py`, `reports.py`, хранилища и модели; новые зависимости; точка как разделитель тысяч.

## Decisions

1. **Суммы «Сферы»**: в регулярном выражении дробная часть через `[,.]` (1–2 цифры), тысячи — только пробел/U+00A0. Поэтому `1.234,56`, `1,234.56` и `1.234` отклоняются сами. Альтернатива (точка как разделитель тысяч) отвергнута: `1.234` неоднозначно.
2. **Служебные строки `sfera_split`**: до обычного разбора суммы обе колонки разбираются как беззнаковые суммы; если обе непустые и обе равны нулю — запись пропускается (как «мусор»), до проверки даты и описания. Допущение: пропуск не зависит от даты и описания, потому что банк помечает такие операции нулями. Ноль + пустая колонка, `-0,00`, ноль + невалидное значение — ошибка строки, как раньше. Если не хватает полей до нужных индексов — «not enough fields», как раньше.
3. **Описание**: `" ".join(description.split())` для всех форматов в `_parse_record` (покрывает пробелы, табы, переводы строк, U+00A0). Пустой результат — ошибка через `Transaction`. Дедупликация не меняется.
4. **`raw`**: `csv.reader` получает построчный итератор по тексту (`io.StringIO(text, newline="")`), который запоминает строки, отданные для текущей записи. `raw` = эти строки без хвостового `\r\n`/`\n`/`\r`, соединённые `\n`. Номер начала записи — по-прежнему `line_num` предыдущей записи + 1. BOM снят ещё при декодировании; для cp1251 используется декодированный текст. Альтернатива (собирать запись из полей `csv.writer`) отвергнута: теряет исходное оформление. Допущение: одиночный `\r` внутри записи считается переводом строки (так считает `csv`).
5. **Строгий режим**: ошибки строк всегда копятся в списке. После разбора, если `strict` и список не пуст, бросается `StatementRowError(errors[0].message, line_no=errors[0].line_no)` с атрибутом `errors`. Конструктор получает необязательный аргумент `errors` (по умолчанию пустой список), старые вызовы работают. Исключение бросается до записи, так что атомарность сохраняется; то же в `dry_run`. Ошибки заголовка/формата бросаются сразу, как раньше.
6. **`dry_run`**: после дедупликации и категоризации при `dry_run` вызов `add_many` пропускается, `transactions` = собранные транзакции (`id=None`). Иначе `transactions = store.add_many(new)`; при пустом `new` запись не выполняется и `transactions=[]`. Счётчики считает общий код, поэтому цифры превью совпадают с реальным импортом.
7. **Типы**: `RowError.raw: str = ""`; `ImportResult.transactions` — последнее поле, `default_factory=list`. `import_csv` не меняется.
8. **Тесты**: в `tests/test_import_statement.py` обновить тесты старого поведения пп. 1–4, добавить новые. Остальные файлы тестов не трогаем (требование «существующие тесты не трогаем» из LEDGER-58 действует, кроме явно разрешённого обновления тестов пп. 1–4).

## Risks / Trade-offs

- [Сохранённые описания меняются, в том числе через `import_csv`] → отмечено в спецификации как BREAKING; на дедупликацию не влияет.
- [Пропуск нулевых строк может скрыть реальные ошибки] → только при явных нулях в обеих колонках, по уточнению аналитика.
- [Файл и список ошибок целиком в памяти] → выписки малы.

## Решения при реализации

- `test_junk_rows_and_line_numbers` сравнивал `RowError(5, message)` целиком; теперь `raw` заполняется, поэтому ожидание дополнено `raw` (правка в том же файле `tests/test_import_statement.py`).
- В `ledger/errors.py` `errors` типизирован как `list[Any]`, чтобы не импортировать `RowError` (нет циклического импорта).
