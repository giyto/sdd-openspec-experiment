## Why

Итоги летней кампании (SHOP-447) показали две дыры: фиксированные коды выгодно брали на мелкие заказы, а возврат использования при любой отмене позволял гонять один лимитированный код по кругу. Для осенней кампании маркетингу нужны промокод на бесплатную доставку, потолок процентной скидки и лимит использований на клиента.

## What Changes

Правки действующих правил:
- **BREAKING** Порог бесплатной доставки снова сравнивается с суммой товаров **до скидки** (`subtotal`); летнее правило «после скидки» отменяется.
- **BREAKING** Фиксированная скидка не больше **50 %** суммы участвующих товаров (доля считается и округляется через `quantize_money`, `ROUND_HALF_UP`). В тикете сначала стояло 30 %, но поправка маркетинга от 22.10 (согласовано с финансами) заменяет число на 50 %.
- **BREAKING** При отмене заказа использование промокода возвращается только если отмена произошла строго раньше чем через 24 часа после оформления (по часам `OrderService`); при ровно 24 часах и позже использование сгорает.
- **BREAKING** Раскладка лишних копеек по строкам (решение бухгалтерии): при равенстве отброшенных остатков копейку получает строка с большей суммой, при равенстве и сумм — строка, раньше стоящая в корзине.

Новое:
- `DiscountKind.FREE_SHIPPING`: скидки на товары нет, доставка обнуляется; `value` должно быть `Decimal("0")`, иначе `ValidationError`.
- `OrderTotal.shipping_discount` — сколько сэкономлено на доставке (`Decimal("0.00")`, если нечего экономить или код другого вида).
- `PromoCode.max_discount` — потолок процентной скидки (только `PERCENT`, `> 0`, иначе `ValidationError`).
- `PromoCode.max_uses_per_customer` — лимит на клиента (`None` или `>= 1`).
- `customer_id` в `PromoRegistry.resolve`/`uses`, в `OrderService.quote`/`place_order` (keyword-only), поле `Order.customer_id`. Код с лимитом на клиента без `customer_id` не применяется (`PromoConditionsError`), исчерпанный клиентом лимит — тоже.

Публичный API берётся из тикета дословно; старые вызовы продолжают работать.

### Modified Capabilities
- `promo-codes`: новые значение `FREE_SHIPPING` и поля `max_discount`, `max_uses_per_customer` с инвариантами; `resolve`/`uses` с `customer_id` и проверкой лимита на клиента.
- `promo-pricing`: потолок 50 % для `FIXED`, `max_discount` для `PERCENT`, новый порядок раздачи копеек, порог доставки по `subtotal`, `FREE_SHIPPING` и `OrderTotal.shipping_discount`.
- `promo-orders`: `customer_id` в `quote`/`place_order` и в `Order`, учёт использований по клиентам, возврат использования только при отмене в пределах 24 часов.

## Impact

- Код: меняются `shop/promo.py`, `shop/pricing.py`, `shop/orders.py`. `shop/errors.py` (иерархия ошибок), `shop/cli.py` и `shop/reports.py` не трогаем.
- API: только добавления (новые поля в конце, новые необязательные параметры); новых зависимостей нет.
- Тесты: новые тесты добавляются отдельно. Два существующих теста в `tests/test_pricing_promo.py` фиксируют отменяемые правила и неизбежно расходятся с тикетом (`test_fixed_capped` — фикс 5000 на 1200 теперь даёт 600.00; `test_shipping_threshold_after_discount` — порог по `subtotal`). Это конфликт требований тикета («существующие тесты не меняем») с самими отменяемыми правилами; см. допущения в `design.md`.
