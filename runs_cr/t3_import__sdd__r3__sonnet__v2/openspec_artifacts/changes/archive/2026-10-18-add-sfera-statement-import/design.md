## Context

Сейчас `ledger/importer.py` содержит только `import_csv` для «Новы»: читает UTF-8, на первой плохой строке бросает `StatementError`, но уже записанные через `store.add` строки остаются. Дедупликации нет. Хранилище даёт атомарный `add_many` (одна запись на диск). Сравнение описаний уже есть: `rules.normalize_text`. Мотивация — см. proposal.md; требования — specs/statement-import/spec.md.

## Goals / Non-Goals

**Goals:**
- Один конвейер для трёх форматов: прочитать байты → декодировать → найти заголовок → разобрать строки → дедуплицировать → одна запись в хранилище.
- `import_csv` — тонкая обёртка без собственной логики.

**Non-Goals:**
- Изменения `cli.py`, `reports.py`, `Transaction`, хранилищ, `Categorizer`.
- Обработка `OSError` при открытии файла (остаётся как в текущем коде) и локалезависимые форматы сумм сверх описанных.

## Decisions

- **Весь файл читается в память** (`Path.read_bytes()`), декодируется `utf-8-sig`, при `UnicodeDecodeError` — `cp1251`; если и он падает (байты вне таблицы) — `StatementError` без `line_no`. Так «читается целиком как UTF-8» проверяется однозначно. Альтернатива — потоковое чтение: сложнее, выигрыша для выписок нет.
- **Парсинг через `csv.reader`** по `io.StringIO(text, newline="")` с разделителем формата. Номер строки записи = `reader.line_num` предыдущей записи + 1 (то есть строка начала, учитывает пустые и многострочные записи). `DictReader` не используем: нужен индекс колонок и контроль нехватки полей.
- **Заголовок** — первая не мусорная запись. Имена приводятся `strip().casefold()`; формат подходит, если все его колонки присутствуют ровно по одному разу. Для `fmt=None` перебираются три формата; ровно одно совпадение — формат, иначе `UnknownFormatError` (0 совпадений — «не распознан», >1 — «неоднозначен»). Разделитель зависит от формата, поэтому заголовок разбирается по очереди с каждым разделителем (`,` и `;`). Правило case/strip применяется и к «Нове» (допущение, см. ниже). `UnknownFormatError.line_no` = номер строки заголовка, для пустого файла `None` (так остаётся истинным существующий тест `line_no == 1`).
- **Мусорная строка** — запись, где `all(not f.strip() for f in row)` (пустая запись `[]` тоже). Проверяется до разбора, в том числе до заголовка.
- **Нехватка полей**: запись короче, чем индекс самой правой нужной колонки + 1, — ошибка строки («not enough fields»). Лишние поля справа игнорируются.
- **Сумма «Сферы»**: один regex `^([+-])?(\d{1,3}(?:[  ]\d{3})+|\d+)(?:,(\d{1,2}))?$` на значении после `strip()`, цифры только ASCII (`[0-9]`); результат собирается из строк в `Decimal` и проверяется `Transaction`. `float` не используется. Для `sfera_split` тот же разбор без допустимого знака; нулевое значение приравнивается к пустому до проверки «ровно одна колонка».
- **Дата «Сферы»**: regex `^[0-9]{2}\.[0-9]{2}\.[0-9]{4}$` + `dt.date(y, m, d)`. Для «Новы» остаётся `date.fromisoformat` и `models.parse_amount` (прежнее поведение).
- **Ошибка строки** — внутренняя `StatementRowError(message, line_no=...)`, ловится в цикле: в нестрогом режиме превращается в `RowError(line_no, exc.message)`, в строгом — пробрасывается. `ValidationError` из `Transaction` оборачивается так же.
- **Дедупликация**: до цикла строится `Counter` ключей `(date, amount, normalize_description(description))` по `store.all()`. Для каждой корректной строки: если счётчик ключа > 0 — уменьшить, `duplicates += 1`; иначе строка идёт в список новых. Внутрифайловые повторы не пополняют счётчик, поэтому два кофе остаются двумя. Это реализует «первые min(k, n) строк — дубли». Ошибочные строки счётчик не трогают.
- **`normalize_description`** делегирует `rules.normalize_text`, чтобы сравнение не расходилось с остальным проектом.
- **Запись**: новые транзакции (с категорией и общим `imported_at = clock.now()`) собираются в список и пишутся одним `store.add_many`; при пустом списке вызов пропускается, чтобы не создавать/перезаписывать JSON. В строгом режиме запись происходит только после полного прохода без ошибок — этим обеспечивается «ничего не попало ни в память, ни в JSON».
- **`import_csv`** = `import_statement(path, store, fmt="nova", strict=True, categorizer=..., clock=...).added`.
- **Иерархия ошибок**: `UnknownFormatError(StatementError)`, `StatementRowError(StatementError)` в `errors.py`; `RowError`, `ImportResult` — frozen dataclass в `importer.py`. `csv.Error` при чтении превращается в `StatementError` с номером строки.

## Допущения

- Заголовок — первая непустая запись, а не обязательно физическая строка 1; ведущий мусор допустим, нумерация остаётся физической.
- Нечувствительность заголовков к регистру и пробелам распространяется и на `nova`.
- Заголовок, подходящий сразу нескольким форматам, — `UnknownFormatError` при `fmt=None`.
- Положительные суммы принимаются как `1200`, `1200,5` (1–2 знака) и без дробной части.
- Для невалидного значения `fmt` — `UnknownFormatError`.
- Описание в `RowError.message` — текст без префикса «line N: ».

- Решение при реализации: номер строки в `UnknownFormatError`, когда заголовок не подошёл ни под один разделитель, — максимум из номеров первых не мусорных записей при разборе с `,` и `;` (мусорность зависит от разделителя). Для явно указанного, но неизвестного `fmt` — то же правило.

## Risks / Trade-offs

- [Поведение CLI `import` меняется (дубли пропускаются, BOM читается)] → это цель тикета, зафиксировано в proposal; существующие тесты `import_csv` остаются зелёными.
- [Строгая группировка тысяч отвергает `12 00,50`] → соответствует «ошибка строки, не угадываем».
- [Файл целиком в памяти] → выписки малы; для больших вариантов потребуется потоковая версия.
- [Декодирование «cp1251 как запасной» может принять не-cp1251 файл] → принято в ТЗ.
