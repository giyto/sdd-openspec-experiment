## Context

`ledger/importer.py` (LEDGER-58) разбирает файл конвейером «прочитать → найти заголовок → разобрать записи (`_parse_rows`, ошибки отдаются как значения) → дедупликация → один `add_many`». Хранилище `add_many` возвращает сохранённые транзакции с `id`. Мотивация и список изменений — в `proposal.md`, требования — в `specs/statement-import/spec.md`.

## Goals / Non-Goals

**Goals:**
- Реализовать пункты 1–7 задачи в существующем конвейере без смены публичного API сверх заданного.
- Сохранить единственную точку записи (`add_many`) и атомарность.

**Non-Goals:**
- Изменения `cli.py`, `reports.py`, хранилищ, `Transaction`, внешние зависимости.
- Изменение разбора `nova` (кроме нормализации описания).

## Decisions

1. **`RowError` переезжает в `ledger/errors.py`** (поля `line_no`, `message`, `raw=""`), `ledger.importer` его импортирует и тем самым реэкспортирует. Иначе `StatementRowError.errors: list[RowError]` даст циклический импорт. Альтернатива — отдельный тип в errors — отвергнута: в задаче `errors` именно `list[RowError]`.
2. **`StatementRowError.__init__(message, *, line_no=None, errors=None, raw="")`** — совместим с прежними вызовами. Если `errors` не задан и `line_no` не `None`, список — `[RowError(line_no, message, raw)]`, иначе `[]`. `raw` и `errors` не попадают в `str(exc)`. В строгом режиме импортёр собирает `RowError` всех ошибок и бросает `StatementRowError(first.message, line_no=first.line_no, errors=all)`.
3. **Сбор `raw`**: рядом с `text` один раз строится список физических строк разбиением по `\r\n|\r|\n` (`re.split`), так как `csv.reader` над `StringIO(newline="")` нумерует строки по тем же трём разделителям (`str.splitlines` не годится: режет по `\x0b`, ` ` и т. д.). `_parse_rows` отдаёт также диапазон строк записи: `start = line_num_до + 1`, `end = reader.line_num` после `next()`; `raw = "\n".join(lines[start-1:end])`. BOM снимается декодированием `utf-8-sig`, `\r` исчезает при разбиении. Для `csv.Error` `end` берётся из `reader.line_num` в момент ошибки (ограничить числом строк). `_parse_rows` оборачивает ошибку строки в `RowError` с `raw`; `_parse_row` остаётся как есть.
4. **Суммы «Сферы»**: в `_DIGITS` десятичная часть `([.,][0-9]{1,2})?`; запятая и точка одновременно регулярка не пропускает (есть только одна десятичная часть, тысячи — только пробелы), поэтому «обе» — ошибка без особого кода. Замена `,`→`.` перед `Decimal` остаётся. Тесты с `1 234.56` и подобные меняются на успешные.
5. **Пропуск служебных строк**: в ветке `sfera_split` после проверки числа полей и до разбора даты обе ячейки колонок проверяются; если обе непусты, корректны (`_UNSIGNED_AMOUNT`) и равны нулю, `_parse_row` возвращает `None`, а `_parse_rows` ничего не отдаёт. Если одна ячейка пуста или невалидна, действует прежняя логика ошибок. Дата и описание пропускаемой записи не проверяются (допущение). Для остальных строк меняется лишь порядок проверок; при нескольких ошибках в одной строке может измениться текст сообщения, но не `line_no`.
6. **Нормализация описания**: `" ".join(description.split())` в `_parse_row` вместо `.strip()` для всех форматов (`str.split()` без аргумента режет по всем юникодным пробельным символам, включая `\t`, `\n`, ` `). Дедупликация использует `normalize_description` как раньше, поэтому сравнение со старыми записями хранилища (с «грязными» пробелами) продолжает работать. Категоризатор вызывается после `_parse_row`, то есть видит нормализованное описание.
7. **Строгий режим**: убрать немедленный `raise` в цикле; ошибки всегда копятся в `errors`; после цикла при `strict and errors` бросается исключение (до `add_many`, до создания файла). Дубли и категоризацию можно считать как раньше — они не влияют на исход.
8. **`dry_run`**: после цикла `stored = store.add_many(to_add) if to_add and not dry_run else to_add`; `transactions = stored` (в `dry_run` это `to_add`, где `id=None`, так как исходные объекты создаются без `id`). Остальные шаги (включая единственный `clock.now()` и категоризатор) выполняются как обычно, так что `added`, `duplicates`, `errors` совпадают с настоящим импортом. `added = len(to_add)`.
9. **`ImportResult`**: новое поле `transactions` добавляется последним с `field(default_factory=list)`; позиционный порядок прежних полей не меняется. В лог добавляется пометка dry-run.
10. **Тесты**: в `tests/test_statement_import.py` обновить только проверки пунктов 1–4 (`1 234.56` из списка плохих сумм → в успешные; `0,00;0,00` из плохих строк split → пропуск; strict-тест → все ошибки; обрезка описания, если проверяется; сигнатура в `test_public_api_signatures`). Новые сценарии — в новом файле `tests/test_statement_import_v2.py`, чтобы не править остальные существующие тесты.

## Risks / Trade-offs

- [Тысячи через точку в европейском стиле (`1.234`) не поддерживаются: три знака после разделителя] → строка попадёт в ошибки, а не будет молча прочитана неверно.
- [Пропуск нулевых строк без проверки даты/описания может скрыть мусор] → осознанное допущение: служебные операции банка пропускаются целиком.
- [Строгий режим на больших файлах копит все ошибки] → выписки малы, файл и так читается целиком.
- [Описание теперь меняется при сохранении, ранее сохранённые остаются прежними] → дедупликация нормализует обе стороны, повторный импорт старого файла не создаёт дублей.
- [`RowError` меняет модуль определения] → реэкспорт сохраняет `ledger.importer.RowError`; `isinstance` и равенство работают.

## Допущения

- Нормализация описания применяется ко всем форматам, включая `nova` («при импорте» в тикете без ограничений), и до проверки на пустоту.
- «Нули явно в обеих колонках» — обе ячейки непусты и разбираются как корректная беззнаковая нулевая сумма (`0`, `0,00`, `0.00`); `+0,00`/`-0,00` — ошибка знака.
- Пропуск нулевой записи не проверяет дату и описание; проверки числа полей (`too many`/`not enough`) выполняются раньше.
- В `dry_run` с `strict=True` ошибки строк бросаются так же, как без `dry_run`.
- `raw` для csv-ошибки охватывает строки от начала записи до места остановки (для незакрытой кавычки — до конца файла).
- `StatementRowError` без явного `errors` формирует список из одной ошибки по `line_no`/`message`.
- Противоречие в «Рамках» («существующие тесты не трогаем» и «обновить тесты прежнего поведения») разрешено в пользу обновления только затронутых проверок.

- Реализация: `_is_zero_pair` проверяет обе колонки до даты; `RowError.raw` собирается в `_parse_rows`; новые тесты — `tests/test_statement_import_v2.py`.
