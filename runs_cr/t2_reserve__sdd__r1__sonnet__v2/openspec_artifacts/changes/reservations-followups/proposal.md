## Why

Резервы под заказы работают месяц (WH-231). Покупатели меняют корзину и оформляют возвраты, а поддержке не видно, какие резервы истекли. Часть прежних правил приходится изменить, часть — добавить.

## What Changes

- **BREAKING** Повторный `reserve` на заказ с активным резервом больше не ошибка, а замена: новый резерв (с новыми `created_at` и сроком) заменяет активный, товар заменяемого резерва при проверке наличия свободен. Журнал: `RESERVE_CANCEL` по старому, затем `RESERVE` по строкам нового. Подтверждённый заказ по-прежнему заменить нельзя (`DuplicateReservationError`).
- **BREAKING** `cancel` подтверждённого заказа — возврат: товар по всем строкам приходуется на те же склады, статус `CANCELLED`. Журнал: `RECEIVE` (`ref` = номер заказа) по каждой строке, затем `RESERVE_CANCEL`.
- **BREAKING** TTL по умолчанию — 20 минут вместо 15.
- Предельный срок: `expires_at <= created_at + MAX_RESERVATION_LIFETIME`. `reserve` с `ttl` больше предела — `ValidationError`; `extend` сверх предела ставит срок ровно на предел.
- Новые методы `Inventory`: `reservations(status=None)`, `availability(warehouse=None)`, `sweep_expired()`; новая модель `Availability`, константа `MAX_RESERVATION_LIFETIME`.
- `sweep_expired` пишет событие `RESERVE_EXPIRE` по каждому истёкшему резерву один раз; это единственное исключение из правила «истечение не пишется в журнал». Статусы и остатки не меняет. Вызывает его внешний планировщик.

### Расхождение в задаче и принятое решение

В описании предел — один час, но в обсуждении (Ольга Смирнова, 10.11) склад согласовал два часа: `MAX_RESERVATION_LIFETIME = timedelta(hours=2)`. Принято более позднее решение — **2 часа**.

### Допущения

- Существующие тесты не меняются (рамки задачи), но три группы из них кодируют отменяемые правила (TTL 15 минут, ошибка при дубликате активного резерва, запрет отмены подтверждённого). Они ожидаемо упадут; при реализации их не править, а перечислить в отчёте для решения владельцев.
- `cli.py` и `reports.py` не меняются; новых зависимостей нет.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `stock-reservations`: замена активного резерва, возврат по подтверждённому заказу, новый TTL по умолчанию и предельный срок, события `RESERVE_EXPIRE`, запросы списка резервов и доступности, `sweep_expired`.

## Impact

- Код: `warehouse/inventory.py`, `warehouse/reservations.py`, `warehouse/models.py`, `warehouse/storage.py` (признак «об истечении записано» в записи резерва), экспорты в `warehouse/__init__.py`.
- Не затрагиваются: `warehouse/cli.py`, `warehouse/reports.py`, формат строки журнала.
- Журнал получает новый тип события `RESERVE_EXPIRE`; потребителям журнала (внешняя выгрузка) стоит учесть его.
