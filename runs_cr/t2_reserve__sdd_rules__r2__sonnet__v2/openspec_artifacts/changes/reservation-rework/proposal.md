## Why

Резервы под заказы работают месяц (WH-231). Покупатели пересобирают корзину и оформляют возвраты, а поддержке не видно, какие резервы истекли. Часть прежних договорённостей (ошибка на повторный `reserve`, запрет отмены подтверждённого заказа, TTL 15 минут) больше не подходит, а для поддержки и склада не хватает запросов и фиксации истечения.

## What Changes

- **BREAKING** Повторный `reserve` на заказ с активным резервом больше не `DuplicateReservationError`, а замена: новый резерв (со своим `created_at` и сроком от момента замены) заменяет активный; товар заменяемого резерва при проверке наличия считается свободным. Журнал: `RESERVE_CANCEL` по старому, затем `RESERVE` по строкам нового. Подтверждённый заказ по-прежнему заменить нельзя (`DuplicateReservationError`).
- **BREAKING** `cancel` подтверждённого заказа — возврат вместо `ReservationStateError`: товар по всем строкам возвращается на те же склады, статус `CANCELLED`. Журнал: `RECEIVE` по каждой строке с `ref` = номер заказа, затем `RESERVE_CANCEL`.
- **BREAKING** `DEFAULT_RESERVATION_TTL` — 20 минут вместо 15.
- Предельный срок: `MAX_RESERVATION_LIFETIME = timedelta(hours=2)` (значение уточнено в обсуждении: склад согласовал два часа, а не час из текста задачи). `expires_at` не позже `created_at + MAX_RESERVATION_LIFETIME`. `reserve` с `ttl` больше предела — `ValidationError`; `extend` сверх предела ставит срок ровно на предел.
- Новая модель `Availability(warehouse, sku, on_hand, reserved, available)` в `warehouse/models.py`.
- Новые методы `Inventory`: `reservations(status=None)`, `availability(warehouse=None)`, `sweep_expired()`.
- `sweep_expired()` пишет по каждому истёкшему резерву, о котором ещё не писали, событие `RESERVE_EXPIRE` (`order`, `expires`) и возвращает `order_id`; статусы и остатки не меняет. Резерв, созданный заново для того же заказа, — отдельный резерв.

## Impact

- Код: `warehouse/models.py`, `warehouse/reservations.py`, `warehouse/inventory.py`, `warehouse/storage.py` (внутреннее хранение уже отданных, но не отмеченных истёкших резервов), `warehouse/__init__.py` — по необходимости.
- Не трогаем: `warehouse/cli.py`, `warehouse/reports.py`, существующие тесты, зависимости. Старый API (имена, сигнатуры) сохраняется; меняется только поведение, перечисленное выше.
- Новые события журнала: `RESERVE_EXPIRE`; существующий формат строки журнала не меняется. Отчёты и CLI типы событий резервов игнорируют.
- Существующие тесты резервов, проверяющие дубликат активного резерва, 15 минут и запрет отмены подтверждённого, противоречат новым правилам; их обновление выходит за рамки «существующие тесты не меняем» и отмечено в design.md как риск.
