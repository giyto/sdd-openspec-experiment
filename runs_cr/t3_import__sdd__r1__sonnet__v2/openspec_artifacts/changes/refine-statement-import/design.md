## Context

Мотивация — `proposal.md`, требования — `specs/statement-import/spec.md`. Сейчас `importer.py`:
разбирает файл целиком, но в строгом режиме бросает `StatementRowError` на первой ошибке;
`RowError` и `ImportResult` определены в `importer.py`; сумма «Сферы» разбирается регуляркой только
с запятой; описание сохраняется как `strip()`; `add_many` возвращает сохранённые транзакции с `id`.
`errors.py` не должен импортировать `importer` (а `importer` импортирует `errors`).

## Goals / Non-Goals

**Goals:** реализовать пункты 1–7 тикета без изменения публичных сигнатур, кроме новых
необязательных аргументов и полей.

**Non-Goals:** `cli.py`, `reports.py`, хранилища, модели; новые зависимости; хранение `raw` или
формата в транзакции; изменение сравнения для дедупликации.

## Decisions

1. **`RowError` переезжает в `ledger/errors.py`**, из `importer.py` реэкспортируется
   (`from ledger.errors import RowError`), так что `from ledger.importer import RowError` и
   `isinstance` в существующих тестах продолжают работать. Альтернатива — `TYPE_CHECKING`-импорт в
   `errors.py` — оставляет `RowError` вне `errors.py`, но тип в аннотации `list[RowError]` без
   реальной зависимости хрупче. Поле `raw: str = ""` — последнее, с умолчанием: старые вызовы
   `RowError(line_no, message)` работают, равенство сравнивает и `raw`.
2. **`StatementRowError.__init__(message, *, line_no=None, errors=None)`**; `errors` по умолчанию
   `[]` (копия списка). В импорте: `StatementRowError(first.message, line_no=first.line_no,
   errors=errors)`. Иначе `str(exc)` останется прежним `line N: message`.
3. **Строгий режим = нестрогий разбор + бросок в конце.** Единый цикл всегда копит `errors`; после
   разбора `if strict and errors: raise`. Это же гарантирует, что до записи ничего не пишется и
   `dry_run` ведёт себя так же. Дедупликация и категоризация в этом случае выполняются зря, но
   дёшево; ради простоты не оптимизируем.
4. **Суммы:** одна регулярка с десятичным разделителем `[.,]`: `^([+-])?(целая)(?:[.,]([0-9]{1,2}))?$`.
   Строка с одновременно `.` и `,` не матчится → ошибка. `1.500`/`1,500` не матчится (3 цифры после
   разделителя; тысячи разделяются только пробелом/U+00A0) → ошибка, как и раньше для запятой.
   Сообщение об ошибке прежнее: `invalid amount '…'`.
5. **Пропуск служебных строк `sfera_split`.** Для каждой из колонок «Приход»/«Расход» считается
   состояние: `empty` (пусто/пробелы), `zero` (по грамматике без знака, значение 0), `value`
   (ненулевое), либо ошибка разбора. Если обе колонки — `zero`, строка пропускается до проверки даты
   и описания (`_parse_row` возвращает `None`). Иначе ровно один `value` и остальные `empty`/`zero`
   → транзакция; прочее → ошибка «exactly one of income/expense must be filled». Ошибка разбора
   любой колонки остаётся ошибкой строки (в т.ч. при нуле во второй), порядок: ошибка разбора суммы
   приоритетнее пропуска, пропуск приоритетнее даты/описания. Пропущенная строка не создаёт ни
   `RowError`, ни дубля, ни транзакции.
6. **Нормализация описания:** `" ".join(description.split())` в `_parse_row` для всех форматов.
   `str.split()` без аргумента режет по Unicode-пробелам (в т.ч. `\n`, `\t`, `\r`, U+00A0); регистр
   не трогается. Пустой результат отдаёт `ValidationError` из `Transaction` → ошибка строки.
   `normalize_description` (ключ дедупликации) не меняется.
7. **`raw`:** текст декодированного файла один раз делится на физические строки по
   `re.split(r"\r\n|\r|\n", text)` (то же правило, что у `csv`/`StringIO(newline="")`, поэтому
   нумерация совпадает с `line_num`; `splitlines()` не годится — режет по `\x0b`, `\x0c`, U+2028 и
   др.). `_records` дополнительно отдаёт номер последней физической строки записи
   (`reader.line_num` после `next()`); `raw = "\n".join(lines[start-1:end])`. Так не нужно
   «восстанавливать» запись из ячеек, кавычки и разделители сохраняются; BOM уже снят
   `utf-8-sig`, cp1251 уже декодирован, `\r` не попадает, перевода строки в конце нет. Для
   `csv.Error` конец записи — `reader.line_num` на момент ошибки (приближение, допущение ниже).
   `raw` заполняется для всех `RowError`, включая попавшие в `StatementRowError.errors`.
8. **`dry_run`:** единственное отличие — не вызывать `store.add_many`; `transactions = new`
   (`id=None`). Обычный режим: `transactions = store.add_many(new)` (с `id`), при пустом `new`
   `[]` и без обращения к хранилищу. `added = len(transactions)`. Так цифры превью совпадают с
   настоящим импортом по построению.
9. **`ImportResult.transactions: list[Transaction] = field(default_factory=list)`** — последним
   полем, существующие позиционные вызовы не ломаются.
10. **Тесты:** обновляются только тесты в `tests/test_statement_import.py`, ожидавшие прежнее
    поведение пп. 1–4; остальные файлы тестов не трогаются; добавляются новые тесты на пп. 5–7.

## Risks / Trade-offs

- [Точка теперь допустима, `1.234` с тремя цифрами могла означать тысячи] → остаётся ошибкой строки,
  не угадывается; тысячи в «Сфере» только через пробел.
- [Нормализация описания меняет значение, сохраняемое в хранилище] → ключ дедупликации не меняется
  (он и так сворачивал пробелы), поэтому повторный импорт старых записей даёт дубли как раньше;
  описания, ранее сохранённые с внутренними двойными пробелами, всё равно сравниваются корректно.
- [Строгий режим тратит работу на дедупликацию перед броском] → пренебрежимо для размеров выписок.
- [`raw` для `csv.Error` — приближение] → для редкого случая (например, незакрытая кавычка до конца
  файла) `raw` — от начала записи до последней прочитанной строки.

## Assumptions (неоднозначности ТЗ, решены автономно)

- «Любые последовательности пробельных символов» — Unicode-пробелы по `str.split()`, включая U+00A0.
- Нормализация описания применяется ко всем форматам, включая `nova` и `import_csv`, так как
  п. 3 говорит «при импорте» без оговорок.
- «Нули явно в обеих колонках» — любое нулевое значение по грамматике сумм (`0`, `0,0`, `0.00`),
  без знака. Нулевая колонка со знаком (`-0,00`) — ошибка строки.
- Пропуск строки с двумя нулями не зависит от корректности даты и описания.
- `dry_run` вместе с `strict` бросает `StatementRowError`, как обычный импорт; `UnknownFormatError`
  и ошибка кодировки тоже бросаются.
- В `dry_run` `imported_at` проставляется из `clock.now()` так же, как при реальном импорте;
  категории — от `categorizer`.
- Конфликт в «Рамках» («существующие тесты не трогаем» и «тесты прежнего поведения обновить»)
  разрешён так: обновляются только тесты, прямо фиксирующие изменённое поведение пп. 1–4.
- `README.md` не входит в запрет рамок, поэтому его раздел о «Сфере» и соглашение об описаниях
  обновляются.
- Экспорт `RowError` из `ledger/__init__.py` не добавляется.
