## Context

Требования — в `specs/statement-import/spec.md`, мотивация — в `proposal.md`. Сейчас
`ledger/importer.py` читает только «Нову» и вызывает `store.add` на каждую строку, поэтому ошибка
посреди файла оставляет частичную запись. `MemoryStore.add_many` атомарен (`JsonFileStore` пишет
файл до обновления памяти), но вызов с пустым списком всё равно пишет JSON. Сравнение описаний в
проекте — `rules.normalize_text` (README, «Соглашения»). Существующие тесты ждут для плохого
заголовка `StatementError` с `line_no == 1`, для плохой строки — `line_no == 3`.

## Goals / Non-Goals

**Goals:** один входной механизм для трёх форматов; полный разбор до записи; одна запись в хранилище.

**Non-Goals:** изменения CLI и отчётов, новые флаги CLI, хранение формата в транзакции, миграция
уже задвоенных данных, изменения `Transaction` и хранилищ.

## Decisions

1. **Двухфазный импорт: разобрать всё → записать одним `add_many`.** Фаза 1 читает файл, формирует
   список валидных `Transaction` и `errors`, считает дубли. Фаза 2: при `strict` и непустых
   `errors` — `StatementRowError` из первой ошибки (до записи); иначе один `add_many`, и только
   если список непуст. Альтернатива (`add` по одной строке с откатом) отвергнута: JSON-файл нельзя
   откатить без нового API хранилища.
2. **`normalize_description` делегирует `rules.normalize_text`** (тонкая обёртка, не копия логики),
   чтобы «как везде в проекте» не разошлось при правках. Ключ дубля:
   `(date, amount, normalize_description(description))`.
3. **Дедупликация по `Counter` ключей хранилища на момент старта.** Для каждой валидной строки в
   порядке файла: если счётчик ключа > 0 — уменьшить и посчитать дубль, иначе добавить. Это даёт
   ровно «первые min(k, n) — дубли» и не считает дублями строки внутри файла. Счётчик не
   пополняется добавляемыми строками. Строки с ошибками счётчик не трогают.
4. **Кодировка:** читаем байты; `decode("utf-8-sig")`, при `UnicodeDecodeError` — `decode("cp1251")`
   (если и он падает — `StatementError` без `line_no`). Текст отдаётся в `csv.reader` через
   `io.StringIO(text, newline="")`, чтобы переводы строк внутри кавычек сохранялись.
5. **Номера строк:** `csv.reader.line_num` — число прочитанных физических строк; номер начала
   записи = `line_num` до `next()` плюс 1. Пропускаемая запись: все ячейки после `strip()` пусты.
   Заголовок — первая непропускаемая запись.
6. **Определение формата:** имена заголовка (`strip().casefold()` для «Сферы»; точные для `nova`,
   как раньше) сравниваются с наборами нужных колонок. Совпавший формат должен быть ровно один,
   имена нужных колонок не повторяются. Индексы колонок берутся по имени. `detect_format` и
   `import_statement` используют общий внутренний разбор заголовка.
7. **Суммы «Сферы» — строгие регулярки, а не `Decimal` напрямую:** `Decimal("1.500")` проходит
   `to_money` (значение равно `1.50`), поэтому «не больше двух знаков» проверяется на тексте
   (`,\d{1,2}`), а не на значении. Тысячи: `\d{1,3}([  ]\d{3})+` либо `\d+`; только
   ASCII-цифры (`[0-9]`, не `\d` с Unicode). Результат (`Decimal`) передаётся в `Transaction`,
   нулевая сумма и пустое описание ловятся его `ValidationError`, который становится ошибкой
   строки. Для `nova` прежний путь: `parse_amount` и `date.fromisoformat`.
8. **`sfera_split`:** обе колонки парсятся той же грамматикой без знака; значение, равное нулю,
   считается пустым; должна быть ровно одна «заполненная».
9. **Ошибка → `RowError`:** разбор строки бросает внутренний `StatementError(line_no=…)`, верхний
   уровень превращает его в `RowError(line_no, message)` либо в `StatementRowError` (strict).
   `csv.Error` на записи трактуется как ошибка строки.
10. **`import_csv`** = `import_statement(path, store, fmt="nova", strict=True, categorizer=…, clock=…).added`.
11. **Новые исключения** в `errors.py`: `UnknownFormatError(StatementError)` и
    `StatementRowError(StatementError)`; конструктор унаследован: `(message, *, line_no=None)`.

## Risks / Trade-offs

- [Повторный `import_csv` теперь возвращает 0 вместо n] → осознанно (решение в обсуждении тикета);
  существующие тесты импортируют в пустое хранилище и не затронуты.
- [Файл целиком в памяти] → выписки малы; упрощает определение кодировки.
- [Строгость сумм отвергает «грязные» значения: U+202F, Unicode-минус] → попадают в `errors`, а не
  угадываются; расширять можно отдельным изменением.
- [Дубль определяется по значению, а не по идентичности] → так задано в ТЗ.

## Assumptions (неоднозначности ТЗ, решены автономно)

- Пропускаемые строки допускаются и перед заголовком; заголовок — первая непропускаемая запись.
- Для `nova` имена колонок остаются точными (как в текущем коде); регистронезависимость — только «Сфера».
- Заголовок, подходящий сразу двум форматам или с повторяющимися нужными колонками, — `UnknownFormatError`.
- Неизвестное значение `fmt` — `UnknownFormatError`.
- Строка короче заголовка — ошибка, только если не хватает нужных колонок; лишние поля игнорируются.
- Нулевое значение в `sfera_split` — любое число по грамматике, равное нулю (`0`, `0,0`, `0,00`).
- На одну строку — одна `RowError` (первая найденная проблема: дата, затем сумма, затем описание).
- Ошибки ввода-вывода (нет файла) не оборачиваются и ведут себя как раньше; файл, не
  декодируемый ни как UTF-8, ни как cp1251, — `StatementError` без `line_no`.
- В `ledger/__init__.py` новые исключения не экспортируются.
- Мусорной считается и запись из одних разделителей `,`/`;` и пробелов независимо от формата
  (иначе `;;;` в файле «Новы» и `,,` в файле «Сферы» ломали бы определение заголовка).
- Заголовок ищется отдельно для каждого разделителя (`,` для nova, `;` для sfera*); при
  нераспознанном заголовке `line_no` — наибольший из найденных номеров первой записи.
