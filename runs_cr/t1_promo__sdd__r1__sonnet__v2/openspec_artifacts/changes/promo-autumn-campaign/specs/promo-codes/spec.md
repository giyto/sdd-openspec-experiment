## MODIFIED Requirements

### Requirement: Валидация промокода
Промокод SHALL иметь непустой (после нормализации) код, вид скидки (процентная, фиксированная или бесплатная доставка) и значение. Значение процентной скидки MUST лежать в (0, 100]. Значение фиксированной скидки MUST быть больше 0 и иметь не более двух знаков после запятой. Значение промокода на бесплатную доставку MUST быть равно нулю. Минимальная сумма заказа MUST быть неотрицательной суммой в копейках (по умолчанию 0.00). `max_uses` MUST быть `None` (без лимита) либо целым числом не меньше 1. `max_uses_per_customer` MUST быть `None` (без лимита на клиента, по умолчанию) либо целым числом не меньше 1. `max_discount` MUST быть `None` (по умолчанию) либо суммой больше 0 не более чем с двумя знаками после запятой и допустим только у процентного промокода. Даты начала и окончания MUST быть aware-датами или `None`; если заданы обе, начало MUST быть раньше конца. Недопустимые данные SHALL приводить к `ValidationError`, а не к голому `ValueError`/`KeyError`.

#### Scenario: Процент вне диапазона
- **WHEN** создаётся процентный промокод со значением 0 или 100.01
- **THEN** выбрасывается `ValidationError`

#### Scenario: Сто процентов допустимы
- **WHEN** создаётся процентный промокод со значением 100
- **THEN** промокод создаётся

#### Scenario: Некорректный фиксированный номинал
- **WHEN** создаётся фиксированный промокод со значением 0, отрицательным значением или 10.005
- **THEN** выбрасывается `ValidationError`

#### Scenario: Некорректный лимит
- **WHEN** создаётся промокод с `max_uses` равным 0, отрицательным числом или `True`
- **THEN** выбрасывается `ValidationError`

#### Scenario: Некорректный интервал
- **WHEN** `starts_at` не раньше `expires_at`, либо одна из дат naive
- **THEN** выбрасывается `ValidationError`

#### Scenario: Пустой код
- **WHEN** создаётся промокод с кодом `""` или из одних пробелов
- **THEN** выбрасывается `ValidationError`

#### Scenario: Промокод на бесплатную доставку
- **WHEN** создаётся промокод вида бесплатной доставки со значением `Decimal("0")`
- **THEN** промокод создаётся

#### Scenario: Бесплатная доставка с ненулевым значением
- **WHEN** создаётся промокод вида бесплатной доставки со значением 5, 0.01 или -1
- **THEN** выбрасывается `ValidationError`

#### Scenario: Допустимый потолок процентной скидки
- **WHEN** создаётся процентный промокод с `max_discount` равным 500.00
- **THEN** промокод создаётся

#### Scenario: Некорректный потолок скидки
- **WHEN** создаётся процентный промокод с `max_discount` равным 0, -1, 10.005 или не `Decimal`
- **THEN** выбрасывается `ValidationError`

#### Scenario: Потолок у непроцентного промокода
- **WHEN** создаётся фиксированный промокод или промокод на бесплатную доставку с любым заданным `max_discount`
- **THEN** выбрасывается `ValidationError`

#### Scenario: Некорректный лимит на клиента
- **WHEN** создаётся промокод с `max_uses_per_customer` равным 0, отрицательным числом, `True` или нецелым
- **THEN** выбрасывается `ValidationError`

#### Scenario: Допустимый лимит на клиента
- **WHEN** создаётся промокод с `max_uses_per_customer` равным 1 или `None`
- **THEN** промокод создаётся

### Requirement: Порядок проверок при разрешении кода
`resolve(code, customer_id=None)` SHALL проверять по порядку: (1) код существует, иначе `UnknownPromoCodeError`; (2) код действует в текущий момент, иначе `PromoExpiredError`; (3) общий лимит не исчерпан, иначе `PromoConditionsError`; (4) для кода с `max_uses_per_customer`: `customer_id` передан и этот клиент использовал код меньше `max_uses_per_customer` раз, иначе `PromoConditionsError`. Текущее время SHALL браться только из часов, переданных реестру. Интервал действия полуоткрытый `[starts_at, expires_at)`; граница `None` — без ограничения. «Ещё не началось» и «уже закончилось» оба дают `PromoExpiredError`. `customer_id` — внутренний идентификатор учётной записи, он сравнивается как есть: без обрезки пробелов и без смены регистра. Для кода без `max_uses_per_customer` `customer_id` на разрешение не влияет. `customer_id`, который не строка и не `None`, SHALL приводить к `ValidationError`. Три исключения SHALL быть независимыми наследниками `PromoError` (ни одно не является наследником другого), а `PromoError` — наследником `ShopError`.

#### Scenario: Неизвестный код
- **WHEN** вызывается `resolve` с кодом, которого нет в реестре, в том числе с `""`
- **THEN** выбрасывается `UnknownPromoCodeError`

#### Scenario: Граница начала включительна
- **WHEN** текущее время равно `starts_at`
- **THEN** код разрешается

#### Scenario: Код ещё не начал действовать
- **WHEN** текущее время раньше `starts_at`
- **THEN** выбрасывается `PromoExpiredError`

#### Scenario: Граница окончания исключительна
- **WHEN** текущее время равно `expires_at`
- **THEN** выбрасывается `PromoExpiredError`

#### Scenario: Срок важнее лимита
- **WHEN** код одновременно просрочен и исчерпан по лимиту
- **THEN** выбрасывается `PromoExpiredError`

#### Scenario: Лимит исчерпан
- **WHEN** число использований кода равно `max_uses`
- **THEN** `resolve` выбрасывает `PromoConditionsError`

#### Scenario: Часы двигаются
- **WHEN** часы реестра переведены за `expires_at`
- **THEN** ранее разрешавшийся код выбрасывает `PromoExpiredError`

#### Scenario: Лимит на клиента без идентификатора
- **WHEN** у кода `max_uses_per_customer=1` и `resolve` вызван без `customer_id`
- **THEN** выбрасывается `PromoConditionsError`

#### Scenario: Клиент исчерпал свой лимит
- **WHEN** у кода `max_uses_per_customer=1` и клиент `u1` уже оформил заказ с этим кодом
- **THEN** `resolve(code, "u1")` выбрасывает `PromoConditionsError`, а `resolve(code, "u2")` разрешает код

#### Scenario: Идентификатор сравнивается как есть
- **WHEN** клиент `u1` исчерпал лимит, а код проверяется для `U1` или ` u1`
- **THEN** это другие клиенты, и код для них разрешается

#### Scenario: Срок важнее лимита на клиента
- **WHEN** код просрочен, а клиент исчерпал свой лимит
- **THEN** выбрасывается `PromoExpiredError`

#### Scenario: Идентификатор без лимита на клиента
- **WHEN** у кода нет `max_uses_per_customer` и `resolve` вызван с любым `customer_id` или без него
- **THEN** код разрешается, как и раньше

#### Scenario: Идентификатор неверного типа
- **WHEN** `resolve` вызван с `customer_id=123`
- **THEN** выбрасывается `ValidationError`

### Requirement: Счётчик использований
Реестр SHALL вести счётчик использований каждого кода, начиная с 0. `uses(code)` SHALL принимать код в любом регистре и с пробелами по краям и возвращать общее число использований; `uses(code, customer_id)` SHALL возвращать число использований кода этим клиентом (0, если клиент код не использовал). Для неизвестного кода выбрасывается `UnknownPromoCodeError`. Использования клиента считаются для любого кода, а не только для кодов с `max_uses_per_customer`. Общий счётчик MUST увеличиваться только при успешном оформлении заказа, счётчик клиента — при том же событии, если у заказа есть `customer_id`. Оба счётчика MUST уменьшаться на единицу при возврате использования (см. «Возврат использования при отмене» в `promo-orders`), но не могут стать отрицательными. `resolve`, `quote` и `calculate_total` счётчики не меняют.

#### Scenario: Новый код
- **WHEN** код только что добавлен
- **THEN** `uses` возвращает 0, в том числе `uses(code, "u1")`

#### Scenario: Разрешение не расходует лимит
- **WHEN** `resolve` вызывается несколько раз подряд
- **THEN** `uses` по-прежнему возвращает 0

#### Scenario: Счётчик клиента
- **WHEN** клиент `u1` дважды оформил заказ с кодом, клиент `u2` — один раз
- **THEN** `uses(code)` равно 3, `uses(code, "u1")` равно 2, `uses(code, "u2")` равно 1

#### Scenario: Заказ без клиента
- **WHEN** заказ с кодом оформлен без `customer_id`
- **THEN** общий счётчик увеличился на 1, счётчики клиентов не изменились
