## Why

Пользователи всё чаще приносят выписки банка «Сфера», а импорт умеет только «Нову». Текущий
импорт (`import_csv`) к тому же хрупкий: повторный импорт задваивает операции, кривая строка
роняет импорт на середине (часть строк уже записана), а файлы, сохранённые из Excel
(UTF-8 с BOM), и файлы в cp1251 не читаются. Нужен один вход, который сам определяет формат,
не задваивает операции и честно сообщает о строках, которые не смог разобрать.

## What Changes

- Новая функция `import_statement(path, store, *, fmt=None, strict=False, categorizer=None, clock=None)`
  возвращает `ImportResult` и принимает форматы `nova`, `sfera` и `sfera_split`.
- Формат определяется по заголовку (`detect_format`). Неизвестный заголовок, пустой файл или заголовок,
  не подходящий к явно указанному `fmt`, дают `UnknownFormatError` без записи в хранилище.
- Новый формат `sfera`: разделитель `;`, колонки `Дата;Сумма;Описание`, сумма со знаком или без него,
  тысячи через пробел (в том числе неразрывный U+00A0).
- Новый формат `sfera_split`: колонки `Дата;Описание;Приход;Расход`, суммы без знака, заполнена
  ровно одна из двух сумм.
- Колонки ищутся по названию без учёта регистра и пробелов по краям, порядок и лишние колонки не важны.
- Кодировка: UTF-8 (с BOM или без), если файл целиком читается как UTF-8; иначе cp1251.
- Пустые строки и строки из одних разделителей пропускаются везде и не считаются ни ошибкой, ни дублем.
- Дедупликация: транзакция из файла считается дублем, если в хранилище до импорта есть столько же
  транзакций с той же датой, суммой и нормализованным описанием (по количеству; дубли внутри файла
  дублями не считаются).
- Ошибки строк собираются в `ImportResult.errors` с `line_no`; импорт остальных строк продолжается.
  В режиме `strict=True` первая ошибка бросает `StatementRowError`, и в хранилище ничего не попадает.
- `import_csv` становится обёрткой над `import_statement` (формат `nova`, строгий режим). Сигнатура
  и возвращаемый `int` прежние; CLI не меняется.
- **Заметное изменение поведения:** повторный импорт той же выписки через `import_csv` больше не
  задваивает операции. Это запланированное исправление, не поломка API.

## Capabilities

### New Capabilities
- `statement-import`: импорт банковских выписок («Нова», «Сфера», «Сфера» с раздельными колонками)
  в хранилище транзакций: определение формата и кодировки, разбор строк, дедупликация с уже
  сохранёнными операциями, ошибки строк и строгий режим.

### Modified Capabilities
- Нет. В `openspec/specs/` пока нет утверждённых capability, поэтому существующие требования
  не меняются.

## Impact

- `ledger/importer.py`: новые `import_statement`, `detect_format`, `normalize_description`,
  `ImportResult`, `RowError`; `import_csv` переписывается как обёртка.
- `ledger/errors.py`: новые `UnknownFormatError` и `StatementRowError`, оба наследуют `StatementError`.
- Тесты: новые тесты для форматов и импорта; существующие тесты не меняются.
- `README.md`: раздел о поддерживаемых форматах выписок.
- Не затрагиваются: `ledger/cli.py`, `ledger/reports.py`, публичный API `Transaction`, хранилищ
  и `Categorizer`. Новых зависимостей нет, только стандартная библиотека.
