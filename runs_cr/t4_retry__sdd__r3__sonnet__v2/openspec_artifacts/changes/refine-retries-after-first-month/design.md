## Context

Повторы и dead-letter реализованы в `jobq/retry.py` (`RetryPolicy.delay_for`, `is_retryable`), `jobq/worker.py` (`_handle_failure`) и `jobq/queue.py` (`mark_dead_lettered`, `requeue_dead_letter`, `purge_finished`, словарь `_dead_letters`). Мотивация — в proposal.md, требования — в дельта-спецификациях. Ограничения: `dashboard.py` и `cli.py` не трогаем, существующие публичные сигнатуры и тесты не меняем, зависимостей не добавляем.

## Goals / Non-Goals

**Goals:**
- Реализовать три пересмотренных правила и три добавления из JOBQ-237 с обратной совместимостью вызовов.

**Non-Goals:**
- Автоматическая очистка dead-letter по расписанию, новые метрики, фильтры по `reason` в API, изменения отчёта дежурных.

## Decisions

1. **Исход падения в `Worker._handle_failure`.** Порядок: нет политики → `FAILED`; `not is_retryable` → dead-letter с `NON_RETRYABLE`; `attempts >= max_attempts` → dead-letter с `EXHAUSTED`; иначе повтор. Проверка неповторяемости стоит раньше исчерпания — так «причина важнее счётчика» (решение тимлида). Альтернатива «сначала счётчик» отвергнута: теряет причину.
2. **`mark_dead_lettered(job_id, error, *, reason=DeadLetterReason.EXHAUSTED)`.** Новый keyword-only параметр с дефолтом сохраняет старые вызовы. `DeadLetterEntry.reason` — последнее поле с дефолтом `EXHAUSTED`, чтобы существующий код и тесты, создающие запись из пяти аргументов, работали.
3. **`RetryLaterError` в `errors.py`.** Наследник `JobqError`, валидация `retry_after` в конструкторе через `ConfigError` (конечное число, не `bool`, `>= 0`; 0 допустим). `ConfigError` определён в том же модуле, циклических импортов нет.
4. **Задержка для `RetryLaterError`.** В воркере: `min(exc.retry_after, policy.max_delay)`, без `delay_for` и без обращения к `rng`. Итоговая формулировка тимлида от 04.11 («джиттер не применяем, `rng` не трогаем») имеет приоритет над более ранним текстом тикета. Альтернатива — метод `RetryPolicy.delay_after(retry_after)`; допустимо, но не обязательно, публичный контракт от этого не зависит.
5. **Джиттер.** `delay *= source.uniform(1 - jitter, 1)`; последующее ограничение `[0, max_delay]` оставляем как защиту от «кривого» `rng`. Число вызовов `uniform` прежнее (один).
6. **Purge.** Для `DEAD_LETTERED` использовать `finished_at` (он равен `dead_lettered_at`, `mark_dead_lettered` ставит оба одним `now`); условие снятия исключения для `DEAD_LETTERED` убирается, а вместе с `store.remove` вычищается и запись `_dead_letters`. Альтернатива — брать время из `DeadLetterEntry`: эквивалентно, но требует лишнего поиска.
7. **`requeue_all_dead_letters`.** Валидация `job_type` до изменений, затем снимок `dead_letters()` (отфильтрованный по типу) и цикл по `requeue_dead_letter`. Так поведение, счётчики и логи гарантированно совпадают с одиночным возвратом, а порядок — с `dead_letters()`. Метод атомарен на практике: после проверки типа ошибки в цикле невозможны (все id из dead-letter и в `DEAD_LETTERED`).
8. **Экспорт.** `DeadLetterReason` и `RetryLaterError` добавляются в `jobq/__init__.py` и `__all__`; README обновляется по трём изменённым правилам.
9. **Очистка** оформлена как новое требование «Очистка dead-letter через purge_finished», а прежнее «Защита от purge_finished» удалено (REMOVED), поскольку его сценарий прямо противоречит новому правилу.

## Допущения (тикет не уточняет)

- Без действующей политики всё как раньше: неповторяемая ошибка и `RetryLaterError` дают `FAILED`. Нет обработчика для типа — по-прежнему `FAILED`.
- `RetryLaterError` проходит обычную классификацию; неповторяемой её делает только явное попадание в `non_retryable` политики (например, `Exception`). Особого статуса исключение не получает.
- `retry_after`: нечисловое, `bool`, NaN и бесконечность тоже `ConfigError` (по аналогии с валидацией `RetryPolicy`); 0 допустим.
- `requeue_all_dead_letters(job_type="")` и нестроковый тип — `ConfigError`, как в `set_retry_policy`.
- `purge_finished` по dead-letter использует то же нестрогое сравнение (`<=`), что и сейчас для остальных.
- `jobs.purged` включает удалённые записи dead-letter; новых счётчиков не вводим.
- Записи, уже лежащие в dead-letter на момент выкладки, живут в памяти процесса и получают `reason = exhausted` по умолчанию (раньше другой причины попасть туда не было).

## Risks / Trade-offs

- [Существующие тесты закрепляют старое поведение: `tests/test_retry.py` (неповторяемая → `FAILED`, двусторонний джиттер, `purge` не трогает dead-letter) и, возможно, `tests/test_worker.py`] → Правки существующих тестов запрещены тикетом. На apply: не менять их, прогнать набор, зафиксировать список тестов, падающих именно из-за пересмотренных правил, и сообщить владельцу тикета; новое поведение покрыть отдельными новыми тестами. Не подгонять код под старые тесты.
- [Первый `purge_finished` после выкладки удалит ~40 тысяч старых записей безвозвратно] → Предупредить дежурных; при необходимости сначала вызвать `requeue_all_dead_letters` для нужных типов.
- [Неповторяемые ошибки теперь заполняют dead-letter и могут быть возвращены массово, снова упасть и вернуться] → `reason` позволяет отличать их; массовый возврат с фильтром по типу доступен.
- [Джиттер вниз сжимает разброс вдвое при том же `jitter`] → Принято осознанно, ради SLA почты.

## Результаты apply

- Падают 3 существующих теста из-за пересмотренных правил (не правились, по тикету): `tests/test_retry.py::test_purge_keeps_dead_letter_and_retry` (purge теперь чистит dead-letter) и `tests/test_retry.py::test_non_retryable_fails_even_on_last_attempt[exc0|exc1]` (неповторяемая ошибка теперь в dead-letter, а не `FAILED`). Остальные 87 существующих проходят; 29 новых в `tests/test_refine_retries.py` проходят.
- Двусторонний джиттер существующие тесты не фиксируют жёстко, поэтому не падают.
