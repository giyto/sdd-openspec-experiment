## Why

Товар сейчас списывается только при отгрузке. Пока покупатель оформляет и оплачивает заказ,
тот же товар могут продать повторно, и склад потом извиняется перед клиентом (WH-214).
Нужно резервировать товар под заказ в момент оформления. Неоплаченный резерв должен сам
перестать действовать по TTL. Фоновых задач в сервисе нет и не будет, поэтому истечение
вычисляется по часам сервиса в момент обращения.

## What Changes

- Новая возможность «резервы» в `Inventory`: `reserve`, `confirm`, `cancel`, `extend`,
  `get_reservation`, а также запросы `reserved` и `available` по позиции (склад + SKU).
- Резерв держит товар под заказ по всем строкам сразу; физический остаток при резервировании
  не меняется. TTL по умолчанию — 15 минут (`DEFAULT_RESERVATION_TTL`).
- Истечение не хранится: резерв с `now >= expires_at` имеет статус `EXPIRED` и не учитывается
  в `reserved`/`available`. В журнал истечение не пишется.
- `confirm` превращает активный резерв в отгрузку: физический остаток списывается по строкам,
  пишутся `ISSUE` (с `ref` = номер заказа) и `RESERVE_CONFIRM`.
- `issue` (и источник `transfer`) проверяют наличие по доступному остатку, а не по физическому,
  чтобы не забирать товар из чужих активных резервов.
- Новые события журнала: `RESERVE`, `RESERVE_CONFIRM`, `RESERVE_CANCEL`, `RESERVE_EXTEND`.
- Новые исключения `ReservationError` и наследники (все с атрибутом `order_id`), новые модели
  `ReservationStatus`, `ReservationLine`, `Reservation` (неизменяемые снимки).
- Старый API не меняется: `receive`, `on_hand`, `stock_levels` и остальное работают как раньше;
  `on_hand` и `stock_levels` показывают физический остаток.
- Не трогаем `warehouse/cli.py`, `warehouse/reports.py`, существующие тесты, зависимости.

## Capabilities

### New Capabilities
- `reservations`: резервирование товара под заказы — жизненный цикл резерва (активен, истёк,
  подтверждён, отменён), TTL и продление, расчёт `reserved`/`available`, влияние резервов на
  `issue`/`transfer`, события журнала по резервам.

## Impact

- Код: `warehouse/models.py` (новые модели и enum), `warehouse/errors.py` (иерархия ошибок
  резервов), `warehouse/reservations.py` (новый модуль, `DEFAULT_RESERVATION_TTL`),
  `warehouse/inventory.py` (новые методы, проверки в `issue`/`transfer`),
  `warehouse/storage.py` (хранение записей резервов по `order_id`), `warehouse/events.py` не меняется.
- Тесты: новые тесты для резервов; существующие тесты не меняются.
- API: добавляется публичный API `Inventory` для резервов; поведение `issue`/`transfer` меняется
  только при наличии активных резервов (без резервов результат прежний).
- Зависимости: не добавляются.
- Внешняя выгрузка журнала получает новые типы событий; формат строки не меняется.
