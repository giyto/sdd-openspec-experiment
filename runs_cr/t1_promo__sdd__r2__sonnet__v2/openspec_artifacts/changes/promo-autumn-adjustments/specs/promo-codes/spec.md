## MODIFIED Requirements

### Requirement: Модель промокода и её инварианты
Промокод SHALL иметь непустой код, вид скидки (процент, фиксированная сумма или бесплатная доставка) и значение. Код SHALL нормализоваться как другие коды, вводимые людьми: пробелы по краям обрезаются, регистр приводится к верхнему. Нарушение инвариантов SHALL приводить к `ValidationError`: пустой (после нормализации) код; процент вне `(0, 100]`; фиксированная сумма не больше нуля или с более чем двумя знаками после запятой; значение бесплатной доставки, не равное нулю; значение не `Decimal`; отрицательная минимальная сумма заказа; `max_uses` не целое или меньше 1 (`None` означает «без лимита»); `max_uses_per_customer` не целое или меньше 1 (`None` означает «без лимита на клиента»); `max_discount` у промокода не процентного вида, `max_discount` не `Decimal`, не больше нуля или с более чем двумя знаками после запятой (`None` означает «без потолка»); naive-`datetime` в `starts_at`/`expires_at`; `starts_at` не раньше `expires_at` (если заданы оба); элементы `excluded_categories`, не являющиеся категориями.

#### Scenario: Код нормализуется при создании
- **WHEN** создаётся промокод с кодом `"  summer10 "`
- **THEN** его код равен `"SUMMER10"`

#### Scenario: Недопустимое значение процента
- **WHEN** создаётся процентный промокод со значением `0` или `100.01`
- **THEN** выбрасывается `ValidationError`

#### Scenario: Процент ровно 100 допустим
- **WHEN** создаётся процентный промокод со значением `100`
- **THEN** промокод создан

#### Scenario: Пустое или инвертированное окно
- **WHEN** `starts_at` равен `expires_at` или позже него
- **THEN** выбрасывается `ValidationError`

#### Scenario: Бесплатная доставка с нулевым значением
- **WHEN** создаётся промокод бесплатной доставки со значением `Decimal("0")`
- **THEN** промокод создан

#### Scenario: Бесплатная доставка с ненулевым значением
- **WHEN** создаётся промокод бесплатной доставки со значением `Decimal("5")`
- **THEN** выбрасывается `ValidationError`

#### Scenario: Потолок у непроцентного промокода
- **WHEN** `max_discount` задан у фиксированного промокода или у промокода бесплатной доставки
- **THEN** выбрасывается `ValidationError`

#### Scenario: Недопустимый потолок процентной скидки
- **WHEN** у процентного промокода `max_discount` равен `0` или отрицателен
- **THEN** выбрасывается `ValidationError`

#### Scenario: Недопустимый лимит на клиента
- **WHEN** `max_uses_per_customer` равен `0`, `-1`, `True` или `1.5`
- **THEN** выбрасывается `ValidationError`

#### Scenario: Прежние промокоды остаются валидными
- **WHEN** создаётся промокод без `max_discount` и `max_uses_per_customer`
- **THEN** промокод создан, оба поля равны `None`

### Requirement: Поиск промокода и порядок проверок
Поиск кода SHALL нормализовать код и проверять по порядку: (1) код существует, иначе `UnknownPromoCodeError`; (2) сейчас действует, иначе `PromoExpiredError`; (3) лимиты не исчерпаны, иначе `PromoConditionsError`. Окно действия SHALL быть полуоткрытым `[starts_at, expires_at)`; граница `None` означает отсутствие ограничения. До `starts_at` SHALL выбрасываться `PromoExpiredError` (отдельного исключения для «ещё не началась» нет). Пустая или пробельная строка при поиске SHALL давать `UnknownPromoCodeError`. Общий лимит исчерпан, когда число использований не меньше `max_uses`. Поиск SHALL принимать необязательный идентификатор клиента. Если у кода задан `max_uses_per_customer`, а идентификатор клиента не передан (`None`), поиск SHALL выбрасывать `PromoConditionsError`; если передан, лимит на клиента исчерпан, когда число использований кода этим клиентом не меньше `max_uses_per_customer`, и поиск SHALL выбрасывать `PromoConditionsError`. Идентификатор клиента SHALL сравниваться как есть (без обрезки пробелов и приведения регистра). Если у кода нет лимита на клиента, идентификатор клиента на результат поиска не влияет. Идентификатор клиента, не являющийся строкой или `None`, SHALL приводить к `ValidationError`.

#### Scenario: Регистронезависимый поиск
- **WHEN** зарегистрирован `"SUMMER"` и ищется `"  summer "`
- **THEN** возвращается этот промокод

#### Scenario: Неизвестный код
- **WHEN** ищется `"NOPE"` или `""`
- **THEN** выбрасывается `UnknownPromoCodeError`

#### Scenario: Начало окна включительно
- **WHEN** текущее время равно `starts_at`
- **THEN** код действует

#### Scenario: Конец окна исключительно
- **WHEN** текущее время равно `expires_at`
- **THEN** выбрасывается `PromoExpiredError`

#### Scenario: Акция ещё не началась
- **WHEN** текущее время раньше `starts_at`
- **THEN** выбрасывается `PromoExpiredError`

#### Scenario: Срок раньше лимита
- **WHEN** код одновременно просрочен и исчерпан по лимиту
- **THEN** выбрасывается `PromoExpiredError`, а не `PromoConditionsError`

#### Scenario: Лимит исчерпан
- **WHEN** `max_uses = 2` и использований уже 2
- **THEN** поиск выбрасывает `PromoConditionsError`

#### Scenario: Лимит на клиента без идентификатора
- **WHEN** у кода `max_uses_per_customer = 1`, поиск вызван без идентификатора клиента
- **THEN** выбрасывается `PromoConditionsError`

#### Scenario: Лимит на клиента исчерпан
- **WHEN** `max_uses_per_customer = 1`, клиент `"u1"` уже использовал код один раз
- **THEN** поиск для `"u1"` выбрасывает `PromoConditionsError`, а поиск для `"u2"` возвращает код

#### Scenario: Идентификатор клиента сравнивается как есть
- **WHEN** `max_uses_per_customer = 1`, код использовал `"u1"`, и ищется для `"U1"` или `"u1 "`
- **THEN** это другие клиенты, поиск успешен

#### Scenario: Идентификатор клиента при коде без лимита на клиента
- **WHEN** у кода нет `max_uses_per_customer`, поиск вызван с идентификатором клиента или без него
- **THEN** результат одинаков

#### Scenario: Срок раньше лимита на клиента
- **WHEN** код просрочен и при этом лимит на клиента исчерпан
- **THEN** выбрасывается `PromoExpiredError`

### Requirement: Счётчик использований
Реестр SHALL сообщать число учтённых использований кода (код нормализуется): для зарегистрированного кода без использований — 0, для незарегистрированного — 0 без ошибки. При передаче идентификатора клиента реестр SHALL сообщать число использований кода этим клиентом, без идентификатора — общее число использований всеми. Использования, учтённые без идентификатора клиента, входят в общее число, но ни в чей клиентский счётчик. Реестр SHALL предоставлять операции учёта использования и его возврата, принимающие необязательный идентификатор клиента; учёт с идентификатором увеличивает и общий, и клиентский счётчик, а возврат уменьшает оба на один и никогда не опускает ни один ниже нуля. Учёт использования при исчерпанном общем лимите или лимите на клиента SHALL приводить к `PromoConditionsError` без изменения счётчиков. Поиск кода счётчик SHALL NOT менять.

#### Scenario: Поиск не расходует лимит
- **WHEN** поиск кода выполнен несколько раз подряд
- **THEN** число использований остаётся 0

#### Scenario: Возврат не уходит в минус
- **WHEN** возврат использования вызван при нулевом счётчике
- **THEN** число использований остаётся 0

#### Scenario: Использования по клиентам
- **WHEN** клиент `"u1"` использовал код дважды, клиент `"u2"` один раз
- **THEN** число использований для `"u1"` равно 2, для `"u2"` — 1, для `"u3"` — 0, общее — 3

#### Scenario: Возврат уменьшает оба счётчика
- **WHEN** использование клиента `"u1"` возвращено
- **THEN** его клиентский счётчик и общий счётчик уменьшились на один
