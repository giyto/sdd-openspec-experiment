## Why

Месяц эксплуатации повторов и dead-letter (JOBQ-212) показал три проблемы: задания с неповторяемой ошибкой (обычно кривые данные) уходят в `FAILED` и теряются, джиттер может поставить повтор позже расчётного времени (нарушает SLA почты), а `purge_finished` не чистит dead-letter, где накопилось 40 тысяч записей. Кроме того, внешним сервисам (Retry-After биллинга) нужен способ самим задавать время следующей попытки.

## What Changes

- **BREAKING** Неповторяемая ошибка (класс из `non_retryable`, `PermanentJobError`) для типа с действующей политикой сразу отправляет задание в `DEAD_LETTERED` без повторов (раньше — `FAILED`). Без политики и для типа без обработчика по-прежнему `FAILED`.
- **BREAKING** Джиттер только уменьшает задержку: множитель `rng.uniform(1 - jitter, 1)` вместо `uniform(1 - jitter, 1 + jitter)`.
- **BREAKING** `purge_finished` удаляет и задания из dead-letter по тому же правилу возраста, считая от момента попадания в dead-letter; запись из `dead_letters()` исчезает вместе с заданием.
- Новое `DeadLetterReason` (`EXHAUSTED`, `NON_RETRYABLE`) и поле `DeadLetterEntry.reason` (последним). Неповторяемая ошибка на последней попытке даёт `NON_RETRYABLE`; `RetryLaterError` на последней попытке — `EXHAUSTED`.
- Новое исключение `RetryLaterError(message="", *, retry_after)`: обычная временная ошибка, следующая попытка планируется через `retry_after` секунд, ограниченных `max_delay`; джиттер и генератор не используются. `retry_after < 0` — `ConfigError`.
- Новый метод `JobQueue.requeue_all_dead_letters(job_type=None) -> list[Job]`: возврат всего dead-letter или записей одного типа в порядке `dead_letters()`; нечего возвращать — пустой список.

Допущения (автономный режим, уточнить было не у кого):
- Актуальна поздняя договорённость (04.11): джиттер к `RetryLaterError` не применяется, `rng` не вызывается; описание в теле тикета («к этой задержке тоже применяем джиттер») отменено.
- `RetryLaterError` проходит обычную классификацию: если политика явно перечисляет его (или его базовый класс) в `non_retryable`, он неповторяемый.
- `retry_after`: нечисловое значение, `bool` и NaN — `ConfigError`, как и отрицательное; `0` допустим; бесконечность допустима и режется до `max_delay`.
- `DeadLetterEntry.reason` получает значение по умолчанию `EXHAUSTED`, чтобы старые вызовы конструктора работали.
- Существующие тесты не меняем; тесты, фиксирующие отменённое поведение (`FAILED` для неповторяемой ошибки, джиттер вверх, `purge_finished` не трогает dead-letter), после изменения неизбежно упадут — это следствие тикета; их список фиксируется в отчёте, а не правится.

### Modified Capabilities
- `job-retry-handling`: неповторяемая ошибка → dead-letter с причиной; `RetryLaterError`; правила использования генератора.
- `retry-policy`: джиттер только вниз.
- `dead-letter-queue`: поле `reason`, очистка `purge_finished`, массовый возврат.

## Impact

- Код: `jobq/models.py`, `jobq/errors.py`, `jobq/retry.py`, `jobq/queue.py`, `jobq/worker.py`, `jobq/__init__.py` (экспорт новых имён).
- Не затрагиваются: `jobq/dashboard.py`, `jobq/cli.py`, сигнатуры существующих публичных методов, зависимости.
- Метрики: `jobs.failed` не растёт для неповторяемых ошибок при наличии политики, `jobs.dead_lettered` растёт; `jobs.purged` учитывает и записи dead-letter; `jobs.requeued` растёт на каждое задание при массовом возврате.
