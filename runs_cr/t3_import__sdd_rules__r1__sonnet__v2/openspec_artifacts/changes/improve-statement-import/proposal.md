## Why

Через месяц после запуска импорта выписок (LEDGER-58) накопились три потребности: «Сфера» сменила формат выгрузки (суммы с точкой), интерфейсу импорта нужны превью до сохранения и сами строки с ошибками, а поддержка жалуется, что строгий режим показывает по одной ошибке за запуск (LEDGER-74).

## What Changes

- «Сфера» (`sfera` и `sfera_split`): десятичный разделитель в сумме — точка или запятая; если в сумме есть и то и другое, это ошибка строки. Раньше точка была ошибкой. **BREAKING** для файлов, где точка считалась ошибкой.
- `sfera_split`: строка, где в обеих колонках `Приход` и `Расход` явно стоят нули, молча пропускается (служебные операции банка): не ошибка, не дубль, не добавленная транзакция. Раньше была ошибкой. Ноль в одной колонке при пустой другой остаётся ошибкой.
- Описание при импорте сохраняется нормализованным по пробелам: края обрезаются, любая последовательность пробельных символов (пробелы, табы, переводы строк) внутри заменяется одним пробелом; регистр и буквы не меняются. **BREAKING** для хранимого текста описаний.
- Строгий режим разбирает файл до конца и бросает `StatementRowError` со всеми ошибками строк в `errors`; `line_no` и сообщение берутся у первой ошибки. Атомарность прежняя.
- Публичный API (дословно из задачи):
  - `import_statement(path, store, *, fmt=None, strict=False, categorizer=None, clock=None, dry_run=False) -> ImportResult`
  - `RowError(line_no: int, message: str, raw: str = "")` — frozen dataclass
  - `ImportResult` — прежние поля и новое `transactions: list[Transaction] = field(default_factory=list)`
  - `StatementRowError.errors: list[RowError]` в `ledger/errors.py`
- `dry_run=True`: превью, расчёт как при обычном импорте, в хранилище ничего не пишется; `transactions` заполнены, `id` равны `None`.
- `ImportResult.transactions`: добавленные транзакции в порядке строк файла, с `id` из хранилища.
- `RowError.raw`: текст записи как в файле (раскодированный, без BOM, без `\r`, без завершающего перевода строки; многострочная запись соединяется через `\n`).

## Impact

- Код: `ledger/importer.py`, `ledger/errors.py`; README (описание форматов, если упоминает точку в суммах).
- Не затрагиваются: `ledger/cli.py`, `ledger/reports.py`, новые зависимости (только стандартная библиотека). Сигнатуры `import_csv` и вызовы `import_statement` без новых аргументов работают как раньше, кроме пунктов выше.
- Существующие тесты не переписываются, кроме тех, что проверяли прежнее поведение четырёх изменённых пунктов (точка в сумме, нули в обеих колонках `sfera_split`, обрезка описания, остановка строгого режима на первой ошибке): их обновляем.

## Assumptions

- Правка описания (п.3) действует для всех трёх форматов, включая `nova`, а значит и для `import_csv`; дедупликация не меняется (она и так сравнивает через `normalize_description`).
- Правила точности суммы прежние: не более двух знаков после разделителя; `1.234` и `1,234` — ошибка. Точка не бывает разделителем тысяч; несколько разделителей (`1.2.3`) — ошибка.
- «Нули явно в обеих колонках» — значения, которые по правилам сумм равны нулю (`0`, `0,00`, `0.00`, `0,0`); решение о пропуске принимается по этим двум колонкам до проверки даты и описания. Если одна колонка — ноль, а другая непустая, строка разбирается как обычно (ненулевая — по общим правилам, невалидная — ошибка). Нуль со знаком остаётся ошибкой (знак в split запрещён).
- `StatementRowError(message, *, line_no)` вызывается как раньше; `errors` — необязательный именованный аргумент, по умолчанию список из одной `RowError(line_no, message)`.
- В `dry_run` строгий режим, ошибки формата и ошибки строк ведут себя как при обычном импорте.
- Тексты сообщений об ошибках не фиксируются.
