## Context

Импорт (`ledger/importer.py`) работает по конвейеру: декодирование → формат → разбор всего файла в список `Transaction | RowError` → дедупликация → одна запись `store.add_many`. Нужны: суммы с точкой, пропуск нулевых строк `sfera_split`, нормализация пробелов в описании, сбор всех ошибок в строгом режиме, `dry_run`, `ImportResult.transactions` и `RowError.raw`. Публичный API задан задачей и не меняется (см. proposal). Только стандартная библиотека; `cli.py`, `reports.py` не трогаем.

## Goals / Non-Goals

**Goals:**
- Реализовать пять изменений поведения и три расширения API минимальными правками конвейера.
- `dry_run` и обычный импорт делят один код расчёта, чтобы цифры совпадали по построению.

**Non-Goals:**
- Менять дедупликацию, определение формата/кодировки, `import_csv`, CLI.
- Фиксировать тексты сообщений об ошибках.

## Decisions

1. **Сумма «Сферы».** Регулярное выражение суммы допускает `,` или `.` как десятичный разделитель (одна штука, 1–2 цифры), тысячи — пробел/U+00A0 группами по три. Наличие обоих символов, `1.234`, `1.2.3` не проходят регулярное выражение → ошибка строки. После проверки разделитель заменяется на `.` и значение идёт в `to_money`. Альтернатива (угадывать точку как тысячи) отвергнута: принцип «не угадывать» из LEDGER-58.
2. **Служебные строки.** В ветке `sfera_split` после проверки длины строки: если обе колонки непусты (после `strip`), оба разбираются как беззнаковые суммы и оба равны нулю — разбор возвращает маркер «пропустить» (например `None`), а `_parse_rows` его не добавляет в результат. Проверка до даты и описания, чтобы служебные строки с пустым описанием не давали ошибок. Если одна из колонок невалидна — обычная ошибка.
3. **Описание.** `" ".join(text.split())` в одном месте сборки `Transaction` для всех форматов (`str.split()` без аргументов покрывает пробелы, табы, переводы строк и Unicode-пробелы, включая U+00A0). Регистр не трогаем.
4. **raw.** Текст после декодирования уже без BOM (`utf-8-sig`). Для `raw` берётся список физических строк, полученный разбиением текста по `\r\n|\r|\n` (то же определение конца строки, что у `csv` при `newline=""`, а не `str.splitlines`, чтобы не резать по `\x0b`, ` `). Для записи, начавшейся на `line_no` и закончившейся на `reader.line_num`, `raw = "\n".join(lines[line_no-1:reader.line_num])`. То же для строк с `csv.Error`. `raw` заполняется только для `RowError`; границы записи считаются в `_parse_rows`, где уже известен `line_no`. Если строка внутри кавычек содержит одиночный `\r`, он тоже считается переводом строки (допущение).
5. **RowError и errors.py.** `RowError` остаётся в `importer.py` (по заданию), получает поле `raw: str = ""`. `StatementRowError.__init__(message, *, line_no, errors=None)`: `errors` по умолчанию `[RowError(line_no, message)]`; чтобы избежать циклического импорта (`importer` импортирует `errors`), `RowError` импортируется в `errors.py` под `TYPE_CHECKING`, а значение по умолчанию создаётся локальным импортом внутри `__init__`. Существующие вызовы `StatementRowError("x", line_no=4)` работают без изменений; `line_no` по-прежнему обязателен.
6. **Строгий режим.** `import_statement` при `strict` и наличии ошибок бросает `StatementRowError(errors[0].message, line_no=errors[0].line_no, errors=errors)` — разбор уже идёт до конца, меняется только то, что передаётся в исключение (копия списка).
7. **dry_run и transactions.** После дедупликации и категоризации список `new` один и тот же. Если `dry_run` ложно и `new` не пуст — `stored = store.add_many(new)`, `transactions = stored` (с `id`); иначе при `dry_run` `transactions = new` (`id=None`), при пустом `new` — `[]`. `added = len(new)` в обоих режимах. `logger.info` помечает режим превью.

## Risks / Trade-offs

- Нормализация описания меняет хранимый текст у уже работающих пользователей `nova`/`import_csv` → зафиксировано как **BREAKING** в proposal; дубли не затронуты, так как сравнение и так нормализует пробелы.
- Точка в суммах расширяет допустимые входы: `1.234` остаётся ошибкой, чтобы не принять тысячи за дробь.
- Пропуск «нулевых» строк независимо от даты/описания может скрыть мусорную служебную строку → принято сознательно, банк помечает так блокировки.
- Хранилище может упасть при `add_many` (`StorageError`) — поведение прежнее, `transactions` в этом случае не возвращается.

## Migration Plan

Миграции данных нет. Выкатка — обычный релиз; откат — возврат коммита. Тесты, закреплявшие старое поведение четырёх пунктов, обновляются в той же правке.
